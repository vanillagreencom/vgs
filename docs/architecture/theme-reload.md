# Theme reload

Covers: scripts/test-vgsh-reload.sh

When a landed target's reload hook runs, and how `vgsh theme reload` re-runs the hooks still pending. How `vgsh theme apply` lands a package is [theme-apply.md](theme-apply.md).

A written file changes nothing on screen until its application re-reads it. A target's `reload` in `target.json` names the hook that makes it re-read: [theme-targets.md § Targets](theme-targets.md#targets). A target whose `reload` is null runs nothing and is never pending.

- **Pending file.** `${XDG_STATE_HOME:-~/.local/state}/vgs/reload-pending.json` is `{ "schemaVersion": 1, "targets": [<name>...] }`, sorted: each target whose application may hold files it has not re-read. It sits beside `theme/`, which the swap replaces. An absent file lists none, and an empty set removes the file. The runner owns `reload-pending.json`; the core never reads it. Apply and reload read it first, and a file that cannot be read, parsed or judged refuses the command with `reason=unreadable`, `unparseable` or `malformed` before anything moves. A write that fails refuses the command with `reason=unwritable`.
- **Due.** Before the stage, apply records as pending every target with a hook whose bytes change or that was pending, and every landing target whose `reload.always` is `true`, so an apply that dies after the swap still leaves them pending. A skipped target, one no longer shipped and one whose `reload` is null leave the set. A failed target keeps its entry.
- **Run.** After the theme file, apply runs the hook of every due target that landed, in name order, one at a time, with each argument's `@{state}` written as the state directory's `theme/` path and `@{wiring}` written as the target's single include file where admitted. A hook that exits 0 clears its target, whose state stays `written` or `unchanged`. Any other exit, a signal, a command that cannot start and a timeout leave the target pending and `reload-pending`, with `reason=reload-failed command=<argv0> status=<N>`, `signal=<SIG>` or `error=<code>`, or `reason=reload-timeout command=<argv0> timeout-ms=<N>`. A due target that did not land runs no hook and stays pending. A failed `@{wiring}` lookup leaves the target `reload-pending` with a keyed failure naming the path and error code.
- **Test runs.** Under the test-run marker, a non-empty `VGS_TEST_RUN`, a hook runs only when its target's directory, the directory its command names and every directory on `PATH` lie inside the scratch root, the real path of `TMPDIR` (else `/tmp`); an empty `PATH` entry is the working directory, and an unset `PATH` is a host default. The hook also needs an environment that names no live session's server: `TMUX`, `DBUS_SESSION_BUS_ADDRESS`, `HYPRLAND_INSTANCE_SIGNATURE` and `WAYLAND_DISPLAY` unset, and `XDG_RUNTIME_DIR` and `TMUX_TMPDIR` set to directories strictly inside the scratch root, since unset they fall back to the host's `/run/user/<uid>` and `/tmp`, where the compositor, the session bus, Hyprland's IPC and the tmux server listen. Any other hook never starts: its target is `reload-pending` and stays pending, with `reason=reload-refused command=<argv0>` and `path=<first directory outside>`, `env=<variable>` or `env=<variable> path=<directory>`, then `scratch=<root>`. A shipped `themes/targets` directory lies outside the scratch root, and so does every host directory a hook would reach the owner's live applications through; a target a test copies or writes under its scratch directory runs its hook through the stubs on the test's `PATH`. `scripts/validate`, the bin/vgsh suites' `scripts/vgsh-rows.sh` and the nested sandbox set the marker: [validation.md](validation.md). Without the marker, nothing here applies.
- **Hook process.** The hook runs with the runner's environment. Its stdin, stdout and stderr are `/dev/null`, so its output never reaches the result line, and no stream is a pipe a child of the hook could hold open past the timeout. At `timeoutMs` the hook gets `SIGKILL`. Descriptor 9, the theme lock's descriptor, is `/dev/null` in the hook, so nothing a hook starts holds the lock: [runtime.md § Process](runtime.md#process).
- **`vgsh theme reload`.** Under the lock, reload runs the hook of every pending target again, in name order, and renders, stages, swaps and wires nothing. A pending target no longer shipped, disabled, undetected, without its setup or without a hook is `skipped` with `not-shipped`, `disabled`, `not-detected`, `setup-absent` or `no-reload` and leaves the set. A target whose `target.json` cannot be read or judged is `failed` and stays pending. Enablement is apply's step 1: a `shell.json` the config judge refuses refuses the reload with `reason=malformed`.

The reload result is `{ state, targets, reason }`. `targets[]` is `{ name, state, reason }` per pending target, `state` being `reloaded`, `reload-pending`, `skipped` or `failed`. `state` is `unchanged` when nothing was pending, `partial` when a target stays pending, else `reloaded`; a refusal is `failed` with `reason` `busy`, `lock-failed`, `unreadable`, `unparseable`, `malformed` or `unwritable`. Text mode prints `target=<name> state=<state>[ reason=<key>]` per target, then `ok reload state=<state>`, or `partial reload state=partial`. Refusals print `vgsh: refused: reload=pending reason=<key>`, and each failed or reload-pending target its `target=` line. Exit 0 for `reloaded` and `unchanged`, 3 for `partial`, 1 on a refusal, 75 when busy, 2 on an argument.

## Invariants

1. A landed target's reload hook runs on changed bytes and on a pending reload, never on unchanged bytes unless its `reload.always` is `true`, and takes the state directory for each argument's `@{state}` and the wired file for `@{wiring}` where admitted; a hook that fails, is killed or passes its timeout leaves its target `reload-pending` and pending, the apply `partial`, and runs on the next apply or reload; the pending file names every due target while its hook runs; a hook's output never reaches the result and it holds no lock descriptor; a skipped, unshipped or hookless target leaves the set, and a reload detects a list entry by any one of its names; a malformed pending file refuses before anything moves; reload clears a target whose hook succeeds and never writes a target or theme file. Enforced by `scripts/test-vgsh-reload.sh` under a PATH of stub hooks, with judge copies that run every landed hook, record no failure, record nothing before the swap, misread a timeout, drop the bound, hand the hook the lock descriptor, drop `always`, require every name of a detect list entry and pass the arguments unwritten as its controls. The `@{wiring}` path is enforced by `scripts/test-vgsh-targets.sh` for WezTerm.
2. Under the test-run marker a hook runs only inside the scratch root: a shipped target's hook, a hook with a `PATH` directory outside it, a command named by a path outside it and a hook under any planted host channel never start, and their target stays `reload-pending` with `reload-refused`; without the marker the same hook runs. Enforced by `scripts/test-vgsh-reload.sh` with a stub for the signal command first on every `PATH`, with judge copies that drop the guard, the target-directory rule, the `PATH` rule, the command-path rule and each host channel's rule as its controls; `scripts/test-validate.sh` proves `scripts/validate` exports the marker, with a copy that drops the export as its control.
