# QML unit validation

Covers: scripts/qml-unit.sh, scripts/test-qml-unit.sh, scripts/qml-tests/*

The QML unit runner, its log rules and its mutation controls. The check selector that runs the rows is [validation.md](validation.md).

- `scripts/qml-unit.sh` runs the QML unit tests under `qmltestrunner` on the offscreen platform, the area `unit`: Qt with no Wayland session. It builds stand-in `qs.Ui`, `qs.Commons`, `qs.Core`, `Quickshell`, `Quickshell.Io`, `Quickshell.Hyprland` and `Qt.labs.folderlistmodel` modules, so `tst_tui_records.qml` can drive a lost folder-listing change and finish `Process` by hand, and `tst_keycapture.qml` can emit Hyprland's `submap` events and read the pass-through requests a recording `Compositor` stand-in kept. `offline` leaves it out; the default `all` area selects it when its inputs change. A missing runner exits 77. A test file fails on a warning or error it logs unless a `// expected-log: <message> -- <reason>` line directly above the test function names it; one logged at load or at teardown always fails. The runner's header holds the rule. A grab of a rendered item needs the test case nested under a root item and one `wait` before the grab; a test case that is the file's root grabs an unrendered image.
- `scripts/test-qml-unit.sh` scopes its mutation table when `VGS_VALIDATE_CHANGED` names a readable changed-path list. A mutation runs when the diff names its target QML or JavaScript file, its `scripts/qml-tests/tst_*.qml` test file, `scripts/qml-unit.sh`, `scripts/test-qml-unit.sh`, or a non-test file under `scripts/qml-tests/` that supplies stand-in modules. An unset or empty `VGS_VALIDATE_CHANGED`, a direct run and `scripts/validate --full` run every mutation. A shared file can weaken a component test that the scoped table skips; that is a mutation-test limit, not product behavior. The product unit tests still run in full. `scripts/test-qml-unit.sh --plan` prints the run and skip decision without starting `qmltestrunner`.
- On the offscreen platform `scripts/qml-unit.sh` uses, Qt Quick draws with its software adaptation: `GraphicsInfo.api` reads `GraphicsInfo.Software`, and forcing `QT_QUICK_BACKEND=rhi` there aborts `qmltestrunner` (measured with qmltestrunner on Qt 6.11.2 on 2026-09-28). That adaptation draws no shader effect, so a `MultiEffect` and the layer it draws are absent from a grab, while a `Shape` draws. A unit test reads such an effect's properties; `scripts/qml-tests/tst_angledcard.qml` reads `AngledCard`'s mask that way.
