# Smoke harness helpers

Covers: scripts/smoke/harness.sh, scripts/smoke/Probe.qml, scripts/smoke/pointer/, scripts/smoke/toplevel/, scripts/check-smoke-readers.py, scripts/test-check-smoke-readers.py

The helpers `scripts/smoke/harness.sh` shares with every smoke row: the row runner and its traceback gate, the start and the stop of a sandbox shell, the readers and the pointer. The sandbox, its verdicts and its teardown are in [validation-smoke.md](validation-smoke.md).

- A row waits on a state the shell reports, never on time. `theme_idle` in `scripts/smoke/harness.sh` answers `idle` once the shell's first plugin scan has ended and its theme runner then holds no job in its queue or its download lane. `ping` answers before that scan ends, and every scan's end queues the follow, which holds the theme lock ([theme-capability.md](theme-capability.md)). A `vgsh theme` command started under the follow is refused `reason=busy`, the product's answer, so a row waits for `theme_idle` before the command and never retries it. A rescan in flight shows no job, so a row that rescans reads the rescan's effect first. `point_item` rests the pointer on a control, which it finds under a built instance or, by a property's value, in a plugin's layer, whose window box it offsets by the layer's position. It reads the control's box again at every poll and stops only after the control reports the pointer over the point at two readings in a row of one box, which it reads once more before it returns: the compositor routes the pointer by where it has placed the surface, which can trail the layout the probe reads after the surface resizes, and a list that grows after it opens or a card that slides in moves a control whose box was read before. `click_item` is `point_item` and one click at the point it settled on; a row that only needs the hover, such as a notification card whose hover pauses its clock or shows its actions, calls `point_item` alone. `scripts/smoke/rows/read-only-prefix.sh` holds `theme_idle`'s controls, and `scripts/smoke/rows/themes.sh` holds `click_item`'s and `point_item`'s: a point the control is not under, and a list item a plant scrolls away after the first reading, which `click_item` on a copy of `point_item` that reads the box once never clicks.
- A reader answers a state word for every state it can meet, such as `absent` before a record exists or `partial` for a record cut short, and never raises. The pollers `expect_poll`, `expect_within` and the notifications row's `wait_for` retry a failed read, so a traceback there would sit in the log behind a passing check. They and `expect` send each read's stderr through `reader_stderr` in `scripts/smoke/harness.sh`, which fails the check on a Python traceback and prints it under the check. `scripts/smoke/rows/updates.sh` plants an absent, an empty and a cut record for its launch reader, and its control polls a reader that raises on an absent record and reads one failure. Every row reader that parses JSON from its stdin goes through `py_reply`, which answers the probe's word, such as `absent` before an instance is built, in place of parsing it, and answers `empty` as a failed read for the empty reply a failed ipc call prints. `scripts/check-smoke-readers.py`, a `tools` row of `scripts/validate`, refuses a row program that `python3` runs itself on JSON from its stdin: `json.load(sys.stdin)`, or `sys.stdin` in a program that also calls `json.loads` or `raw_decode`. A reader that takes a reply as an argument is outside its reach. `scripts/test-check-smoke-readers.py` is its control. The notifications row's `latency_since` polls its emoji latency readers through `reader_stderr` too; its controls plant an empty probe answer and a latency reader that raises. The notifications row's readers of the store's state file answer `absent` before its first save and `missing` for a path the file lacks, and the row's controls plant both.
- `start_shell` in `scripts/smoke/harness.sh` starts every sandbox shell: the first, and each restart over another tree, an installed prefix or a mutant copy. It takes the tree and extra environment words, which win over the harness's own, and sets `shell_pid` to the runner's pid and `shell_qs_pid` to the shell's pid, which a row addresses the shell by. It reads the shell's pid from the started tree's own `vgsh pid`, since the lock file names the shell under both runners a tree may hold: the current runner's `qs` child, or the runner itself in a revision `scripts/sandbox-shots.sh --rev` exports whose runner execs `qs` in place. It fails the row when that pid is not a `qs` process, and finds the instance log by that pid among the sandbox's instances. The nested compositor carries the environment words `start_shell` gives a shell and the sandbox's buses, so a shell `vgsh restart` relaunches through its dispatch finds the same stand-ins and reaches no bus of the user's. `stop_shell` stops the running shell before a row starts another. It sends TERM to the runner, which passes it to the shell, then waits on the instance lock itself with `flock -w`, not on the runner's pid: the runner holds the lock until the shell has exited ([runtime.md § Process](runtime.md#process)), and a runner that `vgsh restart` relaunched is no child the harness can wait for. The bound, `stop_lock_wait_s`, is the 10 s `vgsh restart` gives the same wait. On the bound the row fails, lists each process that holds the lock by pid, command name and argv from a `/proc/<pid>/fd` scan, and `stop_shell` returns 1, which every caller handles. `scripts/smoke/rows/start-order.sh` holds its controls: a copy with no lock wait returns with a relaunched shell's lock held while that shell is stopped with SIGSTOP, and the real stop returns with it free; and a stop whose TERM reaches a stand-in times out on the lock the runner holds, fails once and names the runner, and not the shell, among the holders. The same row reads the instance lock with the probe's `holdUntil`, which plants a detached process that stands in for a download until a gate file exists, within an upper bound: `vgsh restart` during it brings a guarded shell back, and after a SIGKILL to the shell the lock is free and `vgsh run` starts, each with a copy of the tree whose runner execs `qs` with the lock's descriptor open as its control.
- `smoke_row` in `scripts/smoke/harness.sh` runs each row: `scripts/qml-smoke.sh` calls it in place of `source`. It sources the row in the harness's own shell, since rows share state, and sends the row's stdout and stderr through one filter. The filter prints each line at once, so a row that exits still shows its lines, and keeps them in `$sandbox/rows/<row>.out`. A Python traceback anywhere in that output fails the row once and names it: a reader run outside every poller, in a helper or an unchecked pipe, escapes `reader_stderr`. The harness does not wait for the filter to end, since a process the row started can hold the pipe open. The row's last write is an end marker, and the filter writes the count of tracebacks before it to `$sandbox/rows/<row>.result`. A count still absent after `smoke_row_drain_s`, 5 s, fails the row as `output did not drain`. `scripts/smoke/rows/updates.sh` holds the controls, each over a row planted in the sandbox and run in a subshell whose lines go to their own file: a reader of a planted reply that raises outside every expect fails its row once; the same reader answering a state word fails nothing; a row that sends its own output elsewhere hides the marker and fails at the bound.
- The harness builds `scripts/smoke/pointer/click.c` into the sandbox: one click through the nested compositor's virtual pointer protocol, run only with the nested socket in its environment, so a row can click a widget or click outside a menu without any tool that reaches the live seat. It builds `scripts/smoke/toplevel/toplevel.c` the same way: one xdg toplevel with the app-id and, when given, the title a row gives it, which `scripts/smoke/rows/hyprland.sh` and the application window readings of `scripts/smoke/app-window.sh` start and stop by pid and the harness's stand-in terminal maps as a run's window. It prints each keyboard enter, leave and key it receives, so a row reads which window the keyboard reached. The shell's own windows are the nested instance's clients of the shell's class, `HyprlandLayer.APP_WINDOW.appId`: `window_count`, `one_window` and `window_of` read them by title, and `at_centre`, `click_in` and `click_scoped_in` take `window:<title>` where they take a layer's namespace. `pixel` reads one pixel of the nested output through `shot_pixel` in `scripts/smoke/shot.sh`, which gives `grim` the nested socket alone. That stand-in, which `terminal_stand_in` writes as `xdg-terminal-exec` in the shell's stand-in directory below, records the argv a floating TUI's launcher hands it and runs a plugin's script under the real presenter and any core command as `true`, so `scripts/smoke/rows/manager.sh`, `scripts/smoke/rows/tui.sh` and `scripts/smoke/rows/launcher.sh` read a launch back and no core command runs in the sandbox. The shell alone resolves `hyprctl` through a stand-in directory on its path, so a row can replace the command with one that cannot start and prove the dispatch queue survives it. `scripts/smoke/rows/devtools.sh` stands `mise`, `docker`, `podman` and `pacman` in there, so the Dev Tools plugin's queries reach no host package manager, and clicks one row's button among rows that draw the same text with `click_scoped_in`. The Hyprland layer's `hyprctl reload config-only`, which `shell/Core/HyprlandLayer.qml` runs after each write, resolves through the same directory and carries the nested `HYPRLAND_INSTANCE_SIGNATURE`, so it reaches only the nested instance; it is the core's own reload, not a theme target's hook, and `scripts/smoke/rows/hyprland.sh` reads its effect back.
