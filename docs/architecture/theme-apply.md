# Theme apply

Covers: scripts/test-vgsh-reload.sh, scripts/test-vgsh-entries.sh, scripts/test-vgsh-agents.sh

How `vgsh theme apply` lands a package and `vgsh theme reload` re-runs reload hooks. The package format, the runner, the lock and install are [themes.md](themes.md).

## Apply

`vgsh theme apply <name>` lands the package in the state directory, `${XDG_STATE_HOME:-~/.local/state}/vgs/`, and in every enabled target, then in the shell. Targets are the shipped `themes/targets/<target>/`: [theme-targets.md](theme-targets.md). The steps run in this order under the lock.

1. **Enablement.** A target is enabled when its `detect` is met on `PATH` ([theme-targets.md § Targets](theme-targets.md#targets)) and the effective `shell.json`'s `disabledTargets` does not list it: [configuration.md § shell.json keys](configuration.md#shelljson-keys). A target whose `setup` command is not on `PATH` is skipped with `setup-absent`. Either layer that `PluginLogic.configError` refuses refuses the apply with `reason=malformed`, since no target's enablement is then known. A target whose `wiring.create` is `false` and whose wiring file is absent is skipped, and so is a profiles target none of whose `profiles.ini` paths exists, or whose ini lists no profile directory that exists, a fallback target whose config-home file and fallbacks are absent when `create` is `false`, a vaults target whose registry is absent or lists no opened vault, and an entry target with a path something else holds, reason `entry-occupied`: [theme-wiring.md § Entry wiring](theme-wiring.md#entry-wiring). A target with `select` whose settings file is absent, a dangling symlink included, is skipped with `selection-file-absent`, and one whose edit `selectedText` refuses with `selection-refused`: [theme-agents.md § Selection](theme-agents.md#selection). A skipped target renders nothing.
2. **Render.** Every enabled target renders in memory, with the package's curated files and terminal slots. A target that cannot be read or rendered is `failed`; the others go on.
3. **Settle.** No include line or link is left naming a file the swap drops. A disabled target's include line is removed from its configuration file, edited in place as step 5 edits it, or its managed links are removed and then its `owned` directory once it is empty, and its files leave `theme/`. A path the target does not manage and an owned directory holding anything else stay; a removal that cannot be made fails the target and keeps its files. Every other target that renders nothing, failed or skipped, carries the files it landed before, the `theme/` files whose name before the first dot is the target's, so its application keeps its last theme. A `theme/` that cannot be read refuses the apply.
4. **Stage and swap.** Apply removes a `next-theme/` or `old-theme/` a crashed or refused apply left, then writes `theme.json`, `terminal.json` and every rendered or carried target file into `next-theme/`, the sibling of `theme/`. Each file is created exclusively. A rename cannot replace a non-empty directory, so `theme/` moves to `old-theme/`, `next-theme/` becomes `theme/` and `old-theme/` is removed. `theme/` is absent between the two renames; a failed second rename moves the old one back. Then `theme.name` holds the package name, and the background apply chose before anything moved becomes current: [theme-backgrounds.md § Commands](theme-backgrounds.md#commands).
5. **Wiring.** Each landed target's include line is kept in its application's configuration file, on every apply, unchanged bytes included, so a hand edit that drops it is repaired. A profiles target's line is kept in the file of every existing profile its first existing `profiles.ini` lists: [theme-wiring.md § Profile wiring](theme-wiring.md#profile-wiring). A fallback target's line is kept in the first existing fallback only when the configuration-home file is absent: [theme-wiring.md § Fallback files](theme-wiring.md#fallback-files). A symlink is resolved and the file it names is replaced by rename with its mode kept, so a dotfile manager's link stays a link. An absent file is created only when `create` is `true`, never through a dangling symlink. A file that cannot be read or written, or whose wiring the renderer refuses with `wiring-conflict`, fails its target: [theme-wiring.md § Wiring text](theme-wiring.md#wiring-text). An entry target's `dir`, in every vault a vaults target's registry lists, is created with its parents when absent and each absent link is created; a managed link is left as it is, so a later apply changes nothing there, and a path taken since step 1 fails the target with `entry-occupied`. A target whose `wiring` is null keeps nothing here. Then a target with `select` has its one theme key set in its application's settings file, on every apply, unchanged bytes included, through a symlink by rename with the mode kept, as an include line's file is edited; a file already selecting the value is not written, and none is ever created. A settings file absent since step 1 fails the target with `selection-file-absent`, and one refused since then with `selection-refused`. The include line or the links, added here or removed in step 3, and the selection key are the only writes apply makes outside the state directory and the theme file; step 3 never touches the selection key.
6. **Theme file.** Then the package's `theme.json` bytes replace `${XDG_CONFIG_HOME:-~/.config}/vgs/theme.json` by rename, so the shell restyles after every application file is in place and never reads half a file. The copy is byte for byte: a re-serialised copy would report every apply as modified. A file already holding those bytes is not written.
7. **Reload.** Last, each landed target whose reload is due runs its hook: [§ Reload](#reload).

The result is `{ state, shell, targets, theme, reason }`.

| Field | Values |
|---|---|
| `shell` | `applied`, `unchanged` when the file already held the bytes, or `failed` when writing it failed. |
| `targets[]` | `{ name, state, reason }` per shipped target, in name order. `state` is `written`, `unchanged` when every file already held its bytes, `skipped` with `reason` `disabled`, `not-detected`, `setup-absent`, `wiring-file-absent`, `entry-occupied`, `selection-file-absent` or `selection-refused`, `failed` with the renderer's reason, `unreadable`, `unwritable`, `wiring-conflict`, `entry-occupied`, `selection-file-absent` or `selection-refused`, or `reload-pending` with `reload-failed` or `reload-timeout` when its files landed and its reload hook failed. |
| `state` | `partial` when a target failed or is `reload-pending`; else `applied` when the shell or a target took new bytes; else `unchanged`. A refusal is `failed`. |
| `reason` | Null, or a refusal's key: `malformed-name`, `busy`, `lock-failed`, `unknown`, `unwritable`, `unreadable`, `unparseable`, `malformed`, `terminal-fallback` or the package's own. `targets` is `[]` for a refusal before the swap. |

Text mode prints `target=<name> state=<state>[ reason=<key>]` per target, then `ok theme=<name> state=<state> shell=<shell>`, or `partial ...` for a partial apply. `--json` prints the result as one line, refusals included. Each refusal prints `vgsh: refused: theme=<name> reason=<key>` on stderr, a malformed name JSON-quoted, and each failed or reload-pending target `vgsh: refused: target=<name> reason=<key> <detail>`. Exit 0 for `applied` and `unchanged`, 3 for `partial`, 1 on a refusal, 75 when busy, 2 on a bad invocation.

[D021](../decisions/D021-theme-apply-writes-beside-each-destination.md) records why every write is staged beside its destination and the shell document comes last, [D022](../decisions/D022-theme-apply-keeps-managed-links-in-application-directories.md) why an entry target keeps links in its application's directory, and [D024](../decisions/D024-theme-apply-sets-one-theme-key-in-an-application-settings-file.md) why a target with `select` sets one key in its application's settings file.

## Reload

A written file changes nothing on screen until its application re-reads it. A target's `reload` in `target.json` names the hook that makes it re-read: [theme-targets.md § Targets](theme-targets.md#targets). A target whose `reload` is null runs nothing and is never pending.

- **Pending file.** `${XDG_STATE_HOME:-~/.local/state}/vgs/reload-pending.json` is `{ "schemaVersion": 1, "targets": [<name>...] }`, sorted: each target whose application may hold files it has not re-read. It sits beside `theme/`, which the swap replaces. An absent file lists none, and an empty set removes the file. The runner owns `reload-pending.json`; the core never reads it. Apply and reload read it first, and a file that cannot be read, parsed or judged refuses the command with `reason=unreadable`, `unparseable` or `malformed` before anything moves. A write that fails refuses the command with `reason=unwritable`.
- **Due.** Before the stage, apply records as pending every target with a hook whose bytes change or that was pending, and every landing target whose `reload.always` is `true`, so an apply that dies after the swap still leaves them pending. A skipped target, one no longer shipped and one whose `reload` is null leave the set. A failed target keeps its entry.
- **Run.** After the theme file, apply runs the hook of every due target that landed, in name order, one at a time, with each argument's `@{state}` written as the state directory's `theme/` path and `@{wiring}` written as the target's single include file where admitted. A hook that exits 0 clears its target, whose state stays `written` or `unchanged`. Any other exit, a signal, a command that cannot start and a timeout leave the target pending and `reload-pending`, with `reason=reload-failed command=<argv0> status=<N>`, `signal=<SIG>` or `error=<code>`, or `reason=reload-timeout command=<argv0> timeout-ms=<N>`. A due target that did not land runs no hook and stays pending. A failed `@{wiring}` lookup leaves the target `reload-pending` with a keyed failure naming the path and error code.
- **Hook process.** The hook runs with the runner's environment. Its stdin, stdout and stderr are `/dev/null`, so its output never reaches the result line, and no stream is a pipe a child of the hook could hold open past the timeout. At `timeoutMs` the hook gets `SIGKILL`. Descriptor 9, the theme lock's descriptor, is `/dev/null` in the hook, so nothing a hook starts holds the lock: [runtime.md § Process](runtime.md#process).
- **`vgsh theme reload`.** Under the lock, reload runs the hook of every pending target again, in name order, and renders, stages, swaps and wires nothing. A pending target no longer shipped, disabled, undetected, without its setup or without a hook is `skipped` with `not-shipped`, `disabled`, `not-detected`, `setup-absent` or `no-reload` and leaves the set. A target whose `target.json` cannot be read or judged is `failed` and stays pending. Enablement is apply's step 1: a `shell.json` the config judge refuses refuses the reload with `reason=malformed`.

The reload result is `{ state, targets, reason }`. `targets[]` is `{ name, state, reason }` per pending target, `state` being `reloaded`, `reload-pending`, `skipped` or `failed`. `state` is `unchanged` when nothing was pending, `partial` when a target stays pending, else `reloaded`; a refusal is `failed` with `reason` `busy`, `lock-failed`, `unreadable`, `unparseable`, `malformed` or `unwritable`. Text mode prints `target=<name> state=<state>[ reason=<key>]` per target, then `ok reload state=<state>`, or `partial reload state=partial`. Refusals print `vgsh: refused: reload=pending reason=<key>`, and each failed or reload-pending target its `target=` line. Exit 0 for `reloaded` and `unchanged`, 3 for `partial`, 1 on a refusal, 75 when busy, 2 on an argument.

## Invariants

1. Apply copies `theme.json` byte for byte, renders `terminal.json` or the shipped slots, and leaves no `next-theme/`, a stale one included; `apply vgs` writes the shipped defaults. Enforced by `scripts/test-vgsh.sh`, with a re-serialising judge copy as its control.
2. Apply lands each enabled target's files in `theme/` with its encoder, skips a disabled, undetected or unwired target, and never runs a detect command; a target that fails to render costs only itself, carries the file it landed before, and the apply is `partial` with exit 3; a target disabled after it landed loses its include line, the rest of the file kept byte for byte through a symlink with its mode, and its file, and one whose line cannot be removed fails and keeps its file; the include line is kept first in the file, through a symlink with its mode, on unchanged bytes too; a `shell.json` the config judge refuses refuses the apply. Enforced by `scripts/test-vgsh.sh` under a PATH of stub commands, with symlink-replacing, written-only, no-carry and line-keeping judge copies as its controls.
3. A landed target's reload hook runs on changed bytes and on a pending reload, never on unchanged bytes unless its `reload.always` is `true`, and takes the state directory for each argument's `@{state}` and the wired file for `@{wiring}` where admitted; a hook that fails, is killed or passes its timeout leaves its target `reload-pending` and pending, the apply `partial`, and runs on the next apply or reload; the pending file names every due target while its hook runs; a hook's output never reaches the result and it holds no lock descriptor; a skipped, unshipped or hookless target leaves the set, and a reload detects a list entry by any one of its names; a malformed pending file refuses before anything moves; reload clears a target whose hook succeeds and never writes a target or theme file. Enforced by `scripts/test-vgsh-reload.sh` under a PATH of stub hooks, with judge copies that run every landed hook, record no failure, record nothing before the swap, misread a timeout, drop the bound, hand the hook the lock descriptor, drop `always`, require every name of a detect list entry and pass the arguments unwritten as its controls. The `@{wiring}` path is enforced by `scripts/test-vgsh-targets.sh` for WezTerm.
4. An entry target's links land in its application's directory, through a symlinked directory, naming its files in `theme/`, with nothing else written there; an owned directory lands under HOME; a `cache` directory lands under `XDG_CACHE_HOME`, else `~/.cache`; a managed link is kept as it is; a file, a foreign link or a file where the directory belongs skips the target and stays; a disabled target loses only its managed links and its owned directory once empty, never a path it did not make or the user's file inside it. Enforced by `scripts/test-vgsh-entries.sh` with fixture targets, with judge copies that take any symlink as managed, skip the plan's occupancy check, never remove the owned directory, remove it recursively, remove any path at a link's name, put a `home` directory under the configuration home and ignore `XDG_CACHE_HOME` as its controls.
5. A target with `select` is skipped when its settings file is absent or its edit is refused, keeps its selection on every apply with every other byte of the file kept, through a symlink with its mode, never creates the file, and leaves the key when disabled. Enforced by `scripts/test-vgsh-agents.sh`, with judge copies that drop the plan's skip and never keep the selection as its controls; the edit itself is [theme-agents.md § Invariants](theme-agents.md#invariants).
