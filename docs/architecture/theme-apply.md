# Theme apply

Covers: scripts/test-vgsh-entries.sh, scripts/test-vgsh-agents.sh

How `vgsh theme apply` lands a package. When its reload hooks run, and `vgsh theme reload`, are [theme-reload.md](theme-reload.md). The package format, the runner, the lock and install are [themes.md](themes.md), and how a changed package reaches the theme file is [theme-follow.md](theme-follow.md).

## Apply

`vgsh theme apply <name>` lands the package in the state directory, `${XDG_STATE_HOME:-~/.local/state}/vgs/`, and in every enabled target, then in the shell. Targets are the shipped `themes/targets/<target>/`: [theme-targets.md](theme-targets.md). The steps run in this order under the lock.

1. **Enablement.** A target is enabled when its `detect` is met on `PATH` ([theme-targets.md § Targets](theme-targets.md#targets)) and the effective `shell.json`'s `disabledTargets` does not list it: [configuration.md § shell.json keys](configuration.md#shelljson-keys). A target whose `setup` command is not on `PATH` is skipped with `setup-absent`. Either layer that `PluginLogic.configError` refuses refuses the apply with `reason=malformed`, since no target's enablement is then known. A target whose `wiring.create` is `false` and whose wiring file is absent is skipped, and so is a profiles target none of whose `profiles.ini` paths exists, or whose ini lists no profile directory that exists, a fallback target whose config-home file and fallbacks are absent when `create` is `false`, a vaults target whose registry is absent or lists no opened vault, and an entry target with a path something else holds, reason `entry-occupied`: [theme-wiring.md § Entry wiring](theme-wiring.md#entry-wiring). For an entry copy, the planned managed forms are the old link, the old bytes read from `theme/` before the swap and the new render. A target with `select` whose settings file is absent, a dangling symlink included, is skipped with `selection-file-absent`, and one whose edit `selectedText` refuses with `selection-refused`: [theme-agents.md § Selection](theme-agents.md#selection). A skipped target renders nothing.
2. **Render.** Every enabled target renders in memory, with the package's curated files and terminal slots. A target that cannot be read or rendered is `failed`; the others go on.
3. **Settle.** No include line, link or copy is left naming a file the swap drops. A disabled target's include line is removed from its configuration file, edited in place as step 5 edits it, or its managed entries are removed and then its `owned` directory once it is empty, and its files leave `theme/`. A path the target does not manage and an owned directory holding anything else stay; a removal that cannot be made fails the target and keeps its files. Every other target that renders nothing, failed or skipped, carries the files it landed before, the `theme/` files whose name before the first dot is the target's, so its application keeps its last theme. A `theme/` that cannot be read refuses the apply.
4. **Stage and swap.** Apply removes a `next-theme/` or `old-theme/` a crashed or refused apply left, then writes `theme.json`, `terminal.json` and every rendered or carried target file into `next-theme/`, the sibling of `theme/`. Each file is created exclusively. A rename cannot replace a non-empty directory, so `theme/` moves to `old-theme/`, `next-theme/` becomes `theme/` and `old-theme/` is removed. `theme/` is absent between the two renames; a failed second rename moves the old one back. Then `theme.name` holds the package name, and the background apply chose before anything moved becomes current on every screen: [theme-backgrounds.md § Commands](theme-backgrounds.md#commands).
5. **Wiring.** Each landed target's include line is kept in its application's configuration file, on every apply, unchanged bytes included, so a hand edit that drops it is repaired. A profiles target's line is kept in the file of every existing profile its first existing `profiles.ini` lists: [theme-wiring.md § Profile wiring](theme-wiring.md#profile-wiring). A fallback target's line is kept in the first existing fallback only when the configuration-home file is absent: [theme-wiring.md § Fallback files](theme-wiring.md#fallback-files). A symlink is resolved and the file it names is replaced by rename with its mode kept, so a dotfile manager's link stays a link. An absent file is created only when `create` is `true`, never through a dangling symlink. A file that cannot be read or written, or whose wiring the renderer refuses with `wiring-conflict`, fails its target: [theme-wiring.md § Wiring text](theme-wiring.md#wiring-text). An entry target's `dir`, in every vault a vaults target's registry lists, is created with its parents when absent. Each absent link is created, and a managed link is left as it is, so a later apply changes nothing there. Each absent copy is written by rename beside the destination, and a managed copy is replaced only when its bytes differ or it is the old link form. A path taken since step 1 fails the target with `entry-occupied`. A target whose `wiring` is null keeps nothing here. Then a target with `select` has its one theme key set in its application's settings file, on every apply, unchanged bytes included, through a symlink by rename with the mode kept, as an include line's file is edited; a file already selecting the value is not written, and none is ever created. A settings file absent since step 1 fails the target with `selection-file-absent`, and one refused since then with `selection-refused`. The include line or entries, added here or removed in step 3, and the selection key are the only writes apply makes outside the state directory and the theme file; step 3 never touches the selection key.
6. **Theme file.** Then the package's `theme.json` bytes replace `${XDG_CONFIG_HOME:-~/.config}/vgs/theme.json` by rename, so the shell restyles after every application file is in place and never reads half a file. The copy is byte for byte: a re-serialised copy would report every apply as modified. A file already holding those bytes is not written. Apply then records itself in `applied.json`: [theme-follow.md](theme-follow.md).
7. **Reload.** Last, each landed target whose reload is due runs its hook: [theme-reload.md](theme-reload.md).

The result is `{ state, shell, targets, theme, reason }`.

| Field | Values |
|---|---|
| `shell` | `applied`, `unchanged` when the file already held the bytes, or `failed` when writing it failed. |
| `targets[]` | `{ name, state, reason, dropped }` per shipped target, in name order. `dropped` lists each destination whose curated file was dropped ([themes.md § Trust](themes.md#trust)), else `[]`. `state` is `written`, `unchanged` when every file already held its bytes, `skipped` with `reason` `disabled`, `not-detected`, `setup-absent`, `wiring-file-absent`, `entry-occupied`, `selection-file-absent` or `selection-refused`, `failed` with the renderer's reason, `unreadable`, `unwritable`, `wiring-conflict`, `entry-occupied`, `selection-file-absent` or `selection-refused`, or `reload-pending` with `reload-failed`, `reload-timeout` or `reload-refused` when its files landed and its reload hook failed or was refused. |
| `state` | `partial` when a target failed or is `reload-pending`; else `applied` when the shell or a target took new bytes; else `unchanged`. A refusal is `failed`. |
| `reason` | Null, or a refusal's key: `malformed-name`, `busy`, `lock-failed`, `unknown`, `unwritable`, `unreadable`, `unparseable`, `malformed`, `terminal-fallback` or the package's own. `targets` is `[]` for a refusal before the swap. |

Text mode prints `target=<name> state=<state>[ reason=<key>][ dropped=<destination>,...]` per target, then `ok theme=<name> state=<state> shell=<shell>`, or `partial ...` for a partial apply. `--json` prints the result as one line, refusals included. Each refusal prints `vgsh: refused: theme=<name> reason=<key>` on stderr, a malformed name JSON-quoted, and each failed or reload-pending target `vgsh: refused: target=<name> reason=<key> <detail>`. Exit 0 for `applied` and `unchanged`, 3 for `partial`, 1 on a refusal, 75 when busy, 2 on a bad invocation.

[D021](../decisions/D021-theme-apply-writes-beside-each-destination.md) records why every write is staged beside its destination and the shell document comes last, [D022](../decisions/D022-theme-apply-keeps-managed-links-in-application-directories.md) why an entry target keeps links in its application's directory, and [D024](../decisions/D024-theme-apply-sets-one-theme-key-in-an-application-settings-file.md) why a target with `select` sets one key in its application's settings file.

## Invariants

1. Apply copies `theme.json` byte for byte, renders `terminal.json` or the shipped slots, and leaves no `next-theme/`, a stale one included; `apply vgs` writes the shipped defaults. Enforced by `scripts/test-vgsh.sh`, with a re-serialising judge copy as its control.
2. Apply lands each enabled target's files in `theme/` with its encoder, skips a disabled, undetected or unwired target, and never runs a detect command; a target that fails to render costs only itself, carries the file it landed before, and the apply is `partial` with exit 3; a target disabled after it landed loses its include line, the rest of the file kept byte for byte through a symlink with its mode, and its file, and one whose line cannot be removed fails and keeps its file; the include line is kept first in the file, through a symlink with its mode, on unchanged bytes too; a `shell.json` the config judge refuses refuses the apply. Enforced by `scripts/test-vgsh.sh` under a PATH of stub commands, with symlink-replacing, written-only, no-carry and line-keeping judge copies as its controls.
3. An entry target's links and copies land in its application's directory, through a symlinked directory, naming or holding its files in `theme/`, with nothing else written there; an owned directory lands under HOME; a `cache` directory lands under `XDG_CACHE_HOME`, else `~/.cache`; a managed link is kept as it is; an unchanged copy is not written; a changed copy and an old managed link are replaced by rename; a file, a foreign link, an edited copy or a file where the directory belongs skips the target and stays; a disabled target loses only its managed entries and its owned directory once empty, never a path it did not make or the user's file inside it. Enforced by `scripts/test-vgsh-entries.sh` with fixture targets, with judge copies that take any symlink as managed, accept any copy as managed, skip the plan's occupancy check, never remove the owned directory, remove it recursively, remove any path at an entry's name, put a `home` directory under the configuration home and ignore `XDG_CACHE_HOME` as its controls.
4. A target with `select` is skipped when its settings file is absent or its edit is refused, keeps its selection on every apply with every other byte of the file kept, through a symlink with its mode, never creates the file, and leaves the key when disabled. Enforced by `scripts/test-vgsh-agents.sh`, with judge copies that drop the plan's skip and never keep the selection as its controls; the edit itself is [theme-agents.md § Invariants](theme-agents.md#invariants).
