# Notifications: Slack's disk cache

Covers: shell/plugins/vgs.notifications/slack-cache.js, shell/plugins/vgs.notifications/slack-emoji.js, shell/plugins/vgs.notifications/SlackPhotos.qml, shell/plugins/vgs.notifications/WorkspaceIcons.qml, scripts/test-notifications-slack-cache.js, scripts/test-notifications-slack-emoji.js

How `vgs.notifications` reads Slack's disk cache, and the Slack custom emoji it builds from it. [notification-senders.md](notification-senders.md) holds the rules that read Slack's notifications, the workspace icons and the Slack photo cache. The plugin's [slack.md](../../shell/plugins/vgs.notifications/slack.md) says what the user sees. [D049](../decisions/D049-slack-custom-emoji-from-the-cache-drawn-inline.md) records the emoji choices.

## Slack's disk cache

- `slack-cache.js` is the one reader of Slack's disk cache, a Chromium simple cache. Its header holds the format as read against Slack 4.52.162: the entry file a URL names, the entry's header, key and end record. The workspace icons and the custom emoji both read the cache through it; no other file parses an entry.
- An entry opens only as a regular file, never through a link and never blocking on a FIFO. A read answers the body or one reason: `missing`, `too-large`, `malformed` or `unreadable`. Each caller names the most bytes it takes, 5 MiB for an icon and 256 KiB for an emoji, and the read stops there.
- A listing reads each entry's header and key alone and keeps an entry only when its file name is its key's hash. A listing over more than 262,144 entries is refused, never cut short. A missing cache is no Slack on the machine and is quiet.
- `copy` empties its out directory, then writes each icon through a temporary file and rename, and prints `copied <to> version=<16 hex>` or `skipped <to> reason=<reason>`. A refusal is one `notifications-slack-cache:` line on stderr. The file's header holds the exit statuses.

## Slack custom emoji

- The photo helper's run builds each listed team's custom emoji after the photos, in `slack-emoji.js`, so an emoji write never races a photo sweep. `SlackPhotos.qml` passes `--emoji <Slack Cache_Data>` while the `customEmoji` setting is on; a run without it empties every team's emoji index and removes it the run after.
- The token-free source is Slack's disk cache, listed once per run through its reader ([§ Slack's disk cache](#slacks-disk-cache)). An entry whose URL is `https://emoji.slack-edge.com/<listed team id>/<name>/<16 hex>.<png|gif|jpg>` and whose name passes `^[a-z0-9_+-]{1,100}$` is an emoji, and the newest file of a name wins. Only an image the run converts has its body read. Slack's cache on the owner's machine held 17,765 entries on 2026-09-29, 2,542 of them the custom emoji of one of its three teams; the cache keys no alias.
- The token source is `emoji.list`, with the token that serves the team ([notification-senders.md § Slack photo cache](notification-senders.md#slack-photo-cache)), at most once a day. It adds the names the cache lacks, the new image of a name it lists at another URL, and aliases, `alias:<target>`, which take their target's image when the target is in the team's map. `missing_scope` is recorded and asked again a day later, with no problem line and no `stale`; another failure is one `notifications-slack-photos: emoji team=<id> ...` line, keeps the previous list and is asked again after 15 minutes.
- ImageMagick draws the first frame of each image into a transparent 48 by 48 pixel square, as a PNG with no metadata, 32 images a process, one image a process after a chunk fails; the input's coder comes from its magic bytes. The file is `emoji/<16 hex>.png`, the first 16 hex digits of its SHA-256, so a name and its alias share one file. An image whose source URL is unchanged and whose file exists is not converted again. Without ImageMagick the run builds no emoji and says `emoji magick=missing`.
- Limits: 256 KiB a source image, 64 KiB a converted one, 2,048 emoji and 8 MiB of files a team, kept in the order cache entries newest first, then the names only `emoji.list` holds; 256 new images a run, the rest reported as `pending`. `NotificationLogic.slackPhotoDelay` runs the helper again a minute later while a team has pending images, and at most an hour later otherwise, so the cache is read again for the emoji Slack has shown since.
- A team's `emoji.json` holds its map, each name's source URL and its `emoji.list` state; the helper writes it by rename after every file it names is in place. The `emoji/` sweep keeps the files of the index it replaces for one more run. A listed team with emoji and no token keeps its directory with its emoji alone: the root sweep removes its photo files, so no photo outlives its token and a token stored again fetches the team afresh. The output's `emoji` list holds `{ team, map, count, pending }` per team, `map` name to its file's hex; the `teams` list and the photos' `status`, `stale` and `downloadFailed` are the same as with emoji off.
- `SlackPhotos.qml` stamps a run with the team set and the setting it was asked with, and takes a run's emoji only when both still hold: `NotificationLogic.slackEmojiLookups` builds one frozen name-to-URL lookup per team, and `emoji` becomes a new object only when the map changed, which every card's binding follows. Turning the setting off swaps an empty map in at once. A card's lookup (`slackEmojiFor`) takes the team its workspace names, and `emojiSegments` reads `:name:` between tags alone, at most 64 a body, and draws it through `ImageText` ([components-media.md](components-media.md)). A notification reads memory alone: it starts no run and reads no file.

## Invariants

1. A cached custom emoji of a listed team becomes an image in its map, an alias takes its target's image, a second run converts nothing, a run converts at most its budget, and the previous index's files survive one run. Enforced by `scripts/test-notifications-slack-emoji.js`, each rule with a control.
2. A card draws only its own workspace's emoji, never inside a tag, and an unknown name stays text; no notification starts a helper run. Enforced by `scripts/test-notifications-logic.js`, each rule with a control, and by `scripts/smoke/rows/notifications.sh`, which counts the runs beside a copy of the service that runs the helper per card.
3. Slack's disk cache has one reader, and each of its format rules and its bound holds for the icons and the emoji alike. Enforced by `scripts/test-notifications-slack-cache.js`, which runs both callers over a copy of the smoke fixture's cache, with a control per rule: a reader copy that breaks a format rule or the bound turns both callers red.
