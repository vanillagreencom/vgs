# Runtime: QML

Covers: shell/Commons/WatchedFile.qml, scripts/qml-tests/stand-ins/FileView.qml

The Quickshell 0.3.1 and Qt facts the shell's QML rests on, each with the source that establishes it. [runtime.md](runtime.md) holds the process, the runner, the measurement tools and the Hyprland facts.

- `FolderListModel` treats a missing folder as the process working directory and reports the swap through its `folder` property. Compare `folder` with the folder asked for before reading the listing.
- `FolderListModel` compares two listings by file name and kind alone: a file rewritten or replaced under its name changes no row (`FileProperty::operator==` in the installed Qt 6.11.2 header `QtLabsFolderListModel/private/fileproperty_p.h`, read on 2026-09-29). A watcher of a directory's files gives each state a new name; `TuiRecords`' exit records are written that way.
- `FolderListModel` can miss a directory change. Its scan thread waits on a condition only while no update is due, and a change wakes it with `condition.wakeAll()` without marking an update due (`FileInfoThread::run` and `FileInfoThread::dirChanged` in qtdeclarative 6.11 `src/labs/folderlistmodel/fileinfothread.cpp`, read on 2026-09-29). A change that lands after a scan released its lock and before the thread waits again is lost, and the listing stays stale until the next change in the directory. A probe that listed a directory with `FolderListModel` under `qml6` on the offscreen platform, while a script wrote a hidden file, renamed it into place and removed the older record 500 times, each time waiting 2 s for the listing, lost one of the 500 changes on host cachy on 2026-09-29 while it shared one core with two busy loops, and none of 500 when it could run on any core. A smoke row that waits for a run to end says when the core missed an ended record on disk ([validation-latency.md](validation-latency.md)). A TUI run end therefore does not depend on `FolderListModel` alone: `TuiRecords` also waits on the presenter's lock ([D043](../decisions/D043-tui-run-ends-by-lock-release.md)).
- Restart a `Process` from `runningChanged` when `running` is false, as the [Process reference](https://quickshell.org/docs/v0.3.1/types/Quickshell.Io/Process/) requires. Its implementation clears the process before emitting `exited`, then emits `runningChanged`. A command that fails to start emits only `runningChanged`.
- A `Process` stdout parser is attached before the process starts; a null parser closes the channel for good.
- A `SplitParser` on a `Process`'s stdout hands over every line before the process's `exited` and `runningChanged`: Quickshell 0.3.1's `Process::onFinished` calls the parser's `streamEnded` with the rest of the buffer before it emits either signal, and Qt drains the output pipes before `QProcess::finished` ([`src/io/process.cpp`](https://github.com/quickshell-mirror/quickshell/blob/v0.3.1/src/io/process.cpp)). `ThemeRunner` reads a download's progress lines as they arrive and its result from the lines kept at the exit.
- `Qt.resolvedUrl()` gives asset URLs. `Quickshell.shellDir` gives the filesystem path a subprocess needs.
- A JS object handed to `createObject` as an initial property crosses a QVariant conversion: functions vanish and nested lists stop being arrays. Assign such properties after creation.
- A dependent binding may still hold its old value when a property change handler runs. Read the source property inside the handler; [Qt specifies no binding evaluation order](https://doc.qt.io/qt-6/qtqml-syntax-propertybinding.html).
- `ShellScreen.devicePixelRatio` is the ratio between physical pixels and device-independent pixels ([ShellScreen reference](https://quickshell.org/docs/v0.3.1/types/Quickshell/ShellScreen/)), and `ShellScreen.width` and `height` are the device-independent size. Background images multiply the size by that ratio before setting `sourceSize`.
- `Array.prototype.flatMap` is absent from this engine.
- `Object.freeze` does not freeze an array's elements in this engine: on a frozen array, an index write, `push` and `sort` change it while `Object.isFrozen` answers true, and `Object.seal` and `Object.preventExtensions` do not stop `push` either; a frozen object's own properties do hold. A `Proxy` over an array stops the writes but `JSON.stringify` writes it as an object. Read in `qmltestrunner` of Qt 6.11.2 on 2026-09-28. `PluginStatus` hands each reader a copy for this reason.
- A `Loader` sets no required property of the item it loads, and a component that declares one fails to load. `Component.createObject` sets them from its initial properties, so `CardCarousel` builds a card's content that way (measured with qmltestrunner on Qt 6.11.2 on 2026-09-28).
- A `FileView.reload()` while a read of the same path is in flight starts no second read, and the read in flight reports the file as it was; the view emits `loaded` and `loadFailed` before it lets go of that read, so a reload from their handlers starts nothing either ([`fileview.cpp`](https://git.outfoxxed.me/quickshell/quickshell/src/commit/41651d7/src/io/fileview.cpp) `loadAsync`, `operationFinished`). A reload also deletes the view's own watcher and builds a new one after its read has started, so a change that lands in between raises no `fileChanged` (`updatePath`, `updateWatchedFiles`). A file read on change therefore takes two views: one with `preload: false` and `watchChanges: true` that is never reloaded holds the watcher, and one that watches nothing reads, tracks its read, and reads again with `Qt.callLater` once the handler returns when a change lands during one. `WatchedFile` in `qs.Commons` is that pair, and `Config`, `ThemeSource`, the `vgs.themes` wallpaper and the launcher's user menu read their files through it.
- A `FileView` with `preload: false` reads nothing when its path is set, and `reload()` acts as setting the path does ([FileView reference](https://quickshell.org/docs/v0.3.1/types/Quickshell.Io/FileView/) `preload` and `reload()`), so such a view emits neither `loaded` nor `loadFailed` until its data is asked for. The `vgs.updates` service's cache reader emitted neither in the nested smoke on 2026-09-29, so it keeps the default `preload` and reads once when its path is set.
- A `FileView` read whose file passes its existence check and then fails to open, as a file another process removed in between does, logs `Read of <path> failed: Unknown failure when opening file.` whatever `printErrors` says; a missing file is `FileViewError.FileNotFound` and is silent under `printErrors: false` ([`fileview.cpp`](https://git.outfoxxed.me/quickshell/quickshell/src/commit/41651d7/src/io/fileview.cpp) `FileViewReader::read`). `TuiRunner` reads each exit record once, and the presenter leaves a record the core may not have read yet in place.
- `FileView.setText` returns at once, emitting neither `saved` nor `saveFailed`, when its text equals the bytes the view holds, and a write, failed or not, leaves the view holding the bytes it tried to write ([`fileview.cpp`](https://git.outfoxxed.me/quickshell/quickshell/src/commit/41651d7/src/io/fileview.cpp) `setText`, `writeCmpData`, `saveSync`). A write of the same bytes after a failed one therefore does nothing and reports nothing; `Config` and the Hyprland layer (`HyprlandLayer.step`) read the file again first.
- A watching `FileView` adds its file and the file's directory to its `QFileSystemWatcher` once, when its path is set (`updateWatchedFiles`), and the watcher adds no path that does not exist ([`QFileSystemWatcher::addPath`](https://doc.qt.io/qt-6/qfilesystemwatcher.html#addPath)). A file whose directory is absent when the view is built is never watched, so a file created there later raises no `fileChanged`. `bin/vgsh run` creates the configuration directory and the state directory before it starts the shell, and `scripts/test-vgsh.sh` pins the state directory; the launcher makes its menu directory each time it is built, before its watch starts, and `scripts/smoke/rows/launcher.sh` reads a menu first created while it is open; `scripts/smoke/rows/themes.sh` reads the wallpaper a background built at startup draws after the first apply.
- Qt reads an eight-digit colour string as `#aarrggbb`, alpha first. The design system's portable colours are `#rrggbbaa`; `Theme.toColor` is the one place that reorders them.
- A frozen JavaScript object does not protect the channels of a QML colour value inside it: a write to `frozen.accent.r` changes the value read back. Publish a colour as a string.
- A `ShapePath` with `scale` above one loses a stroke under one path unit; scale the `Shape` item with a transform instead. A file in a module subdirectory sees no sibling type of the module by directory alone and imports the module.
- A Qt popup with `popupType: Popup.Window` is placed once on Wayland and never moved: Qt leaves repositioning to the server and sends no reposition, and its position is what the parent window's bounds allow, so a popup taller than a bar is pushed into the bar. A Quickshell `PopupWindow` anchored to the item places below the bar and moves on `anchor.updateAnchor()`; the overlays use it, with a negative bottom anchor margin as the gap.
- A pointer handler declared with a `parent` binding crashes the engine while the parent is still null; make it with `createObject` once the parent is known. A popup of a fresh bar surface opens only after the surface has drawn and taken one pointer event, so a row clicks the widget before it opens a popup.
- Qt Quick picks one cursor per window: it walks from the topmost item under the pointer down, skips an item that is hidden or disabled, and on each item takes a hovered `HoverHandler` that sets `cursorShape` before the item's own cursor, such as a `MouseArea`'s `cursorShape` or the I-beam `T.TextField` sets itself (arrow when read-only). No match unsets the window's cursor, which Qt Wayland draws as the arrow (`QQuickWindowPrivate::findCursorItemAndHandler` in `src/quick/items/qquickwindow.cpp`, `QQuickItemPrivate::effectiveCursorHandler` in `src/quick/items/qquickitem.cpp`, `QQuickTextFieldPrivate` in `src/quicktemplates/qquicktextfield.cpp`, qtdeclarative v6.11.0, read on 2026-09-29). Hover still reaches a disabled item, so a handler's `hovered` is no reading of the cursor. `PointerCursor` rests on this order ([components.md](components.md)).
- A pointer handler declared inside an item is in none of its `children`, `resources` or `data` lists (`QQuickItemPrivate::data_append`), so QML code cannot list an item's handlers. The gallery row therefore cannot see `PointerCursor`.
- Qt Wayland sets a window's cursor through `wp_cursor_shape_v1` when the compositor offers it, and draws a theme cursor itself otherwise; `Qt.PointingHandCursor` is the protocol's `pointer`. It does this per window, whatever the window's role, and only when the window's cursor changes (`QWaylandInputDevice::Pointer::updateCursor` in `src/plugins/platforms/wayland/qwaylandinputdevice.cpp`, qtbase v6.11.0). Hyprland 0.56.2 applies a shape only from the client that holds pointer focus, and logs it at debug level as `cursorImage request: shape <n> -> <name>` (`CInputManager` in `src/managers/input/InputManager.cpp`). In the nested sandbox on 2026-09-29, the bar and the launcher, both layer surfaces, the Settings and Gallery windows, both xdg toplevels, and the list of a `Select`, a popup, each sent the shape of the control under the pointer: `pointer` over one that takes a click, `default` over a disabled one or a bare surface, `text` over a text field. No gap was found. The smoke's cursor rows read those log lines ([validation-latency.md](validation-latency.md)).
- `ignoreWarning` in a QML test case catches warnings alone; a `console.error` is a critical message it does not catch.
- Qt Quick moves the focus on Tab and Backtab at the focused item when that item's `Keys` leave the key unaccepted, so the key never reaches a parent's `Keys`. A `FocusScope` that takes the focus again gives it to the child that last held it. `Dialog` keeps the keys inside with `Keys.onTabPressed` on each action and hands the focus to its accept action each time it takes the focus; `scripts/qml-tests/tst_dialog.qml` holds both.
- `Qt.createComponent` of a `.qml` file written into a directory after the engine listed that directory fails with `File name case mismatch`: the type loader checks the name against its cached listing. Measured with the Qt 6.11.2 `qml` runtime on 2026-09-29, loading one file, then writing a second beside it and loading that. A smoke row that builds several copies of a core file in `shell/Core` writes every copy before it builds the first.
- A Quickshell `FloatingWindow` is an xdg toplevel with a `title`, `minimumSize`, `maximumSize` and a `closed` signal, which it emits when the user or the compositor closes the window and not when `visible` is set false ([`windowinterface.hpp`](https://git.outfoxxed.me/quickshell/quickshell/src/tag/v0.3.1/src/window/windowinterface.hpp)). It has no app-id of its own: the xdg app-id of every toplevel the process maps is `QGuiApplication::desktopFileName()`, which Quickshell sets from the `//@ pragma AppId <id>` line among the root file's pragmas before its first `import`, `org.quickshell` without one (`src/launch/launch.cpp`, v0.3.1). A `FloatingWindow` sends no size change once it is shown (`ProxyFloatingWindow::trySetWidth`, `src/window/floatingwindow.cpp`), so `AppWindow` shows the window only once the plugin is built, at the plugin's implicit size.
- A `PopupWindow` with `grabFocus: true` is a Qt `Popup` that takes an xdg_popup grab, which the compositor dismisses on a click outside it; with `grabFocus: false` it is a Qt `ToolTip` with no grab, which an outside click leaves open ([`popupwindow.cpp`](https://git.outfoxxed.me/quickshell/quickshell/src/tag/v0.3.1/src/window/popupwindow.cpp)). `scripts/smoke/rows/surfaces.sh` and `scripts/smoke/rows/overlays.sh` read both on the nested seat.
- A type listed `internal` in a module's `qmldir` resolves only inside the module: a copy of a module file written outside it sees such a type only through an import of the directory that holds it, or from that same directory. `scripts/smoke/rows/overlays.sh` builds its copy of `Select` that way (measured with Qt 6.11.2 on 2026-09-29).
