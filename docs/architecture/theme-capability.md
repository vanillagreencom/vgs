# Theme capability

Covers: shell/Core/ThemeRunner.qml, scripts/smoke/rows/themes.sh, scripts/smoke/rows/theme-browse.sh, scripts/smoke/rows/theme-browser.sh, shell/plugins/vgs.themes/**

The `theme` capability runs the `vgsh theme` commands of [themes.md](themes.md) for a plugin. The `vgs.themes` plugin is its first-party client: [§ Plugin](#plugin).

## Capability

`shell.theme`, for a plugin naming `theme`, lists, installs and applies packages, reads the catalog, lists and sets wallpapers and downloads a catalog install's wallpapers; token values stay on `Theme`. `shell/Core/ThemeRunner.qml` owns two `vgsh theme` processes, each started as `Quickshell.shellDir + "/../bin/vgsh"`: the queue's and the download lane's. It also owns the jobs waiting for them, the last list, the last apply result and the running download's progress. [`api.md` § The shell object](../../.agents/skills/vgs-plugin/references/api.md#the-shell-object) lists the members.

- **Queue.** One job of the queue runs at a time: `list`, `apply`, `background`, `catalog`, `install`, `images`, `set` and the follow. A list asked for while the last queued job is a list joins it, and so does a catalog behind a catalog. A job starts after the call that queued it returns, so `done` never runs before the member answers.
- **Download lane.** `wallpapers(name, done)` runs `vgsh theme wallpapers --json <name>` on the lane's own process, so a list or an apply never waits behind a download of many megabytes. The lane runs one download. A second `wallpapers` while one runs answers `refused: wallpapers=<name> reason=busy` at once. The fetch holds the download lock alone and the land the theme lock ([theme-wallpapers.md § Fetch and read](theme-wallpapers.md#fetch-and-read)), so a land that meets a queue job holding the theme lock answers `reason: busy`, and the next `wallpapers` downloads again.
- **Immediate refusals.** Each member answers `ok` once its job is queued, or a refusal at once for an argument no runner call can take, the argument JSON-quoted. `ThemeLogic` judges the names and paths. `apply` and `install` refuse `refused: theme=<name> reason=malformed-name` for a name `isPackageName` refuses, and `apply` answers `refused: theme=<name> reason=busy` while another apply runs or waits. `wallpapers` refuses `refused: wallpapers=<name> reason=malformed-name`. `background(step, done)` takes `next` or `previous`, else `refused: background=<step> reason=malformed-step`. `images(scope, done)` takes `applied` or `all`, else `refused: images=<scope> reason=malformed-scope`. `set(path, screen, done)` refuses `refused: set=<path> reason=malformed-path` for a path `isAbsolutePath` refuses, since the runner's working directory is the shell's, and `refused: set=<screen> reason=malformed-screen` for a screen that is neither null nor a name `isOutputName` accepts. Every other refusal arrives in `done`, since the runner makes it.
- **Follow.** `Registry` emits `scanFinished` at the end of every plugin scan attempt, the first at start, and `shell.qml` has the runner queue `vgsh theme follow --json` on it in the guarded instance alone, since a follow writes the theme and application files ([theme-follow.md](theme-follow.md)), so a shipped package a VGS update changed reaches the theme file at the next start. A follow asked for while a follow waits joins it. No plugin reaches the follow. A result whose `follow` is `reapplied` becomes `last.result`. Each follow logs `theme: follow=<outcome> state=<state>[ reason=<key>]`, as an error when its state is `failed`. A follow holds the theme lock while it runs, so a `vgsh theme` command started meanwhile is refused `reason=busy`.
- **Results.** The runner's JSON line is the answer whatever the exit code, so a refusal's exit 1, a partial apply's exit 3 and a held lock's 75 reach `done` as results. A process that fails to start emits only `runningChanged` ([runtime-qml.md](runtime-qml.md)) and answers the member's failure shape with `reason: start-failed`; an exit without a readable line answers the same with `reason: output-unreadable`. Both are logged as `theme: vgsh theme <verb> reason=<key>`, `<verb>` the member's name. An apply's failure shape is `{ state: failed, shell: failed, targets: [], theme, reason }`. A target of an apply result may be `reload-pending`: its application holds the new files and has not re-read them, and `vgsh theme reload` retries it ([theme-apply.md § Reload](theme-apply.md#reload)). A list answers `{ file, packages, reason }`: `reason` is null when the runner printed the list, and `file` and `packages` are null beside the reason otherwise. A background step answers the runner's `{ state, background, theme, path, reason }` ([theme-backgrounds.md § Commands](theme-backgrounds.md#commands)), and a failed start or an unreadable line `{ state: failed, background: null, theme: null, path: null, reason }`.

| Member | Runner command | Result | Failure shape |
|---|---|---|---|
| `catalog` | `vgsh theme catalog --json` | `{ entries, reason }`, the entries of [theme-catalog.md § Install](theme-catalog.md#install), `reason` null | `entries` null |
| `install` | `vgsh theme install --json <name>` | `{ state, theme, path, shadows, reason }` ([theme-catalog.md § Install](theme-catalog.md#install)) | `path` and `shadows` null |
| `images` | `vgsh theme background --json list [--all]` | `{ state, images, reason }` ([theme-backgrounds.md § Commands](theme-backgrounds.md#commands)) | `images` null |
| `set` | `vgsh theme background --json set <path> [--screen <screen>]` | `{ state, background, theme, path, screen, reason }` | every value null |
| `wallpapers` | `vgsh theme wallpapers --json <name>` | `{ state, theme, wallpapers, images, sha256, reason }` ([theme-wallpapers.md § Output](theme-wallpapers.md#output)) | `theme` the name, every other value null |

A failure shape carries `state: failed` where the result has a `state`. A catalog index the runner refuses prints no line, so it answers `output-unreadable` and the log names its exit. The runner keeps no background, catalog, install, image or set result.
- **Lifetimes.** Each `done` is registered in its instance's lifetime: a destroyed instance's callback is dropped and its job still runs, so an apply and a download always complete. `last` is `{ applying, result, downloading }`, `applying` the name of the apply running or waiting, or null. `downloading` is null while no download runs, else `{ name, state, bytes, total }`: the package, then the last progress line the runner printed ([theme-wallpapers.md § Output](theme-wallpapers.md#output)), with `state` null, `bytes` 0 and `total` null before the first. `bytes` counts from 0 again at each progress state. `last` lives in the runner, so a panel or an overlay closed during an apply or a download and reopened after it reads the result or the running download.
- **Readings.** `swatch(name)` is the `ok` package's `palette` from the last list, each colour through `Theme.toColor`; a refused, shadowed or unknown package has none. `modified` is the last list's `file.modified`. Both are null before the first list and after a failed one. `current`, `revision` and `fileState` are `Theme.name`, `Theme.revision` and `Theme.fileState`. `done` can run before `ThemeSource` reloads the file, so a caller that needs the new theme waits on `revision`.

## Plugin

`shell/plugins/vgs.themes` declares `bar-widget`, `panel`, `background`, `overlay` and `service`, with the capabilities `theme`, `surfaces` and `shortcut`, and composes `qs.Ui` only. The shipped bar layout does not place its widget. `vgsh plugin enable vgs.themes` places it in its `defaultSection`, `right`. The panel, the background, the overlay and the service are enabled as a first-party plugin with no placement, so the wallpaper draws, `summon panel vgs.themes` reaches the panel before the widget is placed, and `SUPER+T` reaches the browser through the service. The background and the state file it reads are [theme-backgrounds.md § Plugin](theme-backgrounds.md#plugin).

- **Widget.** One `IconButton` toggles the plugin's own panel through `surfaces`, anchored to the widget.
- **Rows.** One `ListItem` per package the last list names shows its source, the palette `swatch` answers and badges: `Displayed` for the package `Theme.name` names, `Modified` for the file's named package when the list reports the file modified, `Shadowed` and `Refused` for those list states, `Applying` for the apply `last` names. A click on an `ok` row applies it; every row is disabled while an apply runs.
- **Results.** A hidden panel is destroyed, so the panel keeps no result of its own: it reads `last` on open and after every answer. The row of the package `last.result` names shows the result's refusal reason and every target whose state is not `written`, `unchanged` or `skipped`, with the state and reason the runner wrote, then one `<target> dropped <file>` line per destination in any target's `dropped` ([D031](../decisions/D031-installed-themes-render-code-targets.md)). Only those states are named, so a target state the runner adds shows with no panel change. The lines stay until a later apply replaces the result.
- **Wallpaper.** The panel's first section names the file `WallpaperState` reads as current, or `None`, so it follows a step from the CLI as well as its own. Its Previous and Next icon buttons call `background`; both are disabled while no image is current and while a step the instance asked for runs. A refusal or a failed step is shown as a danger line until the next click.
- **Reopen.** A list asked for during an apply waits behind it. A panel opened during an apply shows `Applying <name>` from `last`, then the rows and the result once the apply ends.
- **Service.** The service registers the `themes` shortcut, `vgs.themes:themes`. The manifest binds it to `SUPER+T`. Pressing it summons the plugin's overlay with `{ "view": "themes" }`.
- **Browser.** The overlay entry is one browser with a view table. The only shipped view is `themes`; a payload without `view` opens it. A second summon of the shown view closes it. A later view can switch through the same table without changing the host. The view lists shipped, installed and catalog packages in one card list. All and Installed narrow the list. Type-to-filter matches the package name or the title label. A card image is the package's first background, else the catalog thumbnail, else a palette card from the package or catalog palette. Badges name the displayed package, catalog packages that are not installed and pinned wallpaper archives.
- **Browser apply.** Enter or a click on the selected card installs a catalog package when needed, applies it, waits until `Theme.name` names the package, then refreshes catalog and image state. If the applied catalog package has a positive wallpaper size and its imagery is not installed, the view shows a `Dialog` asking to download its wallpapers. Download runs `wallpapers(name)`, reads progress from `last.downloading`, then applies the package again. Not now leaves the package applied. A failure line names install, apply or download; a partial apply names the Themes panel as the place with target detail.
- **Omarchy.** The browser copies Omarchy's full-screen scrim, angled-card geometry, type-to-filter, Escape clear-then-close and settle-before-reveal through `CardCarousel`. It replaces Omarchy's selection-file and done-file round trip with one `theme` capability job and `last`. It drops v1's Starred filter because v2 has no starred theme state.

## Invariants

1. Through the `theme` capability a plugin applies a package and then reads `current` and `revision` move, lists every package with its state, reads a swatch alpha first and `modified` after a hand edit and `fileState` after a refused one; is refused busy and malformed at once; receives a refusal's non-zero exit and a partial apply's result, a fixture target failing beside one that lands, as its result, an unreadable result and a failed start as failures; and a destroyed instance's callbacks are dropped while its apply completes into `last`, which the rebuilt instance reads. Enforced by `scripts/smoke/rows/themes.sh` through the `acme.probe` fixture, with the sandbox's `vgsh` replaced by stand-ins for the held, unreadable and unstartable runs.
2. Applying the shipped `light` package through the `theme` capability restyles every section of the gallery. One example per section is read back as a property through the probe's `galleryColour`, never a drawn frame. Each colour equals the token `ThemeLogic.accept` resolves from `themes/light/theme.json` and differs from the `vgs` default. Enforced by `scripts/smoke/rows/themes.sh`, which applies `vgs` after it.
3. A rescan follows the applied package: a change to the installed package's accent under an unedited theme file reaches `Theme`, and `last.result.follow` is `reapplied`. Enforced by `scripts/smoke/rows/themes.sh`. The core loads once per sandbox, so no runner copy without the follow can stand in as a control; a shell that never follows fails the accent row.
4. `vgsh plugin enable vgs.themes` places the widget in the right section. A click on it opens the panel, which lists every package with its source, swatch and badges. A click on a row applies the package, and the row shows a failed target until a later apply of the package succeeds, and a file the apply dropped until a later apply drops none; a copy of the panel that reads no `dropped` names none. A hand edit keeping the package's name marks its row `Modified` until a click applies it again. A panel closed during an apply and reopened after it shows the result; one reopened during an apply names it, then shows a target state the panel names nowhere. The Wallpaper section names no image and disables its buttons while none is current, names the image an apply makes current, moves the drawn image and its name on a click on Next or Previous, and shows the runner's busy refusal under a held theme lock. Enforced by `scripts/smoke/rows/themes.sh`, which clicks through the nested seat and reads what each `ThemeRow` draws through the probe's `itemTexts` and `itemColours`, the wallpaper's labels through `itemTexts` and its buttons through `labelledGeometry`.
5. Through the `theme` capability a plugin reads the catalog, installs a catalog package and sees the catalog name it installed, lists every source's images and the applied package's, sets an image as the current one and as one screen's own, and receives the runner's refusal of a second install, an image outside every source and a download of a package that is no catalog install as its result. It is refused at once for a malformed name, scope, path and output name, and for a second download while one runs. A slow download's progress reaches `last.downloading`, an apply completes while it runs, a destroyed instance's download callback is dropped while the download completes, and the rebuilt instance reads the running download's progress. A runner that prints no result answers each member's failure shape. Enforced by `scripts/smoke/rows/theme-browse.sh` through the `acme.probe` fixture, with a stand-in runner for the slow download and the unreadable runs. Its control is a runner copy whose `wallpapers` queues the download on the queue: the smoke probe builds it beside the core's runner, and its apply waits behind its download.
6. The `vgs.themes` service registers `vgs.themes:themes`, the Hyprland layer binds it to `SUPER+T`, and the overlay opens, focuses, filters, pages, installs and applies a catalog card, offers the wallpaper download, handles Download and Not now, shows download progress from `last.downloading`, refuses unknown browser payloads and closes on Escape, the shortcut and the scrim only when no browser job runs. Enforced by `scripts/smoke/rows/theme-browser.sh`, which drives the nested seat and reads `ThemeView`, `ThemeCard`, `Badge`, `Dialog` and card images through the smoke probe.
