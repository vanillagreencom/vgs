# Runtime: Hyprland keyboard capture

Covers: scripts/smoke/rows/overlay-capture.sh, scripts/smoke/rows/key-capture.sh, scripts/smoke/rows/key-passthrough.sh

The Hyprland v0.56.2 facts the overlay keyboard capture ([D067](../decisions/D067-overlay-keyboard-capture.md)) and the key capture pass-through ([D086](../decisions/D086-key-capture-passthrough-submap.md)) rest on ([hyprland.md](hyprland.md)), each with the source or the reading that establishes it. The other Hyprland facts are in [runtime-hyprland.md](runtime-hyprland.md).

- Hyprland runs global binds before a layer surface receives a focused key. The overlay capture uses a submap because a Quickshell layer with keyboard focus alone cannot stop a default-map bind behind it. Read in `scripts/smoke/rows/overlay-capture.sh` on host cachy on 2026-09-29: a harness `SUPER+K` bind wrote no marker while `vgs:overlay` was mapped.
- In Hyprland v0.56.2, `hl.bind` made inside a submap belongs to that submap, and an active submap blocks default-map binds while unbound keys still go to the focused surface. `hl.dsp.submap("reset")` returns to the default map. Read in `scripts/smoke/rows/overlay-capture.sh` on host cachy on 2026-09-29: the same `SUPER+K` bind fired after Escape closed the browser.
- A mapped overlay under the capture submap keeps unbound text off a later mapped xdg toplevel. Read in `scripts/smoke/rows/overlay-capture.sh` on host cachy on 2026-09-29: a helper toplevel mapped behind the theme browser logged no `key` line after `z`, and a copy of `SummonHost.qml` that used `WlrKeyboardFocus.OnDemand` for the overlay also logged no helper key while `vgs:capture` was active.
- `layer.closed` fires when the overlay client goes away. In the event, the closing layer can still be in the layer list, so the capture layer passes that event object into its `hl.get_layers()` scan and ignores it while it checks for other mapped `vgs:overlay` layers. Read in `scripts/smoke/rows/overlay-capture.sh` on host cachy on 2026-09-29: closing the launcher while the theme browser remained open kept `vgs:capture` active and kept `SUPER+K` blocked; a copy with an unconditional close reset let `SUPER+K` fire.
- The generated Hyprland close hook resets the active submap when the shell process that owns the mapped overlay is killed. Read in `scripts/smoke/rows/overlay-capture.sh` on host cachy on 2026-09-29: with the real hook, after the row killed the recorded `shell_qs_pid` with SIGKILL, the `vgs:overlay` layer disappeared, `hyprctl submap` returned the default map and `SUPER+K` fired; after the row replaced the close handler with `local _ = layer`, the submap stayed at `vgs:capture` and `SUPER+K` stayed blocked until the row reset it.

## Key capture pass-through

- A submap no bind names cannot be entered: `Actions::setSubmap` in `src/config/shared/actions/ConfigActions.cpp` answers `Cannot set submap <name>, submap doesn't exist (wasn't registered!)` unless a keybind belongs to it. Each change posts `submap>><name>` on the event socket and the Lua event `keybinds.submap` with the name, `""` for the default map, while the dispatch runs, so the event goes out before `hyprctl` gets its answer (`dispatchRequest` in `src/debug/HyprCtl.cpp`); `KeyCapture.qml` therefore holds a new capture's enter until an earlier leave is answered.
- `hl.timer(fn, { timeout, type })` returns a timer whose `set_enabled(true)` arms it again from that moment and `set_enabled(false)` disarms it (`src/config/lua/bindings/LuaBindingsToplevel.cpp`, `src/config/lua/objects/LuaTimer.cpp`). `CConfigManager::reload` in `src/config/lua/ConfigManager.cpp` cancels every Lua timer and starts a new Lua state before it runs `hyprland.lua` again, so the layer leaves the submap each time it loads.
- In a Lua session `hyprctl dispatch <request>` evaluates `return hl.dispatch(<request>)` (`dispatchRequest` in `src/debug/HyprCtl.cpp`), and `hl.dispatch` takes a Lua function as well as a dispatcher (`pushDispatcherFunction` in `src/config/lua/bindings/LuaBindingsDispatcherUtils.cpp`), so a request may name a function the layer defined; a function that raises answers its error text, not `ok`.
- While `vgs:passthrough` is current, `SUPER+SPACE`, `CTRL+ALT+T` and `F5` typed through wtype, with `input:resolve_binds_by_sym` on, reach the focused Settings window and the harness exec binds on those keys do not fire; with no enter request, the `SUPER+SPACE` bind fires and the window sees nothing. Read in `scripts/smoke/rows/key-capture.sh` on host cachy on 2026-10-01.
- The submap's Escape bind consumes Escape, so the window never sees it, and a no-op in its place keeps the submap current. The layer's `window.close` hook runs when the shell holding the window is killed with SIGKILL: with the hook, the submap read default within the row's 5 s poll after the window was gone; with the hook replaced by `local _ = passthrough`, it still read `vgs:passthrough` a second after. The timer held the submap at 5 s and left it by 14 s. A `hyprctl reload config-only` keeps the current submap, so the layer's leave as it loads is what ends it: with that leave, the submap read default after the reload; without it, `vgs:passthrough` a second after. Read in `scripts/smoke/rows/key-passthrough.sh` on host cachy on 2026-10-01.
