# The Settings window

Covers: shell/plugins/vgs.settings/**, scripts/smoke/rows/manager.sh, scripts/smoke/rows/settings.sh

The Settings window is the plugin manager's user interface: the `vgs.settings` plugin, which reaches the manager through the `manager` capability ([manager.md](manager.md)).

## The window

- **Surface.** An unanchored `panel` summon, which the panel host builds as a layer surface on the top layer, with keyboard focus on demand, when summoned and destroys on hide. `center` placement ignores reserved space, so the window is centred on the whole monitor. It is `min(size.window.width, screen width − 2 × size.window.gutter)` wide and `size.window.heightShare` of the screen's height tall, read from its `screens` capability. The gear widget summons it on its own screen; the `toggle` shortcut, `SUPER+M` in the manifest, and the IPC summon it on the focused monitor.
- **Pages.** The list page holds a search field and one row per manager row; the plugin page holds a back button and the plugin's name as a `TitleButton` whose `Menu` lists every plugin, the current one checked, and jumps to another's page. A push or pop slides on `motion.duration.normal`, so a `motion.scale` of 0 makes it instant. Escape pops the page, then hides the window.
- **Manage.** The list's heading holds an Add plugin button, `add()`. An installed plugin's page holds Update and Remove buttons, `update(id)` and `remove(id)`; a bundled plugin's page draws neither, since a bundled plugin is disabled, never updated or removed. The window sits on the top layer, over the floating terminal, so it hides once the manager answers `ok` and the user answers the terminal. A refusal keeps the window open and stays on the page, or over the list for `add()`, as a setting's does. Omarchy's shell menu opens Add, Clone and Remove in a floating terminal so the warning and the confirmation stay visible (basecamp/omarchy `e332dc9`, `omarchy-menu-plugin`); VGS takes that rule and adds the update, whose question is the diff review.
- **Requirements.** Below the status, one `RequirementRow` per `requirements` row: the command, its state as a `Badge`, Present in the success tone and Missing in the danger tone, or the warning tone for an optional command, and the purpose under it. While one is missing, an Install button calls `installRequirements(id)`, which shows the requirement notice for the plugin: it names each package, and its own Install runs them in a floating terminal.
- **Status.** Above the fields, one read-only `StatusRow` per `status` row, grouped as the fields are under `Status` and each group's heading: the label, the value in a `Badge` of its tone or as text, the hint, and the command in a `CodeLine` with a Copy button. A disabled plugin's rows, and an entry it has not published, read "Not reported". [status.md § Shown](status.md#shown) holds the rules.
- **Fields.** One `SettingField` per schema entry, in the manifest's key order, entries without a `group` first and each group under a `SectionHeader` in the order its first entry appears: a `Switch` for a boolean, a `Select` for an enum, a `Slider` with its value for a number with `min` and `max`, and a `TextField` otherwise. One `KeyField` per bind. A field shows what the configuration holds after every write, so a refused value leaves the old one in place, and the refusal stays on the page until a later call for that plugin succeeds.
- **Payload.** `{}` opens the list and `{"plugin":"<id>"}` that plugin's page, through `vgsh ipc call shell summon panel vgs.settings '<payload>'` or the plugin's own `open` IPC; the `surfaces` capability opens only its caller's surfaces, so another plugin links to a page through that command; an id no plugin has opens the list with a notice naming it, and any other key or a payload that is no object throws out of `open()`, which refuses the summon.
- **Layout.** The list's heading, search field and rows share one left and one right edge, clear of the scroll bar's gutter whether the list overflows or not, and each row's lines centre on its icon. On a page, every inline label starts `row.paddingX` in from the column, every control `field.labelWidth` plus `field.labelGap` past that edge and ends `row.paddingX` from the column's right, and each label centres on its control or value. `scripts/smoke/rows/manager.sh` reads both pages back through the probe's `descendantGeometry` and holds each within one pixel.

## Invariants

1. The window lists every plugin `listPlugins` lists, itself included, with the same enabled state, and writes enablement, a setting and a key that reach `shell.json`, the running instances and the Hyprland layer. Enforced by `scripts/smoke/rows/manager.sh`, which also reads the rows' icon, source, capabilities, binds, requirements and errors back.
2. Update, Remove and Add plugin each open their core TUI, with the plugin's id for the first two, and hide the window over it, and update and remove hand no `--yes`, so the question stays on the terminal; Install shows the requirement notice for the plugin and hides the window; a bundled plugin's page draws no Update or Remove. Enforced by `scripts/smoke/rows/manager.sh`, which clicks each button and reads the argv a stand-in terminal records, the notice the core holds and the layer list, by `scripts/test-tui-logic.js`, whose controls are table copies that pass `--yes` to update or remove, a `managerTui` copy that updates a bundled plugin and `tuiShownAnswer` copies that refuse a focused live window or take another TUI's busy key for it, and by `scripts/test-notice-logic.js`, whose control is a judge copy whose request drops the optional commands.
3. The window is the token width, or the monitor's width less two gutters when that is less, and half the monitor's height, centred on the monitor within one pixel, and it holds the keyboard once open. Enforced by `scripts/smoke/rows/manager.sh`, from the compositor's layer list; the clamp row gives the nested output a 480 by 720 mode, since a headless output stays 0x0 in the sandbox.
4. A click on a row, the title's menu with typed letters and Enter, the back button, Escape, a deep link, the shortcut, the gear and a drag of the page's scroll bar each do what the page says. Enforced by `scripts/smoke/rows/manager.sh` with the nested seat's pointer and keyboard.
5. An edit in progress survives an unrelated configuration change: the same drawn field keeps its focus, text and cursor. Enforced by `scripts/smoke/rows/settings.sh`.
