# Hyprland layer

Covers: shell/Core/HyprlandLayer.qml, shell/Core/HyprlandLayer.js, bin/vgsh-hypr-judge, scripts/test-hyprland-layer.js, scripts/test-vgsh-hypr.sh, scripts/smoke/rows/hyprland.sh, scripts/smoke/rows/windows.sh, scripts/smoke/toplevel/toplevel.c

Hyprland is configured in Lua alone; a classic `hyprland.conf` is unsupported. The shell writes one Lua file, the Hyprland layer, to `${XDG_STATE_HOME:-~/.local/state}/vgs/hypr/vgs.lua`, and one line in the user's `hyprland.lua` loads it. No plugin writes Hyprland configuration: a plugin declares its keys, blur rules and theme appearance switches as data in its manifest, and the core renders them. The core adds three constant sections of its own, the floating TUIs' window rules, the shell's application window rule and the session lock's restore. [D028](../decisions/D028-one-generated-hyprland-layer.md) records the layer, [D044](../decisions/D044-application-windows-are-hyprland-toplevels.md) records application windows, and [D048](../decisions/D048-theme-owned-hyprland-appearance.md) records the theme-owned appearance groups.

## The file

`HyprlandLayer.js` renders the text, and `PluginLogic.hyprlandSection` gives it each plugin's part. In order:

1. A header saying the file is generated and naming `vgsh hypr render`, which writes it again.
2. One Theme appearance section for each enabled group, in fixed order: `borders`, `radius`, `motion`. A disabled group writes only a comment and no `hl.*` call.
3. The floating TUIs' window rules, one `hl.window_rule` per size class, headed `-- Floating TUIs: each size class's app-id floats, centred, at its size.` `HyprlandLayer.TUI_WINDOWS` holds each class's app-id, rule name and size, and the class pattern is the app-id anchored with each dot escaped, so the two cannot differ. The section is constant: it is written whatever the plugins, and no plugin text reaches it.
4. The shell's application window rule, one `hl.window_rule` named `vgs:window`, headed `-- Application windows: the shell's windows float, centred, at the size they ask.` It matches the class `HyprlandLayer.APP_WINDOW.appId`, `org.vgs.shell`, the app-id the `//@ pragma AppId` line of `shell.qml` gives every window the shell maps, and floats and centres it with no size. The section is constant.
5. The overlay keyboard capture section, headed `-- Overlay keyboard capture: full-screen vgs overlays own keys through a submap.` It defines the `vgs:capture` submap, repeats enabled plugin binds inside it, wraps `hl.dsp.focus` and `hl.bind` once to learn default-map directional focus binds, and enters or leaves the submap from `layer.opened`, `layer.closed` and `config.reloaded` by reading `hl.get_layers()`. [D067](../decisions/D067-overlay-keyboard-capture.md) records the choice.
6. The session lock's restore, `hl.config({ misc = { allow_session_lock_restore = true } })`, headed `-- Session lock: a restarted shell takes over a lock whose client died.` It lets a new lock client take over an ext-session-lock whose client died, so a shell started after a crash while locked locks again, as Omarchy's `looknfeel.lua` sets it ([lock-polkit.md](lock-polkit.md)). Any client of the session may then take over any lock, live or dead, and so release it: Hyprland v0.56.2 refuses a second lock only with the option off (`CSessionLockManager::onNewSessionLock`). Without the option only a TTY clears Hyprland's dead-lock screen. The section is constant.
7. One section per enabled plugin whose manifest declares `hyprland` binds or layer rules, by plugin id, headed `-- <id> <version>: binds and layer rules from its manifest`. Its layer rules come first, each named `<id>:<name>` for namespace `^vgs:<name>$`, then its binds, each `hl.dsp.global("<id>:<shortcut>")` with that shortcut id as its description.

- **Theme appearance.** `borders` writes the border colours `HyprlandLayer.BORDERS` maps, `general.border_size` and `decoration.shadow.color`. `radius` writes `decoration.rounding`, `decoration.rounding_power`, `group.groupbar.rounding` and `group.groupbar.gradient_rounding`. Group tabs use the window radius times the highest monitor scale, bounded to 20, because Hyprland scales window corners per monitor but not tab rounding. `HyprlandLayer.qml` gets each screen from `Quickshell.screens` and maps it to a Hyprland monitor through `Hyprland.monitorFor(screen)`; the Quickshell 0.3.1 reference states that `Quickshell.screens` lists `ShellScreen` objects and `Hyprland.monitorFor(screen)` returns the corresponding `HyprlandMonitor`. It falls back to `ShellScreen.devicePixelRatio`, and an unknown scale counts as 1. `motion` writes one core preset for window, layer, workspace and fade leaves. It never writes `global` or `border`.
- **Appearance switches.** A plugin declares `hyprland.appearance` as a map from `borders`, `radius` or `motion` to one of its boolean schema keys. The first enabled declaration by plugin id owns the switches. Later declarations are reported as `hyprland: appearance declaration ignored for <id>: already owned by <owner>`. With no owner, borders and radius are on and motion is off. The `vgs.themes` defaults use those same values.

- **Floating TUIs.** A floating TUI's terminal opens with the app-id of its size class, and that class's rule floats the window, centres it on its monitor's work area and gives it the class's size. No plugin sets a size or a class pattern. [D028's revisit outcome](../decisions/D028-one-generated-hyprland-layer.md#revisit-outcome-2026-09-28-vgs-513) compares the rules with Omarchy's floating windows.

  | Size class | App-id | Rule | Size |
  |---|---|---|---|
  | `default` | `org.vgs.tui` | `vgs:tui` | 875 × 600 |
  | `wide` | `org.vgs.tui.wide` | `vgs:tui-wide` | 1200 × 720 |
  | `tall` | `org.vgs.tui.tall` | `vgs:tui-tall` | 875 × 900 |

- **Application windows.** A window of kind `window` ([surfaces.md](surfaces.md)) has the shell's class and its plugin's name as its title. `vgs:window` floats it and centres it on its monitor's work area, and it keeps the size it asks for. A user rule matches one window by the class and the title.
- **Keys.** A key is written `MOD+MOD+KEY`, with the modifiers `SUPER`, `CTRL`, `ALT` and `SHIFT`. `PluginLogic.hyprlandKey` puts every part in upper case and the modifiers in that order, so two spellings of one key compare equal. A bind takes the key the plugin's `plugins[].keys` entry gives its shortcut, [configuration.md § shell.json keys](configuration.md#shelljson-keys), else the manifest's. A hand edit or the Settings window's Keys rows write that entry, [manager.md](manager.md). A `null` entry unbinds it and leaves `-- unbound <id>:<shortcut>: shell.json sets its key to null`.
- **Conflicts.** A key two binds claim stays with the first plugin by id. The later bind is written as `-- skipped <key>: already bound by <id>`. A layer rule an earlier section wrote, with the same namespace and effects, is written once and noted.
- **Reports.** `vgsh plugin list` and the `listPlugins` IPC list each skipped bind, each `keys` name no bind declares, each ignored appearance owner, and a failed write, mkdir or reload among their errors, each led by `hyprland: `. `HyprlandLayer.qml` hands them to the registry, which both read, and the Settings window shows a plugin's own among its errors.
- **Overlay capture.** A full-screen overlay has namespace `vgs:overlay`. While one is mapped, Hyprland stays in `vgs:capture`. Unbound keys go to the overlay because the host gives it exclusive keyboard focus. The capture submap repeats every enabled plugin shortcut and learns user directional focus binds from dispatcher objects as `hl.bind` receives them.
- **Plugin text.** The only plugin text in the file is data the manifest judge has checked: the id, the shortcut names, the keys, the namespaces, booleans and numbers. A version or theme name reaches a comment only, with every character outside printable ASCII replaced by `?`, so a line break cannot start Lua.

## When the shell writes it

`HyprlandLayer.qml` runs in the runner's shell only. It renders once the first scan is done, the configuration is ready and the theme file is read, and again whenever the plugins, `shell.json`, enablement or the theme change. A theme apply writes `theme.json`, so it reaches the layer too. The shell writes the file by rename, only when its bytes change, then runs `hyprctl reload config-only`. `vgsh hypr render`, the `renderHyprland` IPC, reads the file again, then writes it and reloads Hyprland whatever the bytes; a request made while a step runs starts its own cycle once that step ends.

`HyprlandLayer.step` decides each step, and the QML runs it. Quickshell's `FileView` writes nothing for the bytes it last read or wrote, and keeps a failed write's bytes as those, so after a failed write the next cycle reads the file first. A text whose directory or write failed is written again only once the text changes or a render asks for it, so an unwritable directory costs one attempt per change.

## The line

`vgsh hypr wire` keeps `pcall(dofile, "<state dir>/hypr/vgs.lua")` in `${XDG_CONFIG_HOME:-~/.config}/hypr/hyprland.lua`, first when it adds it. `vgsh hypr unwire` removes every copy. Both follow the theme include line's rule, [theme-wiring.md § Wiring text](theme-wiring.md#wiring-text): a whole-line match, no other byte changed, a symlink resolved and its target replaced with its mode kept, and the file never created. A state directory holding a quote, a backslash or a line break is refused, since the line holds it in a Lua string.

When the shell's first read finds no layer file, its first write also runs `vgsh hypr wire`, which wires `hyprland.lua` if it exists. After `unwire` the layer file stays, so no later start wires it again. The shell writes nothing under `~/.config/hypr/vgs/` and uses no `require` module name, so v1's generated files and modules are left alone.

The line is first, so every setting after it wins: a later `hl.config` value, `hl.unbind("<keys>")` with the keys spelt as the layer writes them, `hl.layer_rule({ name = "<id>:<name>", enabled = false })`, which Hyprland v0.56.2 applies to the rule of that name, and `hl.window_rule({ name = "vgs:tui", enabled = false })`, which v0.56.2 applies the same way to a floating TUI's rule: a window of that class then tiles, as the sandbox reads back, and the other two classes still float. `hl.window_rule({ name = "vgs:window", enabled = false })` tiles the shell's application windows the same way. A key is better changed in `shell.json`, which needs no edit of Hyprland's files.

To let VGS own an appearance group, remove the user's own later lines for that group. Remove `general.border_size` to let the border thickness token win. Remove `decoration.rounding`, `decoration.rounding_power`, `group.groupbar.rounding` and `group.groupbar.gradient_rounding` to let the radius token win. Remove later `hl.animation` rows for windows, layers, workspaces and fades, plus `animations.enabled`, to let the motion preset win. The owner's existing `decorations.lua` and v1-generated `vgs/layout.lua` set `border_size` and `rounding` after the line, so those values override VGS until they are removed.

## Invariants

1. The manifest's `hyprland` key, a key's form, a row's `keys`, `hyprland.appearance` and each plugin's binds are decided in `PluginLogic.js`; the text, its order, the appearance owner, the conflicts, the one copy of a shared rule and the writer's sequence are decided in `HyprlandLayer.js`. Enforced by `scripts/test-hyprland-layer.js`, whose controls each remove one rule from a copy of one of the two files; its step rows include a failed write followed by the same text and then a new one, and a render asked during a reload after the file was removed.
2. The floating TUIs' window rules are written byte for byte as § The file gives them, after the Theme appearance sections and before the first plugin section, with or without plugin sections. Enforced by the same suite, which pins the text and its place; its controls drop the section, write it before Theme appearance, leave the dots in the class pattern unescaped and leave the pattern unanchored.
3. No plugin text reaches the layer's Lua but the judged data above, and a comment holds printable ASCII alone. Enforced by the same suite's manifest rows and its comment row.
4. A full-screen overlay enters `vgs:capture`, keeps enabled plugin binds live there, learns default-map directional focus binds and resets only its own submap. Enforced by `scripts/test-hyprland-layer.js`, `scripts/smoke/rows/theme-browser.sh` and `scripts/smoke/rows/overlay-capture.sh`, with controls that remove submap entry, plugin bind copy, the focus wrapper and layer-close reset.
4. `wire` never creates `hyprland.lua`, puts the line first, keeps a symlink and its target's mode, and refuses a state directory a Lua string cannot hold; `unwire` leaves the file byte for byte as it was. Enforced by `scripts/test-vgsh-hypr.sh` under a temporary HOME, with judge copies that create, skip the quoting refusal, wire on `unwire` and report every run as a change as its controls.
5. On the nested instance the first run wires the harness's `hyprland.lua` and changes no other line. Enabled plugins' binds and rules are loaded, and `SUPER+SPACE` and `SUPER+N` typed on the seat open the launcher and the inbox. A `keys` rebind, an unbind and a conflict reach Hyprland and `listPlugins`, a disabled plugin's section goes, the active border follows a theme apply, `render` writes a removed file again, `unwire` unloads the binds, and `configerrors` stays empty. The same row applies a fixture theme whose Hyprland border is 4 and radius is 8, turns the switches off and reads the compositor values back, then turns motion on and reads animations. Enforced by `scripts/smoke/rows/hyprland.sh`, which fails on a shell copy that writes the layer and never reloads Hyprland.
6. On the nested instance Hyprland v0.56.2 accepts the floating TUIs' rules with an empty `configerrors`. A window of each class, which the harness's toplevel helper maps, floats at its class's size, centred on its monitor's work area, and the helper exits 0 when the row stops it by its pid. After `hl.window_rule({ name = "vgs:tui", enabled = false })` below the line, an `org.vgs.tui` window tiles and an `org.vgs.tui.wide` window still floats. Enforced by `scripts/smoke/rows/hyprland.sh`. It failed on 2026-09-28 on a shell copy whose layer drops the section (no class floats or takes its size) and on one that names the default rule `vgs:tui-default` (the override leaves `org.vgs.tui` floating). No layer edit fails the centre row alone: v0.56.2 centres a new floating window that asks no position on the work area with or without `center` ([runtime-hyprland.md](runtime-hyprland.md)), read on a shell copy whose rules drop `center = true`.
7. On the nested instance the Settings window, of the shell's class, floats and is centred on its monitor's work area, and after `hl.window_rule({ name = "vgs:window", enabled = false })` below the line it tiles. Enforced by `scripts/smoke/rows/windows.sh`. `scripts/test-hyprland-layer.js` pins the rule byte for byte after the floating TUIs' rules and holds `shell.qml`'s AppId pragma equal to its class; its controls drop the rule, write it before the TUIs' rules, match `org.quickshell`, and drop, change or misplace the pragma.
8. The session lock's restore is written byte for byte after the overlay keyboard capture section, before any plugin section, and Hyprland v0.56.2 reads `misc:allow_session_lock_restore` back as true. Enforced by `scripts/test-hyprland-layer.js`, whose controls drop the section and turn the option off, and by `scripts/smoke/rows/lock.sh`, which reads the option and takes over a lock a killed shell left.
