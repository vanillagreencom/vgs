# Sandbox shots

Covers: scripts/sandbox-shots.sh, scripts/smoke/shot.sh, scripts/smoke/host-window.sh, scripts/test-sandbox-shots.sh

The screenshot runner of the nested sandbox, its scenes and its capture guards. The sandbox and its harness are in [validation-smoke.md](validation-smoke.md); the held mode a shot reads is in [validation-smoke-faults.md](validation-smoke-faults.md).

- `scripts/sandbox-shots.sh` takes visual evidence in the same sandbox. It answers the Hyprland consent notice and waits for the wired state before any scene, so screenshots do not capture the consent dialog and later scenes have the generated window rules. It captures the gallery, Settings with the automations' page over the automations row's stand-ins and the Jarvis page over the J09 world the harness prepares, the launcher, the notifications, the bar and its tooltips, the Agent Warden panel and the updates flyout over planted status, the Dev Tools window, the core's requirement notice, the lock screen and the polkit prompt in dark and light, with hover, selection, open-menu, empty-search and focused-error states. The `plugin-pages` scene runs only when named; it reads the Settings window's plugin list through the probe, opens every listed plugin page and captures each further scroll screen for an overflowing page. The polkit prompt is the plugin's own over the probe's stand-in flow, with `vgs.polkit` disabled: [lock-polkit.md § Validation](lock-polkit.md#validation). `scripts/readme-shots.sh` cuts the plugin README images from its shots: [readme-images.md](readme-images.md). The `narrow` scene holds a monitor 480 by 720 logical pixels and takes the bar, the panels, the Dev Tools window, the requirement notice, the launcher, the notifications and the first gallery pages again; the `settings` scene takes the Settings list and a plugin page on that monitor within itself. The `theme-browser` and `wallpaper-browser` scenes run only when named. The `rounded` mode sets `radius.sm`, `radius.md` and `radius.lg` to 6, 12 and 16, so a shot shows whether content clears its corners. A hover shot waits until its item reports the pointer over it, so it never shows a hover that did not land. `--rev` runs an older shell for a before shot, and each scene reaches what that tree ships: the gear's and the launcher entry's item type, a search cleared by keys where no Clear search exists, and Install where a Dev Tools row has no Details. `--scale 2` sets the harness's `shell_output_scale`, which holds the nested output at double its mode and scale 2 through `hold_mode` before the shell starts, so the shell draws each PNG in device pixels at the same layout. A host configure of the nested window resets a held mode, this one or `--size`'s, until a rule takes it again, so before each shot and each hover the run takes the held mode again through `hold_restore` and puts the pointer back where the scene left it (`settle_hold`, reading the harness's `pointer_at`). A shot after whose capture the output no longer reads the mode is taken once more: `shot_held` in `scripts/smoke/shot.sh` settles the hold before each capture and reads it after. A mode that cannot be taken again, or a second reset during that capture, fails the shot. `scripts/smoke/shot.sh` gives grim only the nested socket, in an empty environment. It refuses the host socket, a link to that socket, the host's runtime dir and any output directory outside `tmp/`. Each capture must differ from the shot before it. Otherwise it is the stale frame of a hidden window and fails. A grim with no frame after 10 s exits 77 with `nested-window=not-drawn`. A capture takes only the output `SHOT_OUTPUT` names, the nested compositor's first, so a headless output a scene adds, 0x0 on an NVIDIA host, cannot fail it ([runtime-hyprland-nested.md](runtime-hyprland-nested.md)). Each shot records in `shots.tsv` whether the host showed the nested window while it was taken: `hidden`, `shown`, `absent` when the host lists no window of the nested compositor, `unreadable` when the host cannot be read, `changed` when the state differed before and after the capture. The last line counts the hidden shots as `hidden=N`, and `--hidden` refuses every shot taken in another state, so a run that exits 0 proves each frame arrived while the window was hidden. `scripts/smoke/host-window.sh` reads that state through the host's `hyprctl -j clients` and `hyprctl -j monitors`, the runner's one read of the host compositor, which changes nothing there. `scripts/test-sandbox-shots.sh` is its control. Omarchy runs its acceptance screenshots (`test/acceptance.d/base-test.sh`, read 2026-09-28) as `timeout 10 grim ... || true` inside a VM session. VGS has no VM to capture from, so it uses the nested compositor, and a failed or stale capture fails instead of passing.
