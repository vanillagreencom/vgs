# Theme engine

Covers: themes/, bin/, quickshell/vshell/Services/, quickshell/vshell/Modules/Settings/

The helper derives palette roles and renders app targets. Theme packages own colour and wallpaper data; shell geometry remains a VGS setting. Agent CLI theme rendering and selection are in [agent-cli-themes.md](agent-cli-themes.md).

## Invariants

- User theme files overlay built-in files individually. Curated palettes bypass generated-palette contrast enforcement. `vshell theme lint` judges a curated palette's raw slots and reports what falls short. A vendor port that keeps an upstream colour lists the accepted shortfall in its `theme.json` under `contrastShortfalls`, as `slot`, measured `ratio` and `floor`. Lint then prints that warning as a known shortfall. An entry that matches no measured warning is itself a warning. `test_lint_reports_listed_shortfalls_as_known` in `scripts/check-vshell-helper.py` checks both. A saved copy keeps the list, and a rebuild from the applied theme takes it from the applied package, so an overlay does not hide it. `test_wallpaper_and_save_keep_terminal_slots` checks that a saved `theme.json` keeps it. See theme composition and palette derivation in `bin/vshell-helper`.
- A theme package's optional `terminal-colors.toml` holds ANSI slots as a terminal paints them, and nothing else. A slot change that a terminal needs goes there and never in `colors.toml`, because `colors.toml` also feeds the shell's derived roles, pi's interface and the app templates that read slots directly, such as Helix, Emacs, Obsidian and btop. The file's `colorN` entries reach the templates that write a real terminal palette under `terminal_*` role names; every other template keeps the palette's own slot. `terminal_slot_overrides` drops every key that is not one of the sixteen slots. `test_terminal_slot_overrides_reach_terminals_only` in `scripts/check-vshell-helper.py` checks the reach and the exclusion. `test_light_themes_read_in_a_terminal` covers catppuccin-latte, flexoki-light, horizon-light, rose-pine and white: body text and the bands under it at 4.5:1, muted text at 3:1, white's selection fill under body text at 4.5:1, and every other target rendering the same with and without the file. `test_dark_themes_read_in_a_terminal` covers only horizon: effective body slot 15 at 4.5:1 and muted slot 7 at 3:1 against the background, body text on bands 8 and 0 at 4.5:1, and every nonterminal target rendering the same with and without terminal overrides. `test_dark_themes_draw_diffs_in_two_hues` covers every bundled dark theme outside the single-hue palettes: slots 1 and 2, and slots 9 and 10, at least 60 degrees apart in HSL hue, each at HSL saturation 0.15 and 3:1 on the background, with the same render check for each theme that ships the file. The single-hue palettes ship no terminal slots, and their diffs read by the + and - glyphs: most keep red and green in one hue, and fireside's green is near-grey.
- A curated theme package's optional `ui-roles.toml` declares derived UI roles, keyed by the names `target_roles` emits. `DECLARABLE_UI_ROLES` in `bin/vshell-helper` is the authority on the set and holds the surfaces and containers, `outline`, `outlineVariant`, `muted`, `dim`, `statusBg`, `secondary`, `tertiary` and the `on*` companions of those; the semantic `error`, `warning`, `success` and `info` family and the `inverse*` roles are outside it and a key naming one is refused by name. Each of those roles is otherwise derived from the palette with no way for a vendor to supply its own: `outline`, `outlineVariant`, `muted` and `dim` are a blend of background and foreground pulled toward black or white by the contrast guards; `surfaceVariant`, the `surfaceContainer*` roles and `statusBg` are a lightness shift of the background alone; `surface`, `surfaceContainerLowest` and the three `on*` accent companions are the background verbatim and the `on*Container` roles the foreground verbatim; `secondary`, `tertiary` and the three containers are tinted from the palette's own cyan, magenta and accent. A vendor publishing its own UI palette could state none of them, so its chrome came out a grey it never published. A sibling file rather than a `[roles]` table in `colors.toml`, whose parser flattens a nested table into `roles_statusBg`; `parse_colors_toml` reads it with `normalize` off, because `normalize_color_map` emits only `COLOR_KEYS` and drops every role name. `package_ui_roles` is the one reader and every key the file states is honoured or named: a key naming no declarable role on one line, and a key whose value is not a six-digit hex on another, from the `discarded` list the parser fills, since such a value never enters the parsed map. The loose matugen-shaped fallback is skipped for this file, whose hex group is unanchored where `HEX_RE` is not: it revived a value the strict pass had already named. `declared_ui_roles` is the one owner of the curated test, called by the render, the carry and the digest fold, so a generated blueprint carries and digests none. `declared_or` inside `target_roles` is the one input: the derivation runs either way and a declaration replaces its result, so an undeclared role derives exactly as before. Each call takes its role out of a copy of what the package declared, so a declared role no assignment reads is named at runtime; the `everyroles` fixture in `scripts/check-vshell-helper.py` declares the whole set and reads each value back, which is what holds the set and the assignment sites together. Roles computed from a declared one follow it, so a declared `statusBg` gets its status text and muted text measured against itself. The contrast guards become reporters for a declared role: the tone is written as declared and every rule it misses is named in one warning on the apply result, which makes the apply partial, the same guarantee [agent-cli-themes.md](agent-cli-themes.md) states for a curated Claude Code file. `UI_ROLE_CONTRAST_RULES` holds the rules each role carries and `ui_role_shortfalls` is its one judge, over the base role map alone. Of the roles the table names, only the three accent containers carry two, their declared `on*Container` companion and the palette's own foreground, which the `vgs-shell` target still draws on them; the rest carry one. The five surfaces outside the table carry none and are never measured. A rule landing on a colour an earlier rule for the same declared role already measured is skipped, so a container declared without its companion reports its one defect once. Pulling a declared tone toward grey is the defect the file exists to remove. Declared roles are part of the palette identity: `palette_identity` folds them in under `uiRole.`, so a restyle slider moves them with the palette, each measured against the palette's own mean lightness, and the `curatedPalette` digest covers them, because a merge-style curated file's bands are picked against the roles it merges over. They also join `blueprint_preview_hash` present-only, since the preview renders from `target_roles`. `write_overlay_toml` writes, masks or removes both this file and `terminal-colors.toml`, in sorted key order, and `with_current_terminal_slots` carries the declarations onto every rebuild from the applied theme. Only a curated save touches the file at all: a generated blueprint reads no declaration, so it writes, masks and removes nothing, at any save site, under any name. `apply-colors --save`, `set-wallpaper --extract --save`, `extract-wallpaper --save` and `import-colors` each build one, and each deleted a downloaded vendor theme's only copy of its chrome. `inert_declarations_path` names the unread file once on the apply result, which makes the apply partial, since nothing else says the chrome on screen is derived rather than declared. It asks `package_ui_roles` whether the composed package declares anything, so the masking overlay and a file of unreadable values stay silent, and names the path `compose_theme_files` resolves. `CATALOG_ALLOWED_TOP_LEVEL` admits the file, or declared roles would work for built-in themes and vanish for catalog downloads. `test_declared_ui_roles_replace_the_derivation_without_a_contrast_rewrite` and `test_declared_ui_roles_move_with_a_restyle_and_survive_a_save` in `scripts/check-vshell-helper.py` check the render, the refusals, the reporter, the restyle, the carry, the digest and the preview key.
- `render_roles` in `bin/vshell-helper` is the one place a template's role map gains the terminal slots, and every template render takes its map from it. A slot takes the app's saved `app-colors.toml` override first, under a key `terminal_slot_override_keys` lists: the slot's own `terminal_*` names, then the palette's `colorN` and ANSI name. Then comes `terminal-colors.toml`, then the palette. `app_role_view` reads the same keys, so the App Theming editor shows that override on the slot's `terminal_*` row, and setting the row replaces the slot's other saved keys. `render_template` refuses a placeholder that names a role its map lacks, so a render path that skips `render_roles` fails instead of writing literal placeholder text; a brace token that names no role, such as tmux `#{pane_id}`, passes through. Every rebuild from the current theme takes the applied theme's slots from `with_current_terminal_slots`: a wallpaper change, `save-current`, and a live or saved `apply-colors` edit. It reads them from the applied blueprint in `theme-current.json`, which `applied_blueprint` returns without resolving a package, so a theme applied under a name no package carries keeps its slots; the saved package under the shell state's name answers whenever the applied blueprint carries no slots for the rebuilt mode. Because the applied blueprint wins, a package whose `terminal-colors.toml` is edited on disk reaches a rebuild only after the theme is applied again. A rebuild into the other mode takes none. Restyle adjustments move explicit terminal slots with the palette, each measured against the palette's own mean lightness; `test_restyle_moves_terminal_slots` checks it. A saved package writes the file. A theme saved with no slots removes a stale file, or, under the name of a built-in theme that ships one, writes a file holding no slots so the user overlay masks the built-in slots. A theme's preview cache key covers its terminal slots, since the preview's terminal draws them; `test_preview_key_covers_terminal_slots` checks it. `test_terminal_slot_overrides_reach_terminals_only` checks every render path, the override order and the refusal; `test_wallpaper_and_save_keep_terminal_slots` checks the carry and `test_unsaved_applied_theme_keeps_terminal_slots` checks it for an unsaved name; `test_terminal_app_overrides_show_on_their_editor_row` checks the editor row.
- A theme's per-app overrides travel with a save. `save_theme_package` renders the package's editable app files with each app's saved overrides through `render_roles` and writes them to the package's `app-colors.toml`; `theme regenerate` and the first `theme edit-app` seed render with the theme's own overrides too. A save takes its overrides from the first source that answers. First come the overrides carried on a blueprint rebuilt from the current theme: every such rebuild, including `save-current`, `set-wallpaper --save` and `apply-colors --save`, passes through `with_current_terminal_slots`, which carries the overrides of the package whose name or directory exactly matches the shell state's theme name, in the rebuilt mode. A theme applied under a name no package carries has none to carry, and a name that is only part of another package's name matches nothing. Next comes the blueprint's own package; `set-wallpaper --save` under the applied name restores it through `carry_curated_apps`, which resolves it with `current_theme_obj` by the same exact name, so it holds the same overrides the rebuild carried. Last comes the package already saved under the destination name, which answers for `import-colors` and `extract-wallpaper --save`, so a save over a package keeps the overrides set on it. `test_save_keeps_app_overrides` checks each source and the exact-name match.
- VS Code's integrated terminal is a terminal: `augment_vscode_colors` writes a package's terminal slots into its bundled curated VS Code theme's `terminal.ansi*` keys. In the package's own mode, a program printing ANSI in VS Code reads the same slots as it reads in ghostty or kitty. A blueprint that did not load supplies no slot and the curated values stand. The bundled copies take each package's saved `[vscode]` overrides too. Each bundled copy takes its label and file slug from the theme package name. The active selection uses that package identity whenever the target installs the package's curated VS Code file. Same-mode wallpaper carries select that bundled package copy. Cross-mode carries and transformed modes also select the bundled package copy, so VS Code keeps the package's original-mode terminal slots, tab label colors, and light or dark base type. A template-rendered file from an extracted wallpaper or a live color change uses a generated identity that no bundled package owns. A duplicate package slug stops the install and names both packages. `test_curated_vscode_theme_takes_the_terminal_palette` checks all of these.
- Curated app files take precedence over generated output, with one exception: a merge-style curated file, which merges into a generated render rather than replacing it, is dropped once the palette is no longer the one it was picked against, whatever moved it. `apps/claude-dark.json` and `apps/claude-light.json` are the ones this covers; [agent-cli-themes.md](agent-cli-themes.md) owns that rule. Every other curated file keeps precedence whatever the palette does. Restyle adjustments leave the stored base palette intact. `install_curated_file` copies them verbatim and renders only `{wallpaper}`, so a role placeholder in a curated file stays literal text: a change that must reach a curated file goes through that app's own reconciler, as the VS Code terminal slots do, not through a new placeholder. See app-target rendering and restyle handling in `bin/vshell-helper`.
- Generated target paths are VGS-named and are declared in each target's configuration. Review path changes against the consumers; no checker proves compatibility for all consumers.
- Enabling per-monitor wallpaper mode preserves each screen's current image and disables retained cycling. `scripts/test-switcher-scope.js` checks the transition.
- Theme applies carry distinct request ids and failed reads retain an explicitly identified displayed result. `scripts/test-theme-requests.js` checks request handling.
- A theme downloads as one archive from its `themes-vN` release, accepted only at the catalogued size and sha256, then unpacked member by member under the manifest path rule. `_catalog_fetch_verified` and `_catalog_unpack` in `bin/vshell-helper` own acceptance; `scripts/gen-theme-catalog.py` checks the generated catalog and the release pin.
- The archive streams into `~/.cache/vshell/theme-assets/` in fixed chunks, hashed as it is written, so the verified bytes are the bytes the unpack step reads back and no install holds a whole archive in memory. It is deleted once the install finishes, so the cache holds in-flight downloads only. An installed theme is composed from local directories alone, so applying it makes no network call.
- Each lock entry binds its archive to the definition files it packed. `scripts/gen-theme-catalog.py --check` refuses a catalog whose committed definitions differ from the pinned archive, and `--check-assets-published`, which CI runs, refuses a pin whose archive is not an asset of a release that exists.
- An uninstalled theme paints from `themes/thumbnails/<name>.jpg`, which ships with the package that every install carries. `theme_shipped_preview` in the helper is the one answer to what can be painted without rendering. Both callers, the catalog browser through `catalog_entries` and `theme list --json`, pass the package's own `preview.png` when it has one, and both resolve the thumbnail through `theme_thumbnail_path`.
- Reading the current theme never applies one. With no `theme.json` the helper answers with the file an apply of the default theme would write, rendered from the `vgs-shell` target without writing it, and `theme init`, which `VGSThemeService` runs at startup, is the explicit first-run apply. `test_current_theme_reads_without_applying` and `test_theme_init_applies_only_without_state` in `scripts/check-vshell-helper.py` check both; `scripts/test-theme-startup.js` checks that startup runs `theme init` before its first reads.
- Download publication holds the mutation lock only around the directory swap. Removal requires matching download identity. See `catalog_download_theme` and `catalog_owns` in the helper.
