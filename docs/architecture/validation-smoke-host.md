# Smoke host guards

Covers: scripts/smoke/rows/auth-sentinel.sh, scripts/smoke/rows/tui-guard.sh, scripts/smoke/fixtures/tui/, scripts/check-smoke-terminal.py, scripts/test-check-smoke-terminal.py

What no smoke row may reach on the host: an authentication against the host user, a plugin's real TUI script, and a host command the shell runs, which resolves to the shell's stand-in directory. The host's audio, radios, network, VPN, DDC and hidraw, and the device commands that reach them, are in [validation-smoke-devices.md](validation-smoke-devices.md). The helpers every row shares are in [validation-smoke-harness.md](validation-smoke-harness.md), and the sandbox itself in [validation-smoke.md](validation-smoke.md).

- The shell alone resolves `hyprctl` through a stand-in directory on its path, so a row can replace the command with one that cannot start and prove the dispatch queue survives it. The stand-in terminal, which `terminal_stand_in` writes as `xdg-terminal-exec` in that directory, records the argv a floating TUI's launcher hands it and runs the real presenter under the stand-in terminal rule below, so `scripts/smoke/rows/manager.sh`, `scripts/smoke/rows/tui.sh` and `scripts/smoke/rows/launcher.sh` read a launch back. `scripts/smoke/rows/devtools.sh` stands `mise`, `docker`, `podman` and `pacman` in there, so the Dev Tools plugin's queries reach no host package manager. `scripts/smoke/rows/lock.sh` stands `systemd-inhibit`, `busctl` and `dbus-monitor` in there, so the lock's before-sleep hook reaches no logind and a row announces the sleep ([lock-polkit.md § Validation](lock-polkit.md#validation)). `scripts/smoke/rows/automations.sh` stands `systemctl`, `systemd-run` and `notify-send` in there through the harness's `automations_stand_ins`, which log each call, and `automations_stand_ins_restore` puts back the files they covered, so the Automations engine reaches no systemd manager or notification server; `loginctl` stays the harness's sentinel. The harness stands `crontab` in there for the whole run, since crontab picks the caller's table by user and not by HOME ([automations.md § Invariants](automations.md#invariants)). The Hyprland layer's `hyprctl reload config-only`, which `shell/Core/HyprlandLayer.qml` runs after each write, resolves through the same directory and carries the nested `HYPRLAND_INSTANCE_SIGNATURE`, so it reaches only the nested instance; it is the core's own reload, not a theme target's hook, and `scripts/smoke/rows/hyprland.sh` reads its effect back.
- No row authenticates against the host user: the nested sandbox shares the host's PAM, polkit and faillock. The harness stands a sentinel in the shell's own PATH directory for `sudo`, `doas`, `run0`, `pkexec` and `su`, which log their argv and exit 1; for `loginctl`, which answers `show-user` alone; and for `secret-tool`, which answers `search` and `lookup` alone. It makes the sandbox tree's `bin/vgsh-browser-policy`, which runs sudo from the system directories, a sentinel too. The stand-in terminal runs no plugin's TUI script, so a row that presses a plugin step reads the argv the stand-in recorded and plants any state the run's end reads itself. A row that needs one to answer its own way stands over it with `sentinel_stand_over` and puts it back with `sentinel_restore`, which keep one list of the sentinels stood over. `scripts/smoke/rows/auth-sentinel.sh`, the last row, reads every sentinel still first on that PATH, each file the sentinel again, that list empty and the log empty; its controls log a sudo, a `loginctl enable-linger` and a `secret-tool store`. `scripts/sandbox-shots.sh` fails a run that logged one ([D061](../decisions/D061-no-manual-commands.md)).
- The stand-in terminal runs no plugin script but a smoke fixture's: the nested sandbox shares the host's files and sudo timestamp, so a plugin's real TUI script could change the host. At its start the harness copies every TUI fixture script into a read-only index in the sandbox, from `scripts/smoke/fixtures/plugins/<id>/tui/` and from `scripts/smoke/fixtures/tui/<id>/tui/`, which holds the scripts a row plants into its copy of a shipped plugin; an id in both homes stops the harness. `terminal_stand_in` hands the presenter a plugin's script only when it is `tui/<name>`, a regular file of the snapshot and not a link, and byte for byte the index's copy under the plugin's id. Any other plugin script, and every core command, runs as `true`: the presenter still writes the run's records, with code 0, and a refused script's key, plugin id and path go to a refusal log. A row reads the argv the stand-in recorded, never the script's effect; each plugin's offline suite runs its TUI scripts. `hold_runs` keeps every replaced run live until `release_runs`, so a row can read a busy key or plant the state a run's end reads, and `terminal_stand_in windowless` maps no window. `scripts/smoke/rows/tui-guard.sh`, just before `auth-sentinel.sh`, reads that the stand-in is the text `terminal_stand_in` last wrote and resolves first, that the index still matches the tree's fixtures and cannot be written, and that every refused script is one a shipped plugin holds under `tui/`. Its controls call the stand-in with the launcher's argv: an exact copy of `acme.tui`'s `wait.sh` ends with its code, while a planted script, a changed copy, the copy under another id and a path that leaves `tui/` each end with 0, touch no marker and add one refusal line; a planted refusal log naming a made-up script fails the reading once. `scripts/check-smoke-terminal.py`, a `tools` row of `scripts/validate`, refuses a line of a row, outside a comment, that names `xdg-terminal-exec`, so only `terminal_stand_in` writes the stand-in; `scripts/test-check-smoke-terminal.py` is its control.
