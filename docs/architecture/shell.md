# Shell runtime

Covers: quickshell/vshell/

QML draws the shell and coordinates services. A service owns long-lived state; a module consumes that state and draws a surface.

## Boundaries

- Display settings consume native output state from `HyprlandService` or `NiriService`. `DisplayService` owns hardware brightness. `scripts/check-display-config-fixtures.js` tests device assignment, including ambiguous Apple display models.
- Settings sidebar and section tabs share `Modals/Settings/SettingsNavigation.qml`. The registry owns stable page indexes. `scripts/test-settings-navigation.js` checks group membership, support filtering and search expansion. `scripts/qml-smoke.sh --settings` opens each available page in the isolated session.
- `Services/CompositorService.qml` owns the shared focus answer. Consumers may subscribe to the existing compositor singleton; a second external connection or competing focus owner requires review. `scripts/test-compositor-focus.js` tests focus expressions, not all subscriptions.
- The same singleton owns the toplevel and monitor refresh fan-out from Hyprland raw events; other components keep their own `rawEvent` connections for their own concerns. One list of event names per refresh it drives, neither list carrying both names of a v1/v2 pair. Every signal-driven producer of the toplevel view shares one zero-interval timer, so one user action costs one rebuild on either compositor: the Hyprland fan-out, the two `NiriService` handlers, and the `ToplevelManager` list, which reaches it everywhere. Construction and compositor detection seed the view directly, outside that rule. Remembered Niri focus stays synchronous, because `lastFocusedAppId` reads it without waiting for a rebuild. `scripts/test-compositor-events.js` checks both lists, the timers, every coalesced producer, and that no handler in a `Connections` block rebuilds outside the timer.
- `Modules/WorkspaceOverlays/OverviewWidget.qml` owns the overview's own toplevel, workspace and monitor fetches for as long as it is on screen, because `HyprlandToplevel` carries no geometry or class property and every tile's rectangle, icon and click target comes from `lastIpcObject`, which only an explicit fetch fills. That is the other half of the split above: the fan-out issues no toplevel fetch. The overview builds one widget per screen, so one action asks for those fetches once per monitor; in Quickshell 0.3.1 each stays one round trip, because `HyprlandIpc` drops a second request while the first is outstanding. That guard is an internal detail of the binary rather than a documented API, and nothing here reddens if a later Quickshell drops it. `scripts/test-overview-refetch.js` checks the single fetch function, its producers and the reads that depend on it.
- The bar resolves which screen a Hyprland workspace sits on from `HyprlandWorkspace.monitor`, the dedicated property Quickshell tracks from the event stream, in both `Modules/Bar/BarContent.qml` and `Modules/Bar/Widgets/WorkspaceSwitcher.qml`. `lastIpcObject.monitor` names the screen the workspace had at the last explicit fetch, and the fan-out above issues no workspace fetch, so reading it keeps a workspace moved between monitors on its old screen. `scripts/test-bar-workspace-filter.js` runs both filters over a workspace whose two monitor fields disagree.
- `Services/CaptureService.qml` owns QML capture state. The bundled plugin id stays `screenRecord` for saved layouts.
- Shared launcher panels belong under `Widgets/Launcher/`; feature-only panels stay with their consumer. See [D004](../decisions/D004-overview-search-ownership-and-plugin-boundary.md).
- Consumers reach the shared tooltip body through `VgsTooltip` or `VgsInlineTooltip`, not through the public widgets import.

## Invariants

- Only the direct child of the instance lock holder draws the desktop shell: the runner, or `flock` when `vshell run` has no backend. `shell.qml` reads its parent pid from `/proc/self/stat` and compares it with `VGS_RUNNER_PID`, because every process the shell starts inherits that variable. The greeter and `VSHELL_DISABLE_INSTANCE_GUARD=1` skip the check; only the `scripts/qml-smoke.sh` sandbox sets that variable. A refused shell logs both pids, draws nothing and signals its own exit. `scripts/test-shell-runner-guard.js` checks the parent pid test, and `scripts/qml-smoke.sh --nested` starts the shell with the check on under a stand-in parent, once admitted and once refused. The runner's lock is in [backend.md](backend.md).
- Brightness pins use connector names, not position-dependent display labels. `scripts/check-display-config-fixtures.js` checks the shared Settings, Control Center and focused-screen readers.
- Display naming selectors share the state owner's identifier transition. It moves complete backend settings and pending edits before preview or profile extraction. `scripts/check-display-config-fixtures.js` checks both formats, collision refusal and cancellation.
- Plugin-backed properties remain bindings. Setters persist through the plugin service; dependent work responds to its change notification. See the plugin service implementations under `Modules/Plugins/`.
- Destructive pill actions require a click origin; unspecified origins are IPC calls. `scripts/test-pill-hover-safety.js` checks the shared dispatch and protected actions.
- Launcher selection follows pointer movement only while its hover gate is armed. `scripts/test-launcher-hover-latch.js` checks asynchronous result replacement.
- Provider replies carry their own identity, and each usage fetch channel is bound to one provider for its life, so a payload is only ever filed under the identity it names. `scripts/test-ai-usage-logic.js` and `scripts/test-ai-usage-lifecycle.js` cover the usage widget.
- The usage widget's provider catalog has one owner: `AiUsageLogic` names every provider, its icon and whether it needs a credential, and the bar slots, the filter, the popout deck and the fetch channels are all generated from it. `scripts/test-ai-usage-wiring.js` checks that no surface spells a provider out, and `scripts/test-ai-usage-sources.js` checks the catalog against the helper's.
- AI-usage credentials are written 0600 under the state directory and reach argv nowhere; the widget hands a key to the helper on stdin. `scripts/test-ai-usage-sources.js` checks both.
- A managed icon theme costs one helper call per theme, never a process per icon. `IconThemeService` reads the name-to-path map `vshell icons index <theme>` prints and replaces it whole, so icon bindings re-evaluate once when it lands. It loads the map again when the theme or the installed desktop entries change. The helper caches the map under `~/.cache/vshell/icon-index/` and rebuilds it when the inherit chain's directory list, an `index.theme`, or a directory within two levels of a chain theme changes. `test_icon_index_picks_each_name_through_the_inherit_chain` in `scripts/check-vshell-helper.py` checks the selection and the cache.
- Where an icon theme can live has one owner: the helper's `icon_theme_base_dirs`. `list_installed_icon_themes` lists the sets under it, `ensure_bundled_icon_themes` links the sets VGS ships into the user directory it names, and the Icons settings tab draws that list as a tile per set with a sample of the set's own icons, so a user sees a set before applying it. The tab draws the tiles only while the user owns the choice and a set is installed; before the list arrives, when reading it failed, with nothing installed, and under Follow theme, it draws one line of copy in their place rather than a control that does nothing, and it names the set it draws in every one of those states without claiming a set is absent from a list it does not have. `test_icon_picker_lists_every_base_dir_and_samples_each_set` in `scripts/check-vshell-helper.py` checks the list and the samples, and `scripts/test-icon-picker.js` checks the tab's tiles and the states that replace them.
- `vshell cache prune`, which `VGS.qml` runs when it loads, owns `~/.cache/vshell/imagecache`. It deletes files named by the hash scheme `CachingImage`, the wallpaper thumbnail preloader and `TrackArtService` share until the rest fit `IMAGECACHE_MAX_BYTES`, and leaves every other name alone. Every `remote_` track art download goes before any `@NxN.png` thumbnail, and the oldest-written file goes first within each. A cache hit writes nothing, so a thumbnail in constant use carries the oldest write time and would otherwise go first. `test_cache_prune_bounds_imagecache_and_drops_unreferenced_notification_images` in `scripts/check-vshell-helper.py` checks it. The same verb reconciles notification images; see [notifications.md](notifications.md).
