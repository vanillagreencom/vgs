# Theme overlay

Covers: shell/plugins/vgs.themes/Browser.qml, shell/plugins/vgs.themes/BrowserLogic.js, shell/plugins/vgs.themes/Service.qml, shell/plugins/vgs.themes/ThemeView.qml, shell/plugins/vgs.themes/ThemeCard.qml, shell/plugins/vgs.themes/WallpaperView.qml, shell/plugins/vgs.themes/WallpaperCard.qml, shell/plugins/vgs.themes/Files.js, scripts/smoke/rows/theme-browser.sh, scripts/test-themes-browser.js

The `vgs.themes` overlay: one full-screen browser with a theme view and a wallpaper view, and the service whose shortcuts summon it. Both views drive the `theme` capability of [theme-capability.md](theme-capability.md); the rest of the plugin is [theme-capability.md § Plugin](theme-capability.md#plugin). `BrowserLogic.js` holds every decision the views make, with no QML object and no I/O.

## Overlay

- **Service.** The service registers one shortcut per view of `BrowserLogic.VIEWS`: `vgs.themes:themes`, which the manifest binds to `SUPER+T`, and `vgs.themes:wallpapers`, bound to `SUPER+W`. Pressing one summons the plugin's overlay with `{ "view": <name> }`.
- **Browser.** The overlay entry is one browser with a view table, `themes` and `wallpapers`; a payload without `view` opens `themes`. A second summon of the shown view closes it, and a summon of the other view switches to it. The view lists shipped, installed and catalog packages in one card list. All and Installed narrow the list. Type-to-filter matches the package name or the title label. A card image is the package's first background, else the catalog thumbnail, else a palette card from the package or catalog palette. Badges name the displayed package, catalog packages that are not installed and pinned wallpaper archives.
- **Browser apply.** Enter or a click on the selected card installs a catalog package when needed, applies it, waits until `Theme.name` names the package, then refreshes catalog and image state. If the applied catalog package has a positive wallpaper size and its imagery is not installed, the view shows a `Dialog` asking to download its wallpapers. Download runs `wallpapers(name)`, reads progress from `last.downloading`, then applies the package again. Not now leaves the package applied. A failure line names install, apply or download; a partial apply names the Themes panel as the place with target detail.
- **Wallpaper browser.** The `wallpapers` view reads `images("all")` and the catalog on open and splits them in `BrowserLogic.wallpaperCards`. Theme lists the applied package's images, then a download card when its catalog entry is installed, pins an archive of more than 0 bytes and has no imagery installed, or an update card when the index pins another archive than the one unpacked (`wallpaperOffer`). All lists every image, packages in name order, then the user folder, each badged with its package's label or `User folder`. With two screens or more a scope control shows, All monitors first on every open; This monitor passes `shell.screens.current.name` to `set`, All monitors passes `*`. Enter on an image sets it and holds the browser open until the set answers: it closes on success and shows a failure line otherwise. Enter on the card runs `wallpapers` on the lane, with `{ update: true }` for the update card, shows progress from `last.downloading`, applies the package again so its image shows, reads the lists again and stays open. Each view loads its card images under a generation, a clock reading taken on open and, in the wallpaper view, again when a download or an update ends: `BrowserLogic.railKey` folds it into each card's identity, and the card loads its file under it as the URL's stamp (`Files.stampedUrl`). The carousel hands a card its entry once and Qt's pixmap cache keys a decode by URL across opens, so without it a file an update replaced under its name would keep showing its old picture. The selection starts on the image the scope shows, from `WallpaperState`'s `path` or the output's `screenPaths` entry, and follows it until a key or a click moves it. The keys are `BrowserLogic.WALLPAPER_KEYS`, v1's set for a browser without a filter: Left, Up and A back, Right, Down and D forward, Home, End, Enter, Escape, S for the source, and W, Tab and Shift+Tab for the scope while its control shows, else Tab and Shift+Tab step. The view holds the keyboard itself and the rail never takes the focus, because `CardCarousel` takes Tab as a step ([runtime-qml.md](runtime-qml.md)). A segment click focuses its control and a click on the chosen segment emits no `activated`, so each segmented control in both views hands the keyboard back whenever it takes it, one event-loop turn later. v1's Add to theme, Remove and Delete are dropped ([D025](../decisions/D025-no-theme-override-layer.md): a package changes only as a whole installed package; the user's own images live in the user folder).
- **Omarchy.** The browser copies Omarchy's full-screen scrim, angled-card geometry, type-to-filter, Escape clear-then-close and settle-before-reveal through `CardCarousel`. It replaces Omarchy's selection-file and done-file round trip with one `theme` capability job and `last`. It drops v1's Starred filter because v2 has no starred theme state. Omarchy's background switcher (`bin/omarchy-theme-bg-switcher` at `basecamp/omarchy` `e332dc9`) lists the applied theme's images and the user folder for that theme with the current image selected, and sets one background for every monitor. The wallpaper view takes the preselected current image. It adds v1's All source, the scope control and the download or update card, because v2 has per-screen images ([D039](../decisions/D039-per-screen-wallpaper-map.md)) and catalog archives the user downloads on demand.

## Invariants

1. The `vgs.themes` service registers `vgs.themes:themes`, the Hyprland layer binds it to `SUPER+T`, and the overlay opens, focuses, filters, pages, installs and applies a catalog card, offers the wallpaper download, handles Download and Not now, shows download progress from `last.downloading`, refuses unknown browser payloads and closes on Escape, the shortcut and the scrim only when no browser job runs. Enforced by `scripts/smoke/rows/theme-browser.sh`, which drives the nested seat and reads `ThemeView`, `ThemeCard`, `Badge`, `Dialog` and card images through the smoke probe.
2. The `vgs.themes` service registers `vgs.themes:wallpapers`, the Hyprland layer binds it to `SUPER+W`, and the overlay opens the wallpaper view holding the keyboard, lists the applied package's images under Theme and every source's under All, flips the source on S and the scope on W, Tab and Shift+Tab while two screens show the scope control, steps on Tab with one screen, starts each open on All monitors, selects the image the scope shows, sets an image on the browser's screen alone under This monitor and on every screen with each screen's own cleared under All monitors, closes once the set lands, runs the update card on the download lane with `--update`, applies the package again and stays open with the new image listed and an image replaced under its name drawn anew, reads that image anew on the next open, and after a click on the chosen segment steps the rail on Right. In the theme view the same click leaves the scope on Right. Enforced by `scripts/smoke/rows/theme-browser.sh`, which drives the nested seat with a second headless output and reads `WallpaperView` through the probe and each screen's drawn image through the background, with copies of `WallpaperView.qml` that set every image as the current one, keep each card's identity across an update and keep the keyboard on the source control, and a copy of `ThemeView.qml` that keeps it on the scope control, as its controls. The view's decisions, `BrowserLogic.js`'s sources, scopes, cards, card rule, keys, rail identity, selection and lines, and `Files.js`'s stamped URL, are enforced by `scripts/test-themes-browser.js`, with a copy per rule as its controls.
