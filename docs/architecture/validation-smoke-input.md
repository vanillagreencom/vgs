# Smoke probe and input helpers

Covers: scripts/smoke/harness.sh, scripts/smoke/Probe.qml, scripts/smoke/pointer/, scripts/smoke/toplevel/, scripts/smoke/keyboard/

The probe readers, disposable QML controls and input helpers that smoke rows use inside the nested sandbox. The row runner, JSON transport and shell lifetime helpers are in [validation-smoke-harness.md](validation-smoke-harness.md). The host safety rules are in [validation-smoke-host.md](validation-smoke-host.md).

- The probe's `focused(hostKey, id)` reader answers `absent` before the instance exists, `no-focus` while focus is outside that instance, or `[type, label, visualFocus, ringShown, inView]` for the focused descendant. It reads a descendant `FocusRing`, the item and window boxes, and each clipping Flickable ancestor so keyboard rows can prove focus is visible and in view without adding test-only properties to shipped components.

- The probe's `galleryFocusMissing` reader holds the Gallery's required focus examples, including `DeviceRow`. The Gallery row uses that inventory check and `focused` for its Tab tour: [validation-smoke-gallery.md](validation-smoke-gallery.md).

- A row that writes a disposable QML control after shell startup writes it in a fresh subdirectory and loads the file whose basename matches the type it creates. It never writes a new `.qml` file directly into `shell/Core`, `shell/Ui` or a plugin directory after the engine may have listed that directory, because Qt caches directory listings and a later `Qt.createComponent` can fail with `File name case mismatch` ([runtime-qml.md](runtime-qml.md)).

- The probe finds a control the way a user reads it: `windowGeometry`, `scopedWindowGeometry` and their clicks match an item's `text`, an icon's `name`, an icon button's `label` or a `Select`'s `currentText`, the probe's `reads`. `revealText` and `revealScopedText` move the innermost shown scroll area holding such an item so it sits a third of the way down the view, as a wheel over that list would, and answer the new `contentY`, `unscrolled` for an item no scroll area holds, or `absent`, so a row clicks a field below the fold of a page that holds more than one scroll area; `scrollTo` moves a page's one scroll area to a position. `scrollMenu` scrolls the one open `Menu` under an instance so its highlighted entry lies part way past the top, for a shot of a cut row. `activeFocusItem` answers the type and text of the item holding the keys, and `activeFocusWithin` whether that item lies inside a page, so a keyboard row sends its next keys only once the field or the page it means has the focus. `scripts/smoke/rows/automations.sh` drives the Automations window through them.

- The probe's `viewHolding(hostKey, id, text)` answers the innermost Flickable, a `ScrollArea` or a list view included, holding the first shown item that reads `text`: its type, `contentY`, content height, height, `acceptedButtons` and window box. `setViewButtons` sets that view's `acceptedButtons` and answers the value it held, so a row's control gives one view Qt's left-button drag back. The harness's `view_pointer` drags the mouse up a third of that view, or turns the pointer helper's wheel one notch down over it, and answers `moved` or `still`. `scripts/smoke/rows/settings.sh` reads the Settings page and `scripts/smoke/rows/gallery.sh` the Gallery's slim list so, as [components.md](components.md) states the scroll rule.

- The harness builds `scripts/smoke/pointer/click.c` into the sandbox: one click, hover, drag or wheel turn through the nested compositor's virtual pointer protocol, run only with the nested socket in its environment, so a row can click a widget or click outside a menu without any tool that reaches the live seat. It builds `scripts/smoke/toplevel/toplevel.c` the same way: one xdg toplevel with the app-id and, when given, the title a row gives it, which `scripts/smoke/rows/hyprland.sh` and the application window readings of `scripts/smoke/app-window.sh` start and stop by pid and the harness's stand-in terminal maps as a run's window. It prints each keyboard enter, leave and key it receives, so a row reads which window the keyboard reached. The shell's own windows are the nested instance's clients of the shell's class, `HyprlandLayer.APP_WINDOW.appId`: `window_count`, `one_window` and `window_of` read them by title, and `at_centre`, `click_in` and `click_scoped_in` take `window:<title>` where they take a layer's namespace. `pixel` reads one pixel of the nested output through `shot_pixel` in `scripts/smoke/shot.sh`, which gives `grim` the nested socket alone. That stand-in, which `terminal_stand_in` writes as `xdg-terminal-exec` in the shell's stand-in directory below, records the argv a floating TUI's launcher hands it and runs the real presenter under the rule of [validation-smoke-host.md](validation-smoke-host.md), so `scripts/smoke/rows/manager.sh`, `scripts/smoke/rows/tui.sh` and `scripts/smoke/rows/launcher.sh` read a launch back. The shell alone resolves `hyprctl` through a stand-in directory on its path, so a row can replace the command with one that cannot start and prove the dispatch queue survives it. `scripts/smoke/rows/devtools.sh` stands `mise`, `docker`, `podman` and `pacman` in there, so the Dev Tools plugin's queries reach no host package manager, and clicks one row's button among rows that draw the same text with `click_scoped_in`. `scripts/smoke/rows/lock.sh` stands `systemd-inhibit`, `busctl` and `dbus-monitor` in there, so the lock's before-sleep hook reaches no logind and a row announces the sleep ([lock-polkit.md § Validation](lock-polkit.md#validation)). The Hyprland layer's `hyprctl reload config-only`, which `shell/Core/HyprlandLayer.qml` runs after each write, resolves through the same directory and carries the nested `HYPRLAND_INSTANCE_SIGNATURE`, so it reaches only the nested instance; it is the core's own reload, not a theme target's hook, and `scripts/smoke/rows/hyprland.sh` reads its effect back.
