# Validation

Covers: scripts/validate, bin/lib/qml-library.js, scripts/test-qml-library.js, bin/lib/check-manifests.js, scripts/check-plugin-boundary.py, scripts/test-check-manifests.js, scripts/test-check-plugin-boundary.py, scripts/test-plugin-logic.js, scripts/test-vgs-plugin.py, scripts/test-validate.sh, .github/workflows/**

How the shell's changes are checked: the check selector and its rows. The nested sandbox, its harness and the smoke's verdicts are in [validation-smoke.md](validation-smoke.md).

- `scripts/validate` owns the commands and their input globs. Local runs default to changes from the default branch's merge base, including staged, unstaged and untracked files. `--changed BASE` selects a fix round and its whitespace range; `--full` explicitly selects the whole area. Shared dependencies select every listed consumer; unknown source inputs or a failed diff select the full area. Documentation and harness-only changes run repository checks without the product smoke. A selector change runs its own control rather than every product suite. `scripts/test-validate.sh` checks selection and plants a forbidden import that escapes when its dependency edge is removed.
- The install tree check is selected when a shipped runtime file, root README, licence, installer or manifest changes. `scripts/test-install-tree.sh` installs with `DESTDIR` and `PREFIX`, runs `scripts/check-install-tree.sh`, and plants missing, extra, wrong-link, stale-target, enumerator-failure and markdown-drop controls. A new shipped file without a manifest update fails with the command to regenerate the manifest.
- The nix flake check is selected when the flake, its lock, `config/requirements.json`, the installer, the manifest or a shipped file changes. Its area is `nix`, which `offline` leaves out, while the default `all` area selects it. It needs podman or docker and a route to `cache.nixos.org`, and exits 77 without either: [distribution-nix.md](distribution-nix.md).
- The Fedora checks are selected when a file under `packaging/fedora/`, `.copr/Makefile`, `VERSION`, `bin/vgsh`, the core requirements or a plugin manifest changes; a Fedora recipe change starts no nested smoke. `scripts/fedora-container.sh`, the Fedora install test, needs podman and the network and runs by hand before publication: [distribution-fedora.md](distribution-fedora.md).
- Validation is explicit, not a commit, push or merge gate. GitHub Actions and branch rules are disabled. Run the affected checks once before delivery, and reuse the result while those inputs are unchanged. A fix round compares against the last validated commit; submitting the same content does not start another full battery.
- The document byte ceiling row, `doc_limits_check`, reports a document over its ceiling before the change lands, since VGS runs no commit gate. It runs the doc-limits checker `--against` the change base, so a change fails when it puts a document over its ceiling or grows one into the margin under it: [policy](../../.agents/skills/doc-limits/references/policy.md). Its area is `tools`, and a Markdown file, a file under `docs/` or the checker's configuration selects it; a repo row would run on every change. It measures the tree the change will commit: a scratch copy of the index into which every Markdown and docs HTML file is added as the worktree holds it, untracked ones included. The real index is not written. A missing checker, no base and a failed scratch index exit 77. `scripts/test-validate.sh` holds its controls.
- `scripts/qml-unit.sh` runs the QML unit tests under `qmltestrunner` on the offscreen platform, the area `unit`: Qt with no Wayland session. `offline` leaves it out; the default `all` area selects it when its inputs change. A missing runner exits 77. A grab of a rendered item needs the test case nested under a root item and one `wait` before the grab; a test case that is the file's root grabs an unrendered image.
- `scripts/arch-packages.sh` builds and installs both Arch recipes in a rootless podman container, the area `package`. It needs podman and the Arch mirrors; a missing podman or a failed image pull, container start, system update or dependency download exits 77. `offline` leaves it out; the default `all` area selects it when a recipe under `packaging/arch/` or the installer changes. A recipe change does not start the nested smoke. [distribution-arch.md](distribution-arch.md) states what the build asserts.
- On the offscreen platform `scripts/qml-unit.sh` uses, Qt Quick draws with its software adaptation: `GraphicsInfo.api` reads `GraphicsInfo.Software`, and forcing `QT_QUICK_BACKEND=rhi` there aborts `qmltestrunner` (measured with qmltestrunner on Qt 6.11.2 on 2026-09-28). That adaptation draws no shader effect, so a `MultiEffect` and the layer it draws are absent from a grab, while a `Shape` draws. A unit test reads such an effect's properties; `scripts/qml-tests/tst_angledcard.qml` reads `AngledCard`'s mask that way.
- `scripts/check-devtools-catalog.js` judges `shell/plugins/vgs.devtools/catalog.json` with the pure catalog judge and checks the plugin-owned appearance table in dark and light mode. Its control is `scripts/test-check-devtools-catalog.js`, which plants one catalog defect per rule and keeps accepted edge cases for backend regex options, non-latest tags and loopback database ports.
- Every check that spawns a process passes that process an explicit environment, never the developer's live one.
- Every test and sandbox run carries the test-run marker, `VGS_TEST_RUN=1`: `scripts/validate` exports it for every row, `scripts/vgsh-rows.sh` sets it in the environment every bin/vgsh suite hands vgsh, with `TMPDIR` set to the suite's scratch directory, and `scripts/smoke/harness.sh` sets it in the sandbox environment. Under it the theme judge runs a reload hook only when the target's directory, the hook's command and every `PATH` directory lie inside the scratch root, `TMPDIR`, and no variable names a live session's server: the suites' environment unsets `TMUX`, `DBUS_SESSION_BUS_ADDRESS`, `HYPRLAND_INSTANCE_SIGNATURE` and `WAYLAND_DISPLAY` and points `XDG_RUNTIME_DIR` and `TMUX_TMPDIR` into the scratch directory. Any other hook, every hook in the nested sandbox included, is refused as `reload-refused` and never starts ([theme-reload.md](theme-reload.md)). A shipped target's hook therefore never detects and signals the host's live applications from a test, whatever tree the test copied. `scripts/test-validate.sh` proves the export, and `scripts/test-vgsh-reload.sh` the refusal.
- A budget in a script names the machine and date it was measured on. Each latency reading in the smoke carries its poll interval: 10 ms for the first bar, one `qs ipc` round trip for the build records.
