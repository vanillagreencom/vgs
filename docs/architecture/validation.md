# Validation

Covers: scripts/validate, bin/lib/qml-library.js, scripts/test-qml-library.js, bin/lib/check-manifests.js, scripts/check-plugin-boundary.py, scripts/test-check-manifests.js, scripts/test-check-plugin-boundary.py, scripts/test-plugin-logic.js, scripts/test-inset.js, scripts/test-vgs-plugin.py, scripts/test-validate.sh, scripts/check-user-commands.py, scripts/test-check-user-commands.py, scripts/landing-times.py, scripts/test-landing-times.py, .github/workflows/**

How the shell's changes are checked: the check selector and its rows. The nested sandbox, its harness and the smoke's verdicts are in [validation-smoke.md](validation-smoke.md).

The shared Jarvis test environment, its private services and its behavior controls are in [validation-jarvis.md](validation-jarvis.md). It belongs to test infrastructure, not the installed shell.

The [Jarvis Session](jarvis-session.md#session) has pure reducer and effect-owner rows in the `logic` area. The protocol row also selects on the Session state judge it imports. The real daemon and nested service rows use the private Jarvis environment.

The QML unit runner and mutation controls are in [validation-qml-unit.md](validation-qml-unit.md).

The pure Jarvis guidance, speech text and language suites select from their modules, runtime assets and fixtures. Their [voice text contract](jarvis-voice.md) defines the consumer boundary and mutation evidence. The installed consumer runs in the install-tree suite and nested read-only prefix row.

The task record, event-producer and [task runner](jarvis-task-control.md#evidence) rows exercise the [coding-task contract](jarvis-tasks.md) in that environment. Each selects on its owners, the isolation helper and its fixtures.

The [playback rows](jarvis-playback.md#evidence) select on Audio, its child bootstrap, the Session judge and their shared test world. The private PipeWire row also selects on its null-sink configuration. It reads actual monitor PCM after interruption, not bytes sent to the player.

The [Jarvis audit](jarvis-audit.md#evidence) has a redaction row in `logic` and a real-file writer row in `cli`. Both select on the tool schemas, shared fixture and private environment.

The [wire brain rows](jarvis-brain.md#evidence) select both drivers on shared history, release, transport, secret and stream inputs. Each driver's vendor scripts select its own row. The [Messages row](jarvis-anthropic.md#evidence) includes schema-pinned loopback and cancellation controls.

The [Jarvis account suites](jarvis-accounts.md#evidence) select from the account judge, provider declaration, secret owner, terminal and private fixtures. Their CLI rows use the shared isolated world. The nested Jarvis row reads account status and core TUI completion.

The [router](jarvis-approval.md#evidence-and-comparison) shares inputs with the audio daemon; `scripts/test-validate.sh` controls its edges.

The standalone GPU instrument and passive-layer presentation checks are in [validation-shaders.md](validation-shaders.md).

The [local setup contract](jarvis-setup.md#evidence) adds installer controls in `tools` and a nested Settings/TUI row. The installer doubles run inside J09 and never download or install a real runtime.

- `scripts/validate` owns the commands and their input globs. Local runs default to changes from the default branch's merge base, including staged, unstaged and untracked files. `--changed BASE` selects a fix round and its whitespace range; `--full` explicitly selects the whole area. Shared dependencies select every listed consumer; unknown source inputs or a failed diff select the full area. Documentation and harness-only changes run repository checks without the product smoke. A selector change runs its own control rather than every product suite. Each executed row prints `validate: secs=<seconds> exit=<status> row=<label>`, and the final selected line carries total seconds. `scripts/test-validate.sh` checks selection and plants a forbidden import that escapes when its dependency edge is removed.
- On a readable diff-scoped run, `scripts/validate` exports `VGS_VALIDATE_CHANGED` as the NUL-delimited changed-path file it built for selection. A row may read that file to narrow its own work. The variable is unset on `--full`, an unreadable diff and an unknown input that selects the full area.
- The `runner CLI controls`, `requirement report controls` and `outdated controls` rows select bundled plugins by `shell/plugins/*/manifest.json`. Those suites run `bin/vgsh`, which reads bundled plugins through `bin/vgsh-scan`: manifest text, the manifest content hash and requirement probes. The `bundled manifests` row still selects on `shell/plugins/*`, so a scan failure on a plugin file still fails.
- The `user command text controls` row selects only the control script, bundled plugin manifests, `shell/Core/PluginLogic.js`, `shell/Core/PackageManagers.js`, `bin/*`, `config/requirements.json`, `scripts/qml_source.py` and `bin/lib/qml-library.js`. Its real-tree pass and coverage floor repeat the `user command text` row, which keeps `shell/*`.
- The nested smoke and nix flake rows do not select on root `LICENSE` or `README.md`. The smoke harness and the installer copy those files as opaque bytes. The install tree controls row keeps both and checks their installed presence.
- The repo rows always run. `whitespace_check` catches defects against the selected base. `rows_cover_tests` stops a test file with no validation row. `runtime_reads_no_scripts` keeps the installed runtime independent of `scripts/`. `private_keys_check` blocks private-key armor in the tree. `md_refs_check` protects links, heading routes, decision references and source citations across files the diff did not touch.
- The install tree check is selected when a shipped runtime file, root README, licence, installer or manifest changes. `scripts/test-install-tree.sh` installs with `DESTDIR` and `PREFIX`, runs `scripts/check-install-tree.sh`, and plants missing, extra, wrong-link, stale-target, enumerator-failure and markdown-drop controls. A new shipped file without a manifest update fails with the command to regenerate the manifest.
- The nix flake check is selected when the flake, its lock, `config/requirements.json`, the installer, the manifest or a shipped file changes. Its area is `nix`, which `offline` leaves out, while the default `all` area selects it. It needs podman or docker and a route to `cache.nixos.org`, and exits 77 without either: [distribution-nix.md](distribution-nix.md).
- The Fedora checks are selected when a file under `packaging/fedora/`, `.copr/Makefile`, `VERSION`, `bin/vgsh`, the core requirements or a plugin manifest changes; a Fedora recipe change starts no nested smoke. `scripts/fedora-container.sh`, the Fedora install test, needs podman and the network and runs by hand before publication: [distribution-fedora.md](distribution-fedora.md).
- Validation is explicit, not a commit, push or merge gate. GitHub Actions and branch rules are disabled. Run the affected checks once before delivery, and reuse the result while those inputs are unchanged. A fix round compares against the last validated commit; submitting the same content does not start another full battery.
- The document byte ceiling row, `doc_limits_check`, reports a document over its ceiling before the change lands, since VGS runs no commit gate. It runs the doc-limits checker `--against` the branch point, the default branch's merge base, whatever `--changed`, `DEV_VALIDATE_BASE` or `VGS_VALIDATE_BASE` names, so a fix round after a rebase is not charged with the base branch's own growth. A change fails when it puts a document over its ceiling or grows one into the margin under it: [policy](../../.agents/skills/doc-limits/references/policy.md). Its area is `tools`, and a Markdown file, a file under `docs/` or the checker's configuration selects it; a repo row would run on every change. It measures the tree the change will commit: a scratch copy of the index into which every Markdown and docs HTML file is added as the worktree holds it, untracked ones included. The real index is not written. A missing checker, no base and a failed scratch index exit 77. `scripts/test-validate.sh` holds its controls.
- The markdown reference row, `md_refs_check`, runs the commit-guards md-refs checker `--all`, so a dead link, section route, decision reference or `<path>.md § Heading` citation in a source comment fails before the change lands. Any tracked file can carry a citation or be the target of one, so it is a repo row and runs on every change. It reads the same kind of scratch index as the ceiling row, built from every file the worktree holds. `COMMIT_GUARDS_MD_REFS_SOURCE_PATHS` in `kendex.settings.toml` adds the extensionless scripts to the checker's source extensions. A missing checker or a failed scratch index exits 77; a checker configuration error fails. `scripts/test-validate.sh` holds its controls.
- The private-key row, `private_keys_check`, refuses a PEM private-key armor line anywhere along a line in the tree. The tree is every tracked and untracked file that git does not ignore, as it is on disk. The row does not read the index or the commits in history; GitHub secret scanning covers pushed history. It covers every key type, such as RSA, EC and OPENSSH, and the PGP private key block; certificates and public keys pass. A refusal prints the path, the line number and the armor line only, never the key body. It is a repo row and runs on every change. It has no exemption list: a test that needs a key makes it at run time. The HTTPS redirect row of the v1 converter suite makes its own key and certificate with openssl, and the suite exits 77 without openssl. A file the check cannot read fails the row. `scripts/test-validate.sh` holds its controls.
- `scripts/landing-times.py` reads GitHub repository activity through `gh api` and reports branch landings from newest to oldest. It reports total minutes from open to land, wait minutes from ready to land, and medians for all landings, push landings, pull-request landings and wait time. It exits 77 when `gh` is missing, the activity feed cannot be read, a landing cannot be measured or fewer landings than requested exist. `scripts/test-landing-times.py` supplies its controls through a stand-in `gh`.
- `scripts/test-session-lock.sh` runs the real session-lock owner through that unit entry point. Its disposable copies remove requested-state observation, secure-state observation, provider freezing and lock preservation on holder unload. The nested session row reads the fixture's delivered capability and reactive state beside the lock holder: [capabilities.md](capabilities.md).
- `scripts/arch-packages.sh` builds and installs both Arch recipes in a rootless podman container, the area `package`. It needs podman and the Arch mirrors; a missing podman or a failed image pull, container start, system update or dependency download exits 77. `offline` leaves it out; the default `all` area selects it when a recipe under `packaging/arch/`, the installer or the release tarball builder changes. A recipe change does not start the nested smoke. [distribution-arch.md](distribution-arch.md) states what the build asserts.
- `scripts/check-readme-images.py` holds each first-party plugin README to its screenshots, the table `scripts/readme-shots.sh` makes them from and the files under `docs/images/plugins/`, and selects on any change under `shell/plugins/` or `docs/images/`: [readme-images.md](readme-images.md).
- `scripts/test-displays-brightness.py`, area `cli`, selects on the `vgs.displays` brightness helper and the device fixtures it uses; what it runs and its controls are in [displays.md](displays.md#validation).
- `scripts/check-user-commands.py`, area `boundary`, holds [D061](../decisions/D061-no-manual-commands.md)'s rule on the text a user reads: each plugin's Markdown and manifest, and every string literal of the shell's QML and JavaScript, read through `instruction`, with the drawn ones read by the rules below too. It fails a clause that tells the user to run a command or names one as the subject of a verb that does a step, `instruction`; a shell code block that starts with one, `shell-block`; inline code naming one in a drawn string, or a drawn string or a `CodeLine`'s text that reads as a command line, `code-command`; and a drawn property bound to a `commandLine`, the name a judge gives a whole command a reader could run, `drawn-command-line`, which keeps the requirement notice's install command behind its Show command. A path names the command its last part does, a template literal is read with each `${...}` as an argument, and a binding reaches back over the lines its statement wraps across. Its manifest fields are path patterns, and every key the judge admits is named there or in its exempt list. A command is a head its extractors read from `bin/`, every manifest's and the core's requirements and the package-manager table, with a floor and required members so a broken extractor exits 2 rather than passing. A `<details>` block whose summary is Show command is the allowed disclosure. `vgs-plugin check` runs it with `--plugin`. `scripts/test-check-user-commands.py` plants one violation per rule and runs a copy of the check without each rule, the disclosure's reach, the string blanking of `drawn-command-line`, each form above and the floor as its controls; its manifest classification reads the judge's key lists and fails on a key named in neither list. It reads nothing outside `shell/`: the top-level README's install commands install VGS itself, before any VGS surface exists, and `docs/` is read by maintainers, not users.
- `scripts/check-devtools-catalog.js` judges `shell/plugins/vgs.devtools/catalog.json` with the pure catalog judge and checks the plugin-owned appearance table in dark and light mode. Its control is `scripts/test-check-devtools-catalog.js`, which plants one catalog defect per rule and keeps accepted edge cases for backend regex options, non-latest tags and loopback database ports.
- `scripts/check-voiceorb-shader.py` compiles the passive core visual and compares its baked pack with the shipped bytes. Its control plants invalid source, stale or absent packs, a missing compiler, iteration and texture input. Both rows select on shader source and pack changes. The compiler contract and the distinction between unit properties and compiled shader status are in [runtime-qml-shaders.md](runtime-qml-shaders.md).
- Every check that spawns a process passes that process an explicit environment, never the developer's live one.
- Every test and sandbox run carries the test-run marker, `VGS_TEST_RUN=1`: `scripts/validate` exports it for every row, `scripts/vgsh-rows.sh` sets it in the environment every bin/vgsh suite hands vgsh, with `TMPDIR` set to the suite's scratch directory, and `scripts/smoke/harness.sh` sets it in the sandbox environment. Under it the theme judge runs a reload hook only when the target's directory, the hook's command and every `PATH` directory lie inside the scratch root, `TMPDIR`, and no variable names a live session's server: the suites' environment unsets `TMUX`, `DBUS_SESSION_BUS_ADDRESS`, `HYPRLAND_INSTANCE_SIGNATURE` and `WAYLAND_DISPLAY` and points `XDG_RUNTIME_DIR` and `TMUX_TMPDIR` into the scratch directory. Any other hook, every hook in the nested sandbox included, is refused as `reload-refused` and never starts ([theme-reload.md](theme-reload.md)). A shipped target's hook therefore never detects and signals the host's live applications from a test, whatever tree the test copied. `scripts/test-validate.sh` proves the export, and `scripts/test-vgsh-reload.sh` the refusal.
- A budget in a script names the machine and date it was measured on. Each latency reading in the smoke carries its poll interval: 10 ms for the first bar, one `qs ipc` round trip for the build records. How the first-bar budget is derived: [validation-latency.md](validation-latency.md).
