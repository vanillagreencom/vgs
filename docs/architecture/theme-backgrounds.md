# Theme backgrounds

Covers: bin/lib/theme-backgrounds.js, scripts/test-vgsh-backgrounds.sh, shell/plugins/vgs.themes/Background.qml, shell/plugins/vgs.themes/WallpaperState.qml

How a theme package's `backgrounds/` images reach the screen: which image `vgsh theme apply` makes current, how `vgsh theme background next` and `previous` move on, how `set` shows one chosen image on every screen or on one output, what `list` names, and how the `vgs.themes` plugin draws it. The package format is [themes.md § Package shape](themes.md#package-shape); the apply steps are [theme-apply.md § Apply](theme-apply.md#apply). The per-screen map and its clearing on apply are [D039](../decisions/D039-per-screen-wallpaper-map.md).

## State

`bin/lib/theme-backgrounds.js` owns every read and write below; `bin/vgsh-theme-judge` calls it. The state directory is `${XDG_STATE_HOME:-~/.local/state}/vgs/`, which the first write creates.

- **Images.** A package's images are the entries of its `backgrounds/` whose name ends in `.png`, `.jpg` or `.jpeg` in any case and does not start with `.`, each a file and never a symlink ([themes.md § Trust](themes.md#trust)), in name order. Every other entry is skipped. An absent `backgrounds/` holds none, and so does a symlinked one. One that cannot be read refuses the command with `reason=unreadable`. The user folder, `${XDG_CONFIG_HOME:-~/.config}/vgs/backgrounds/`, holds images by the same rule and belongs to no package.
- **`backgrounds.json`.** `{ "schemaVersion": 1, "current": <path|null>, "stamp": <string|null>, "themes": { "<theme>": "<file>" }, "screens": { "<output>": { "path": <path>, "stamp": <string> } } }`. `current` is the absolute path of the image shown now, `stamp` that file's size and modification time, null with no image, `themes` the image `next`, `previous` or `set` last chose for each package, and `screens` the image `set --screen` chose for one Hyprland output, which that output shows in place of `current`, stamped the same way. The writer includes `screens` only while it names an output, so a file without it holds no screen image, and `schemaVersion` stays 1 ([D039](../decisions/D039-per-screen-wallpaper-map.md)). An output name starts with a letter or a digit and holds only letters, digits, `-` and `_`, as `DP-1` and `HDMI-A-1` do. The stamp makes an image replaced under its name, as `vgsh theme update` can, a change the next apply writes; a screen's stamp is taken when `set` writes it. An absent file is no current image, nothing remembered and no screen image, and that state removes the file. A file that cannot be read, parsed or judged refuses the command with `reason=unreadable`, `unparseable` or `malformed` before anything moves. The file is replaced by rename when its content changes.
- **`background`.** A symlink to the `current` image, for a lock screen or any other application that draws the theme's background. It is replaced by rename, and removed while no image is current.

## Commands

- **Apply.** Before anything moves, apply reads the state and the package's images, chooses the image `themes` remembers for the package while the package still holds it, else its first image, else none, and stamps it; a chosen image that cannot be read refuses the apply with `reason=unreadable`. After the swap, once `theme.name` holds the package name, it writes the `background` symlink and then `backgrounds.json`, with `screens` cleared, so the package shows on every screen. A write that fails refuses the apply with `reason=unwritable`. The apply result does not report the background.
- **`vgsh theme background next` and `previous`.** Under the theme lock, a step reads the package `theme.name` names and shows the image after, or before, the one apply would choose, wrapping at either end, remembers it in `themes` and writes the symlink and the file as apply does. `screens` stays as it is. It prints `ok background=<file> theme=<name> path=<image>`. Refusals print `vgsh: refused: background=<step> reason=<key>`: `not-applied` without a `theme.name`, `malformed` for one no package could have, `unknown` for a package no longer present, the package's own refusal reason, `no-backgrounds`, `busy` with exit 75, `lock-failed`, and the state reasons above.
- **`vgsh theme background set <path> [--screen <output>]`.** Under the theme lock, `set` takes exactly an image `list --all` names: one of the images above, directly in an accepted package's `backgrounds/` or in the user folder. A path relative to the working directory is read from there. The directory above `backgrounds/` is matched by its real path, so a symlink above it reaches the same place, and the state names the image by that package's or folder's own path; nothing at or below `backgrounds/` is followed. Without `--screen`, `set` makes the image current, writes the symlink and keeps `screens`. It remembers the image in `themes` only when it belongs to the package `theme.name` names, so a later step moves on from it and a later apply shows it. With `--screen` it writes that output's entry in `screens` alone, and the symlink, `current` and `themes` stay. The judge checks the output name's shape only and never asks Hyprland whether the output exists. It prints `ok background=<file> theme=<name> path=<image>[ screen=<output>]`, with `theme=-` for the user folder, which no package name can be. Refusals print `vgsh: refused: background=set reason=<key>`: `malformed-screen` with the name JSON-quoted, `outside` for a path in no accepted package's `backgrounds/` and not in the user folder, a refused or shadowed package's included, `symlink` with the symlinked image or `backgrounds/`, `absent`, `not-an-image`, `not-a-file`, `busy` with exit 75, `lock-failed`, `malformed` and `unreadable` for `theme.name`, and the state reasons above.
- **`vgsh theme background list [--all]`.** With no lock, `list` names the applied package's images, and `--all` names every accepted package's, packages in name order, then the user folder's. Each source's images are in name order, and a shadowed or refused package names none. It prints one line per image: `background=<file> theme=<name> path=<image>`, with `theme=-` for the user folder, and nothing for no image. `list` refuses `not-applied`, `malformed`, `unknown` and the package's own reason as a step does, and both forms refuse `unreadable` for a directory that cannot be read, with `vgsh: refused: background=list reason=<key>`.
- **`--json`.** `vgsh theme background --json <verb>` prints one line on stdout on every path, the refusal's included, with `state` `ok` and a null `reason`, or `state` `failed` beside the refusal's reason. A step prints `{ state, background, theme, path, reason }`: the file, the package and the image's path, and on a refusal the package once the step has read it and every other value null. `set` prints that result with `screen`, the output or null, and on a refusal the output once its shape is accepted, and the package and file once the image is found. `list` prints `{ state, images, reason }`, `images` a list of `{ background, theme, path }`, `theme` null for the user folder, and `images` null beside a refusal. The refusal line and its exit status follow as without `--json`. The `theme` capability reads the lines of a step, of `set` and of `list`: [theme-capability.md](theme-capability.md).

## Plugin

`shell/plugins/vgs.themes` declares the kind `background` beside its widget and panel: [theme-capability.md § Plugin](theme-capability.md#plugin). It is a first-party plugin, so it is enabled unless `disabledPlugins` lists it, and `vgsh plugin disable vgs.themes` turns off the drawing with the widget and the panel: [plugins.md § Kinds](plugins.md#kinds).

- **Source.** `WallpaperState.qml` is the plugin's one reader of `backgrounds.json`, one per plugin instance: the background draws `sourceFor` its screen and the panel names `current`. `sourceFor(name)` is the output's own entry in `screens` when the file holds one, else `current`, each loaded under its own `stamp`, a query a local file URL ignores, so every change decodes the image again. The reader reads the file under `Paths.stateDir` on every change, through `WatchedFile`, as [runtime-qml.md](runtime-qml.md) requires. A file whose `screens` is not a map of `path` and `stamp` strings is not the runner's. It does not watch the `background` symlink: a `FileView` watch on a symlink watches its target, since `QFileSystemWatcher` adds the path to inotify without `IN_DONT_FOLLOW` ([Qt's inotify engine](https://github.com/qt/qtbase/blob/6.11/src/corelib/io/qfilesystemwatcher_inotify.cpp)) and FileView's directory watch reports only a path it no longer watches ([`fileview.cpp`](https://git.outfoxxed.me/quickshell/quickshell/src/tag/v0.3.1/src/io/fileview.cpp) `onWatchedDirectoryChanged`). A retargeted or removed link whose target stays raises nothing.
- **Surface.** `Background.qml` is `shown` only while its image is drawn, so the host maps no surface while no image is current, the image cannot be read or the state file is not the runner's. A wallpaper another program draws then stays visible, and the host never shows its background colour alone. A new image loads while the old one stays on screen.
- **Drawing.** One `Image` fills the surface with `PreserveAspectCrop`, decoded at the screen's device-pixel size rather than at the file's size. Each screen matches its entry by the Quickshell screen's `name`, the output name Hyprland reports ([ShellScreen](https://quickshell.org/docs/v0.3.1/types/Quickshell/ShellScreen)). A screen whose own image cannot be decoded, as when the image was deleted while `screens` kept its entry, draws `current` until its entry changes. That holds when the entry names the current image under the same stamp: the screen draws nothing while that image stays current, and follows the next `current`. An unreadable image and a state file the runner did not write are logged as `background: <url> unreadable` and `background: <path> malformed`.
- **Sandbox.** The smoke harness leaves `vgs.themes` enabled, so its background is built on every screen from the start and maps no surface while the sandbox holds no `backgrounds.json`: the host rows see only their fixture's background surface. The wallpaper block in `scripts/smoke/rows/themes.sh` applies packages with images.

## Invariants

1. Apply shows a package's remembered image while the package holds it, else its first image in name order, and removes the link for a package with none; only image names count, and neither a symlinked image nor a symlinked `backgrounds/`; an image replaced under its name replaces the state file; `next` moves to the following image and wraps to the first, `previous` to the one before and wraps to the last, each remembers it and is refused busy under the theme lock, and `--json` prints the result, a refusal's included; a state file or `backgrounds/` that cannot be used refuses the apply before the theme file changes. Enforced by `scripts/test-vgsh-backgrounds.sh`, with copies that forget the remembered image, take any file, keep the link, stamp every image alike, stop at the last image, stop at the first image, step forward for `previous`, accept a malformed state file, ignore the lock, and take a symlinked image or `backgrounds/` as its controls.
2. `set` takes an image of an accepted package or of the user folder, reached through a symlink above `backgrounds/` too and on a home with no state directory yet, and refuses a symlinked image or `backgrounds/`, a path in another `backgrounds/`, a refused or shadowed package's image, a name that is no image, an absent file, a directory and a malformed output name; without `--screen` it links the image, keeps `screens` and remembers only the applied package's image, and with `--screen` it writes that output's entry alone; `next` and `previous` keep `screens` and an apply clears it; `screens` is written only while it names an output, and a file holding a screen image alone stays; a malformed `screens` map is refused; `list` names the applied package's images, and `--all` every accepted package's in name order, then the user folder's with no package. Enforced by `scripts/test-vgsh-backgrounds.sh`, with copies that create no state directory, accept a malformed `screens` map, accept any output name, write an empty `screens`, remove a file holding only a screen image, match a source by any real path, match a source by its written path alone, remember no set image, remember a user-folder image, write `current` for `--screen`, keep `screens` through an apply, drop `screens` on a step, list every source without `--all`, drop the user folder and take a refused package, as its controls. The controls that take any file, a symlinked image, a symlinked `backgrounds/` and an ignored lock also reach `set`.
3. The plugin draws a screen's own entry in `screens` on that screen alone and keeps it through `next` and `previous`, draws `current` on a screen whose own image cannot be read, a later `current` when that image was also the current one, and the applied package's image on every other screen; it requests `sourceSize` at the screen's logical size multiplied by `devicePixelRatio`, decodes to cover the screen and smaller than a larger file, follows `next`, `previous`, a later apply, two state changes back to back and an image replaced under its name, and draws no image for a package without backgrounds or a malformed state file; the host maps one surface per screen while the image is drawn and none while no image is. Enforced by `scripts/smoke/rows/themes.sh`, which reads the drawn `Image` through the probe's `images` and the surfaces from the compositor, with a copy of `Background.qml` that drops the device-pixel multiplier, a copy of `WallpaperState.qml` that ignores `screens`, a copy of `WallpaperState.qml` that never reloads the state file and a copy of `Background.qml` that is always shown as its controls.
