# Theme backgrounds

Covers: bin/lib/theme-backgrounds.js, scripts/test-vgsh-backgrounds.sh, shell/plugins/vgs.themes/Background.qml, shell/plugins/vgs.themes/WallpaperState.qml

How a theme package's `backgrounds/` images reach the screen: which image `vgsh theme apply` makes current, how `vgsh theme background next` and `previous` move on, and how the `vgs.themes` plugin draws it. The package format is [themes.md § Package shape](themes.md#package-shape); the apply steps are [theme-apply.md § Apply](theme-apply.md#apply).

## State

`bin/lib/theme-backgrounds.js` owns every read and write below; `bin/vgsh-theme-judge` calls it. The state directory is `${XDG_STATE_HOME:-~/.local/state}/vgs/`.

- **Images.** A package's images are the entries of its `backgrounds/` whose name ends in `.png`, `.jpg` or `.jpeg` in any case and does not start with `.`, each a file or a symlink to one, in name order. Every other entry is skipped. An absent `backgrounds/` holds none. One that cannot be read refuses the command with `reason=unreadable`.
- **`backgrounds.json`.** `{ "schemaVersion": 1, "current": <path|null>, "stamp": <string|null>, "themes": { "<theme>": "<file>" } }`. `current` is the absolute path of the image shown now, `stamp` that file's size and modification time, null with no image, and `themes` the image `next` or `previous` last chose for each package. The stamp makes an image replaced under its name, as `vgsh theme update` can, a change the next apply writes. An absent file is no current image and nothing remembered, and that state removes the file. A file that cannot be read, parsed or judged refuses the command with `reason=unreadable`, `unparseable` or `malformed` before anything moves. The file is replaced by rename when its content changes.
- **`background`.** A symlink to the `current` image, for a lock screen or any other application that draws the theme's background. It is replaced by rename, and removed while no image is current.

## Commands

- **Apply.** Before anything moves, apply reads the state and the package's images and chooses the image `themes` remembers for the package while the package still holds it, else its first image, else none. After the swap, once `theme.name` holds the package name, it writes the `background` symlink and then `backgrounds.json`. A write that fails refuses the apply with `reason=unwritable`, and a chosen image that can no longer be read with `reason=unreadable`. The apply result does not report the background.
- **`vgsh theme background next` and `previous`.** Under the theme lock, a step reads the package `theme.name` names and shows the image after, or before, the one apply would choose, wrapping at either end, remembers it in `themes` and writes the symlink and the file as apply does. It prints `ok background=<file> theme=<name> path=<image>`. Refusals print `vgsh: refused: background=<step> reason=<key>`: `not-applied` without a `theme.name`, `malformed` for one no package could have, `unknown` for a package no longer present, the package's own refusal reason, `no-backgrounds`, `busy` with exit 75, `lock-failed`, and the state reasons above.
- **`--json`.** `vgsh theme background --json <step>` prints one line on stdout on every path: `{ state, background, theme, path, reason }`, `state` `ok` with the file, the package and the image's path and a null reason, or `failed` beside the refusal's reason, with the package once the step has read it and every other value null. The refusal line and its exit status follow as without `--json`. The `theme` capability reads this line: [theme-capability.md](theme-capability.md).

## Plugin

`shell/plugins/vgs.themes` declares the kind `background` beside its widget and panel: [theme-capability.md § Plugin](theme-capability.md#plugin). It is a first-party plugin, so it is enabled unless `disabledPlugins` lists it, and `vgsh plugin disable vgs.themes` turns off the drawing with the widget and the panel: [plugins.md § Kinds](plugins.md#kinds).

- **Source.** `WallpaperState.qml` is the plugin's one reader of `backgrounds.json`: the background draws the image it names and the panel names it. It reads the file under `Paths.stateDir` on every change, through `WatchedFile`, as [runtime-qml.md](runtime-qml.md) requires, and loads the `current` image under its `stamp`, a query a local file URL ignores, so every change decodes the image again. It does not watch the `background` symlink: a `FileView` watch on a symlink watches its target, since `QFileSystemWatcher` adds the path to inotify without `IN_DONT_FOLLOW` ([Qt's inotify engine](https://github.com/qt/qtbase/blob/6.11/src/corelib/io/qfilesystemwatcher_inotify.cpp)) and FileView's directory watch reports only a path it no longer watches ([`fileview.cpp`](https://git.outfoxxed.me/quickshell/quickshell/src/tag/v0.3.1/src/io/fileview.cpp) `onWatchedDirectoryChanged`). A retargeted or removed link whose target stays raises nothing.
- **Surface.** `Background.qml` is `shown` only while its image is drawn, so the host maps no surface while no image is current, the image cannot be read or the state file is not the runner's. A wallpaper another program draws then stays visible, and the host never shows its background colour alone. A new image loads while the old one stays on screen.
- **Drawing.** One `Image` fills the surface with `PreserveAspectCrop`, decoded at the size that covers the screen rather than at the file's size. An unreadable image and a state file the runner did not write are logged as `background: <url> unreadable` and `background: <path> malformed`.
- **Sandbox.** The smoke harness leaves `vgs.themes` enabled, so its background is built on every screen from the start and maps no surface while the sandbox holds no `backgrounds.json`: the host rows see only their fixture's background surface. The wallpaper block in `scripts/smoke/rows/themes.sh` applies packages with images.

## Invariants

1. Apply shows a package's remembered image while the package holds it, else its first image in name order, and removes the link for a package with none; only image names count; an image replaced under its name replaces the state file; `next` moves to the following image and wraps to the first, `previous` to the one before and wraps to the last, each remembers it and is refused busy under the theme lock, and `--json` prints the result, a refusal's included; a state file or `backgrounds/` that cannot be used refuses the apply before the theme file changes. Enforced by `scripts/test-vgsh-backgrounds.sh`, with copies that forget the remembered image, take any file, keep the link, stamp every image alike, stop at the last image, stop at the first image, step forward for `previous`, accept a malformed state file and ignore the lock as its controls.
2. The plugin draws the applied package's image on every screen, decoded to cover the screen and smaller than a larger file, follows `next`, `previous`, a later apply, two state changes back to back and an image replaced under its name, and draws no image for a package without backgrounds or a malformed state file; the host maps one surface per screen while the image is drawn and none while no image is. Enforced by `scripts/smoke/rows/themes.sh`, which reads the drawn `Image` through the probe's `images` and the surfaces from the compositor, with a copy of `WallpaperState.qml` that never reloads the state file and a copy of `Background.qml` that is always shown as its controls.
