# Nested smoke

Covers: scripts/qml-smoke.sh, scripts/smoke/, scripts/test-smoke-teardown.sh, scripts/test-sandbox-shots.sh

The nested sandbox, its harness and the smoke's verdicts. The process rules the sandbox obeys are in [runtime.md § Process](runtime.md#process), and the check selector that runs the smoke is [validation.md](validation.md). The latencies the smoke reads and their budgets are in [validation-latency.md](validation-latency.md). The sandbox faults the smoke excuses as not measured, a held mode among them, are in [validation-smoke-faults.md](validation-smoke-faults.md). The harness's shared helpers, the row runner and its gates are in [validation-smoke-harness.md](validation-smoke-harness.md).

The shader frame row observes a passive layer's own window. It separates advancing presentation from quiet reduced-motion and unmapped windows, with controls in that row. GPU cost runs in a standalone scene through the same harness, with no product services: [validation-shaders.md](validation-shaders.md).

- The nested smoke stays one integration suite: its rows share state and run in a fixed order. `scripts/smoke/harness.sh` owns startup, teardown and shared readers; it sources the teardown from `scripts/smoke/teardown.sh` before it makes the sandbox. It starts the shell only once every monitor the nested compositor lists has a size, so no bar is built for Qt's placeholder screen or for Hyprland's 0x0 `FALLBACK` monitor. Hyprland lists that monitor when no output is ready two seconds after launch (`READY_TIMEOUT_TO_UNSAFE_MS` in its `src/state/FallbackState.cpp`, v0.56.2), as when a loaded host is slow to configure the nested window, and its `arrangeLayersForMonitor` in `src/render/Renderer.cpp` configures no layer surface on a monitor with no size: a bar there never lays out or reserves space. A monitor still unsized after 10 s exits 77 with `nested-monitor=unsized`.
- The core loads once per sandbox, so a control for a core QML file runs a copy of it beside the core's own. The smoke probe's `runnerLoad` builds a `ThemeRunner` copy from a file the row writes under the sandbox's `shell/Core`, where its imports resolve as the shipped file's do, and a row drives it through `runnerCall` as the capability drives the core's runner. `popupLoad` builds a copy of a popup the same way, `SummonPopup` or a `qs.Ui` overlay without its focus grab, as a child of a plugin instance, and `popupCall`, `popupRead` and `popupDrop` drive it.
- `scripts/smoke/rows/layers.sh` proves pointer pass-through with the toplevel helper's button records. The harness prepares its mask-control files before shell startup, so Qt's directory cache includes them ([runtime-qml.md](runtime-qml.md)). The probe's `layerSurfaceLoad` builds a mask-control copy with the registered plugin's real component; `popupDrop` destroys it. The row releases the original layer before clicking the copy, so the original cannot catch input the copy drops. Both pad omissions and a gap-catching mask break the row's shared input assertion. A silent copy of the toplevel helper also breaks it, after a keyboard round trip confirms the client has processed input.
- `scripts/smoke/fixtures/plugins/` holds the plugins copied into the sandbox. The offline manifest and boundary rows check every fixture. `scripts/smoke/rows/failed-builds.sh` asserts runtime refusal for `acme.broken` and `acme.nowidget`: their manifests and imports are valid, but their entry points lack properties the host assigns. These fixtures have no offline exemption.
- `scripts/smoke/rows/compositor-dispatchers.sh` runs after the application-window rows, through the existing fixture's dispatch handler. It reads the new compositor operations from Hyprland state and proves each readback fails when the transport returns `ok` without dispatching. Its windows, extra output, transport stand-in and nested mouse-focus settings are restored before the reveal rows.
- The sandbox needs `WAYLAND_DISPLAY` and `XDG_RUNTIME_DIR` in the environment and Hyprland, `qs`, `hyprctl`, `python3`, `node`, `flock`, `setpriv`, `setsid`, `git`, `dbus-daemon`, `gdbus`, `cc`, `wayland-scanner`, `wtype`, `pkg-config` with `wayland-client`, `grim`, ImageMagick (`magick` or `convert`) for the Slack custom emoji the notifications row and the shots draw, and the launcher file search's `fd`, `fzf` and `file` on the path. A missing one exits 77 and names it. `wtype` types keys on the nested seat, so a row reaches a focused input; the pointer helper also moves the pointer without a press, so a row hovers an item, and clicks the right button, so `scripts/sandbox-shots.sh` opens the launcher's file flyout. A layer surface the compositor maps gets the keyboard a moment later, so a row waits for an item of it to hold active focus before it types; one mapped while a press rests on another surface gets no click until the pointer moves, so a row hovers before it clicks there. Both were read in `scripts/smoke/rows/launcher.sh` on 2026-09-27.
- The sandbox runs two private D-Bus daemons with no service directories as the session and system buses, so the shell's notification server and polkit agent never reach the user's buses and nothing is activated on them. It sets `TMUX_TMPDIR` to the sandbox runtime dir, so a tmux command cannot find the user's live server.
- `scripts/smoke/harness.sh` copies the shell into the sandbox and adds `scripts/smoke/Probe.qml`. The copy holds no shipped theme target: the sandbox's PATH is the host's, so a shipped target would detect the host's own application, and the test-run marker ([validation.md](validation.md)) refuses its reload hook; the theme rows add the fixture targets they read. It also keeps a copy of its own `hyprland.lua` as `hyprland-harness.lua` before the shell starts, since the shell's first run wires that file, and `scripts/smoke/rows/hyprland.sh` compares the two. The observer owns test counters, instance readback and form setup. A generated alias exposes the user file view only in this copy. The shipped shell contains none of these test methods.
- `scripts/sandbox-shots.sh` takes visual evidence in the same sandbox. It captures the gallery, Settings, the launcher, the notifications, the bar and its tooltips, the Agent Warden panel and the updates flyout over planted status, the Dev Tools window and the core's requirement notice in dark and light, with hover, selection, open-menu, empty-search and focused-error states. The `narrow` scene holds a monitor 480 by 720 logical pixels and takes the bar, the panels, the Dev Tools window, the requirement notice, the launcher, the notifications and the first gallery pages again; the `settings` scene takes the Settings list and a plugin page on that monitor within itself. The `theme-browser` and `wallpaper-browser` scenes run only when named. The `rounded` mode sets `radius.sm`, `radius.md` and `radius.lg` to 6, 12 and 16, so a shot shows whether content clears its corners. A hover shot waits until its item reports the pointer over it, so it never shows a hover that did not land. `--rev` runs an older shell for a before shot, and each scene reaches what that tree ships: the gear's and the launcher entry's item type, a search cleared by keys where no Clear search exists, and Install where a Dev Tools row has no Details. `--scale 2` sets the harness's `shell_output_scale`, which holds the nested output at double its mode and scale 2 through `hold_mode` before the shell starts, so the shell draws each PNG in device pixels at the same layout, and a shot fails when the output left that mode or scale before or during its capture: `shot_held` in `scripts/smoke/shot.sh` reads the hold before and after each capture. `scripts/smoke/shot.sh` gives grim only the nested socket, in an empty environment. It refuses the host socket, a link to that socket, the host's runtime dir and any output directory outside `tmp/`. Each capture must differ from the shot before it. Otherwise it is the stale frame of a hidden window and fails. A grim with no frame after 10 s exits 77 with `nested-window=not-drawn`. A capture takes only the output `SHOT_OUTPUT` names, the nested compositor's first, so a headless output a scene adds, 0x0 on an NVIDIA host, cannot fail it ([runtime-hyprland-nested.md](runtime-hyprland-nested.md)). Each shot records in `shots.tsv` whether the host showed the nested window while it was taken: `hidden`, `shown`, `absent` when the host lists no window of the nested compositor, `unreadable` when the host cannot be read, `changed` when the state differed before and after the capture. The last line counts the hidden shots as `hidden=N`, and `--hidden` refuses every shot taken in another state, so a run that exits 0 proves each frame arrived while the window was hidden. `scripts/smoke/host-window.sh` reads that state through the host's `hyprctl -j clients` and `hyprctl -j monitors`, the runner's one read of the host compositor, which changes nothing there. `scripts/test-sandbox-shots.sh` is its control. Omarchy runs its acceptance screenshots (`test/acceptance.d/base-test.sh`, read 2026-09-28) as `timeout 10 grim ... || true` inside a VM session. VGS has no VM to capture from, so it uses the nested compositor, and a failed or stale capture fails instead of passing.
- The smoke's HiDPI row, `scripts/smoke/rows/hidpi.sh`, stops the running shell, holds the first monitor at double its mode and scale 2, and starts the sandbox's tree over the default set on it: a running shell does not follow a scale change ([runtime-qml.md](runtime-qml.md)). It reads the held mode and scale from the compositor, the screen the probe's `screenOf` reads from the `vgs.themes` background at ratio 2 and half the held mode, and the background's `sourceSize` at the held mode. Its controls drop only the scale under the hold, which the hold reads as reset, and a copy of `Background.qml` that decodes at logical pixels, which requests half the held mode. It stops its shell and gives the monitor its own mode at scale 1 again.
- The Gallery row brings each discovered `VoiceOrb` example into its viewport and captures its box through `shot_grim` on the nested socket. It requires pixels in that example's tone. The control must first draw a blue ring in a blank slot beside the examples; hiding its shader then removes those pixels. This positive check prevents a hidden-control check from passing when nothing draws. The installed Gallery exercises the same pack from a read-only prefix. The status-cache limitation is in [runtime-qml-shaders.md](runtime-qml-shaders.md). These checks establish actual drawing, not GPU cost or no-frame-swap behavior.
- The smoke harness copy, probe and last overlay-capture row are documented in [validation-smoke-harness.md](validation-smoke-harness.md).
- The smoke's log check fails on every error line except those a row provokes on purpose and names in `expected_errors`.
- The smoke's read-only prefix row installs into the sandbox and verifies that pristine tree. Before its snapshot, it replaces the installed target set with fixtures, adds the shared observer through `tree_smoke_observer`, and instruments Jarvis's child to use its [private test world](jarvis.md#evidence). It puts process-signalling stand-ins first on PATH, removes prefix write bits, restarts the installed shell, reads Jarvis's answer, waits for `theme_idle`, and runs `theme apply vgs`. It checks the installed log and compares the tree snapshots. The source and installed copies use the same observer setup in `scripts/smoke/tree.sh`; `scripts/test-sandbox-shots.sh` controls each inserted hook. The installed observer is a test fixture added after the pristine manifest check and before the read-only snapshot. Its apply control holds the theme lock and reads the `reason=busy` refusal. The row uses a user-owned non-writable tree because tests cannot make a root-owned prefix.
- The smoke's teardown runs on every exit of the harness. It ignores TERM, INT and HUP first, so a second signal cannot end it. A second signal is common: a timeout signals the runner, then the systemd unit that stops signals every process in it. It stops the recorded process groups, then gives the owner read, write and directory search permission back on the whole sandbox before it removes the sandbox and the runtime dir. The read-only prefix row gives the write bits back only at its end, so a row that fails or is signalled before then leaves a tree `rm -rf` cannot empty without that step. `--keep` keeps the sandbox with the permissions given back, so plain `rm -rf` removes it. A failed step prints `qml-smoke: cleanup=chmod-failed` or `qml-smoke: cleanup=rm-failed` with the path on stderr. SIGKILL cannot be caught, and a run killed with it leaves the sandbox behind. The orchestrator's job runner sends SIGKILL 10 s after its TERM (`JOB_UNIT_KILL_GRACE` in `.agents/skills/orch/scripts/lib/job-unit.sh`), so the teardown must finish inside that grace. `scripts/test-smoke-teardown.sh` runs the teardown after a `set -e` failure, after TERM, HUP and INT, after a second signal during the teardown and under `--keep`, and its controls remove the permission step and the signal step.
- The sandbox runtime dir is a short name under the host's `XDG_RUNTIME_DIR`. The short path leaves space for Hyprland's signature and socket names.
- The compositor keeps a destroyed layer surface in `hyprctl layers` with pid -1 until it drops it. A row that counts surfaces counts only layers with a client, and reads reserved geometry from `hyprctl monitors` for what the user feels.
