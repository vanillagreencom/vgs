# Nested smoke

Covers: scripts/qml-smoke.sh, scripts/smoke/, scripts/test-smoke-teardown.sh

The nested sandbox, its harness and the smoke's verdicts. The process rules the sandbox obeys are in [runtime.md § Process](runtime.md#process), and the check selector that runs the smoke is [validation.md](validation.md). The latencies the smoke reads and their budgets are in [validation-latency.md](validation-latency.md). The sandbox faults the smoke excuses as not measured, a held mode among them, are in [validation-smoke-faults.md](validation-smoke-faults.md). The harness's shared helpers, the row runner and its gates are in [validation-smoke-harness.md](validation-smoke-harness.md). The probe's readers, its disposable QML controls and the nested input helpers are in [validation-smoke-input.md](validation-smoke-input.md).

The shader frame row observes a passive layer's own window. It separates advancing presentation from quiet reduced-motion and unmapped windows, with controls in that row. GPU cost runs in a standalone scene through the same harness, with no product services: [validation-shaders.md](validation-shaders.md).

The physical Jarvis key row runs [the bubble row](jarvis-bubble.md#evidence) inside its scripted-port lifetime. The row reads the actual host and its presented indicator, with no bar widget, and keeps capture refusal and input pass-through separate from shader pixels.

The read-only-prefix row also exercises the installed [coding-task producer](jarvis-tasks.md) from its data copy. It writes only synthetic records inside J09 and opens no task TUI.

The [local setup row](jarvis-setup.md#evidence) runs a J09 status-process double and an allow-listed TUI fixture. It starts no real installer, downloader or inference runtime.

The [coding-task row](jarvis-task-control.md#evidence) sends task TUI requests from a gated daemon copy. The stand-in terminal holds the shipped task script's run, so no task script, agent or tmux runs.

- The nested smoke stays one integration suite: its rows share state and run in a fixed order. `scripts/smoke/harness.sh` owns startup, teardown and shared readers; it sources the teardown from `scripts/smoke/teardown.sh` before it makes the sandbox. It starts the shell only once every monitor the nested compositor lists has a size, so no bar is built for Qt's placeholder screen or for Hyprland's 0x0 `FALLBACK` monitor. Hyprland lists that monitor when no output is ready two seconds after launch (`READY_TIMEOUT_TO_UNSAFE_MS` in its `src/state/FallbackState.cpp`, v0.56.2), as when a loaded host is slow to configure the nested window, and its `arrangeLayersForMonitor` in `src/render/Renderer.cpp` configures no layer surface on a monitor with no size: a bar there never lays out or reserves space. A monitor still unsized after 10 s exits 77 with `nested-monitor=unsized`.
- `scripts/smoke/rows/layers.sh` proves pointer pass-through with the toplevel helper's button records. The harness prepares its mask-control files before shell startup, so Qt's directory cache includes them ([runtime-qml.md](runtime-qml.md)). The probe's `layerSurfaceLoad` builds a mask-control copy with the registered plugin's real component; `popupDrop` destroys it. The row releases the original layer before clicking the copy, so the original cannot catch input the copy drops. Both pad omissions and a gap-catching mask break the row's shared input assertion. A silent copy of the toplevel helper also breaks it, after a keyboard round trip confirms the client has processed input.
- `scripts/smoke/fixtures/plugins/` holds the plugins copied into the sandbox. The offline manifest and boundary rows check every fixture. `scripts/smoke/rows/failed-builds.sh` asserts runtime refusal for `acme.broken` and `acme.nowidget`: their manifests and imports are valid, but their entry points lack properties the host assigns. These fixtures have no offline exemption.
- `scripts/smoke/rows/compositor-dispatchers.sh` runs after the application-window rows, through the existing fixture's dispatch handler. It reads the new compositor operations from Hyprland state and proves each readback fails when the transport returns `ok` without dispatching. Its windows, extra output, transport stand-in and nested mouse-focus settings are restored before the reveal rows.
- A shared fixture stays neutral outside the row that owns a specialized contract. `scripts/smoke/rows/hyprland.sh` adds its keycode bind to the installed `acme.probe` only during its key checks, then restores the manifest and configuration byte for byte and reads the original enabled state back. Earlier Settings rows therefore see no Keys section from that fixture.
- `scripts/smoke/rows/hold-shortcuts.sh` installs `acme.hold` only for its rows. The harness builds the physical-key helper through its existing Wayland helper builder, with `xkbcommon` for the evdev map and modifier state. The helper keeps one keyboard alive while a key is down. Negative reads wait for a native marker in the test observer on the shell's same shortcut connection. The marker remains available after fixture disable. Healthy stopped senders resume only when the marker reader runs; they cannot satisfy a negative control by delayed delivery. The dropped-delivery control uses a functioning sender for the marker. All commands use the nested environment. The row restores configuration and disables the fixture: [hyprland-shortcuts.md § Hold shortcuts](hyprland-shortcuts.md#hold-shortcuts).
- The sandbox needs `WAYLAND_DISPLAY` and `XDG_RUNTIME_DIR` in the environment and Hyprland, `qs`, `hyprctl`, `python3`, `node`, `flock`, `setpriv`, `setsid`, `git`, `dbus-daemon`, `gdbus`, `cc`, `wayland-scanner`, `wtype`, `pkg-config` with `wayland-client` and `xkbcommon`, `grim`, ImageMagick (`magick` or `convert`) for the Slack custom emoji the notifications row and the shots draw, and the launcher file search's `fd`, `fzf` and `file` on the path. A missing one exits 77 and names it. The device rows also need `pipewire`, `wireplumber` and python-dbusmock (Arch `python-dbusmock`); a missing one records that row alone as not measured, the run exits 77 with no other failure, and every other row still runs: [validation-smoke-devices.md](validation-smoke-devices.md). `wtype` types keys on the nested seat, so a row reaches a focused input; the pointer helper also moves the pointer without a press, so a row hovers an item, and clicks the right button, so `scripts/sandbox-shots.sh` opens the launcher's file flyout. A layer surface the compositor maps gets the keyboard a moment later, so a row waits for an item of it to hold active focus before it types; one mapped while a press rests on another surface gets no click until the pointer moves, so a row hovers before it clicks there. Both were read in `scripts/smoke/rows/launcher.sh` on 2026-09-27.
- The sandbox runs two private D-Bus daemons with no service directories as the session and system buses, so the shell's notification server and polkit agent never reach the user's buses and nothing is activated on them. It sets `TMUX_TMPDIR` to the sandbox runtime dir, so a tmux command cannot find the user's live server.
- `scripts/smoke/harness.sh` copies the shell into the sandbox and adds `scripts/smoke/Probe.qml`. The copy holds no shipped theme target: the sandbox's PATH is the host's, so a shipped target would detect the host's own application, and the test-run marker ([validation.md](validation.md)) refuses its reload hook; the theme rows add the fixture targets they read. It also keeps a copy of its own `hyprland.lua` as `hyprland-harness.lua` before the shell starts. `scripts/smoke/rows/hyprland-consent.sh` presses Connect, then `scripts/smoke/rows/hyprland.sh` compares the wired file with that copy. The observer owns test counters, instance readback and form setup. A generated alias exposes the user file view only in this copy. The shipped shell contains none of these test methods.
- `scripts/sandbox-shots.sh` takes visual evidence in the same sandbox: its scenes, its held mode and its capture guards are in [validation-smoke-shots.md](validation-smoke-shots.md).
- The smoke's HiDPI row, `scripts/smoke/rows/hidpi.sh`, stops the running shell, holds the first monitor at double its mode and scale 2, and starts the sandbox's tree over the default set on it: a running shell does not follow a scale change ([runtime-qml.md](runtime-qml.md)). It reads the held mode and scale from the compositor, the screen the probe's `screenOf` reads from the `vgs.themes` background at ratio 2 and half the held mode, the background's `sourceSize` at the held mode, the Gallery `ImageText` sample's pool image and magenta pixels, and a 40-row notifications inbox opened eight times, each with its first card whole under the header and inside the list (`long_inbox_cut` in `scripts/smoke/rows/notifications-keys.sh`, whose control holds it at scale 1). The `ImageText` reading requires `sourceSize` to equal `deviceSize` and `deviceSize` to equal twice `imageSize`. Its controls drop only the scale under the hold, which the hold reads as reset, and a copy of `Background.qml` that decodes at logical pixels, which requests half the held mode. It stops its shell and gives the monitor its own mode at scale 1 again.
- The Gallery row's readings, with their controls, are in [components-gallery.md](components-gallery.md): its form, device and level-display boxes in [§ Invariants](components-gallery.md#invariants), and its Tab tour, slim list, custom-emoji pixels and VoiceOrb tones in [§ Evidence](components-gallery.md#evidence).
- `scripts/smoke/rows/overlay-capture.sh` runs after every other product row but the key capture rows, the panes row and the System window row, which restart the shell for their controls. It starts the normal tree after start-order control shells, appends harness binds to the nested `hyprland.lua`, checks capture and its controls, restores the harness Lua file and leaves a live shell for teardown.
- `scripts/smoke/rows/key-capture.sh` and `scripts/smoke/rows/key-passthrough.sh` follow `scripts/smoke/rows/overlay-capture.sh`, before `tui-guard.sh` and `auth-sentinel.sh`. Each saves the nested `hyprland.lua` with `hypr_lua_save`, appends `input:resolve_binds_by_sym`, so wtype's keys reach a bind, and the first also user binds on the captured keys, and each puts its own copy back with `hypr_lua_restore` at its end; the second leaves a live shell. `overlay-capture.sh` uses the same two helpers. Their shared readings, `key_submap`, `settings_key`, `key_field` and `key_reset`, are in `scripts/smoke/harness.sh`. `scripts/smoke/rows/notifications-keys.sh`, after `notifications.sh`, whose readers it uses, saves, appends and restores the same way to type the inbox shortcut.
- The smoke's log check fails on every error line except those a row provokes on purpose and names in `expected_errors`.
- The smoke's read-only prefix row installs into the sandbox and verifies that pristine tree. Before its snapshot, it replaces the installed target set with fixtures, adds the shared observer through `tree_smoke_observer`, and instruments Jarvis's child to use its [private test world](jarvis.md#evidence). It puts process-signalling stand-ins first on PATH, removes prefix write bits, restarts the installed shell, reads Jarvis's answer, waits for `theme_idle`, and runs `theme apply vgs`. It checks the installed log and compares the tree snapshots. The source and installed copies use the same observer setup in `scripts/smoke/tree.sh`; `scripts/test-sandbox-shots.sh` controls each inserted hook. The installed observer is a test fixture added after the pristine manifest check and before the read-only snapshot. Its apply control holds the theme lock and reads the `reason=busy` refusal. The row uses a user-owned non-writable tree because tests cannot make a root-owned prefix.
- The smoke's teardown runs on every exit of the harness. It ignores TERM, INT and HUP first, so a second signal cannot end it. A second signal is common: a timeout signals the runner, then the systemd unit that stops signals every process in it. It stops the recorded process groups, then gives the owner read, write and directory search permission back on the whole sandbox before it removes the sandbox and the runtime dir. The read-only prefix row gives the write bits back only at its end, so a row that fails or is signalled before then leaves a tree `rm -rf` cannot empty without that step. `--keep` keeps the sandbox with the permissions given back, so plain `rm -rf` removes it. A failed step prints `qml-smoke: cleanup=chmod-failed` or `qml-smoke: cleanup=rm-failed` with the path on stderr. SIGKILL cannot be caught, and a run killed with it leaves the sandbox behind. The orchestrator's job runner sends SIGKILL 10 s after its TERM (`JOB_UNIT_KILL_GRACE` in `.agents/skills/orch/scripts/lib/job-unit.sh`), so the teardown must finish inside that grace. `scripts/test-smoke-teardown.sh` runs the teardown after a `set -e` failure, after TERM, HUP and INT, after a second signal during the teardown and under `--keep`, and its controls remove the permission step and the signal step.
- The sandbox runtime dir is a short name under the host's `XDG_RUNTIME_DIR`. The short path leaves space for Hyprland's signature and socket names.
- The compositor keeps a destroyed layer surface in `hyprctl layers` with pid -1 until it drops it. A row that counts surfaces counts only layers with a client, and reads reserved geometry from `hyprctl monitors` for what the user feels.
