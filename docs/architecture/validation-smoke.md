# Nested smoke

Covers: scripts/qml-smoke.sh, scripts/smoke/, scripts/test-smoke-verdict.sh, scripts/test-smoke-teardown.sh

The nested sandbox, its harness and the smoke's verdicts. The process rules the sandbox obeys are in [runtime.md § Process](runtime.md#process), and the check selector that runs the smoke is [validation.md](validation.md).

- The nested smoke stays one integration suite: its rows share state and run in a fixed order. `scripts/smoke/harness.sh` owns startup, teardown and shared readers; it sources the teardown from `scripts/smoke/teardown.sh` before it makes the sandbox. It starts the shell only once every monitor the nested compositor lists has a size, so no bar is built for Qt's placeholder screen or for Hyprland's 0x0 `FALLBACK` monitor. Hyprland lists that monitor when no output is ready two seconds after launch (`READY_TIMEOUT_TO_UNSAFE_MS` in its `src/state/FallbackState.cpp`, v0.56.2), as when a loaded host is slow to configure the nested window, and its `arrangeLayersForMonitor` in `src/render/Renderer.cpp` configures no layer surface on a monitor with no size: a bar there never lays out or reserves space. A monitor still unsized after 10 s exits 77 with `nested-monitor=unsized`.
- The core loads once per sandbox, so a control for a core QML file runs a copy of it beside the core's own. The smoke probe's `runnerLoad` builds a `ThemeRunner` copy from a file the row writes under the sandbox's `shell/Core`, where its imports resolve as the shipped file's do, and a row drives it through `runnerCall` as the capability drives the core's runner.
- `scripts/smoke/fixtures/plugins/` holds the plugins copied into the sandbox. The offline manifest and boundary rows check every fixture. `scripts/smoke/rows/failed-builds.sh` asserts runtime refusal for `acme.broken` and `acme.nowidget`: their manifests and imports are valid, but their entry points lack properties the host assigns. These fixtures have no offline exemption.
- The sandbox needs `WAYLAND_DISPLAY` and `XDG_RUNTIME_DIR` in the environment and Hyprland, `qs`, `hyprctl`, `python3`, `node`, `flock`, `setsid`, `git`, `dbus-daemon`, `gdbus`, `cc`, `wayland-scanner`, `wtype`, `pkg-config` with `wayland-client`, and the launcher file search's `fd`, `fzf` and `file` on the path. A missing one exits 77 and names it. `wtype` types keys on the nested seat, so a row reaches a focused input; the pointer helper also moves the pointer without a press, so a row hovers an item. A layer surface the compositor maps gets the keyboard a moment later, so a row waits for an item of it to hold active focus before it types; one mapped while a press rests on another surface gets no click until the pointer moves, so a row hovers before it clicks there. Both were read in `scripts/smoke/rows/launcher.sh` on 2026-09-27.
- A row waits on a state the shell reports, never on time. `theme_idle` in `scripts/smoke/harness.sh` answers `idle` once the shell's first plugin scan has ended and its theme runner then holds no job in its queue or its download lane. `ping` answers before that scan ends, and every scan's end queues the follow, which holds the theme lock ([theme-capability.md](theme-capability.md)). A `vgsh theme` command started under the follow is refused `reason=busy`, the product's answer, so a row waits for `theme_idle` before the command and never retries it. A rescan in flight shows no job, so a row that rescans reads the rescan's effect first. `click_item` clicks a control only after the control reports the pointer over the click point: the compositor routes a click by where it has placed the surface, which can trail the layout the probe reads after the surface resizes. `scripts/smoke/rows/read-only-prefix.sh` holds `theme_idle`'s controls, and `scripts/smoke/rows/themes.sh` holds `click_item`'s.
- A row that waits for a floating TUI's run to end calls `expect_run_end` in `scripts/smoke/harness.sh`. It polls `key_idle`, the core's view of the key, every 0.2 s until the key reads `idle` or `run_end_ceiling_ms` has passed, and prints each wait as `latency_run_end_ms`. The ceiling bounds the chain from the presenter's exit to the core's runs, and the harness names the runs that measured it. A key still busy at the ceiling fails and prints the key's record files beside the core's view, so an ended record on disk that the core never listed reads as a missed listing ([runtime-qml.md](runtime-qml.md)), not as a slow run. The requirement notice's rows wait the same way, through `expect_within`, for the scan after an install run. `scripts/smoke/rows/tui.sh` holds the control: a presenter copy that writes no ended record leaves a run that never ends, and `expect_run_end` fails on it.
- The harness builds `scripts/smoke/pointer/click.c` into the sandbox: one click through the nested compositor's virtual pointer protocol, run only with the nested socket in its environment, so a row can click a widget or click outside a menu without any tool that reaches the live seat. It builds `scripts/smoke/toplevel/toplevel.c` the same way: one xdg toplevel with the app-id and, when given, the title a row gives it, which `scripts/smoke/rows/hyprland.sh` starts and stops by pid and the harness's stand-in terminal maps as a run's window. That stand-in, which `terminal_stand_in` writes as `xdg-terminal-exec` in the shell's stand-in directory below, records the argv a floating TUI's launcher hands it and runs a plugin's script under the real presenter and any core command as `true`, so `scripts/smoke/rows/manager.sh`, `scripts/smoke/rows/tui.sh` and `scripts/smoke/rows/launcher.sh` read a launch back and no core command runs in the sandbox. The shell alone resolves `hyprctl` through a stand-in directory on its path, so a row can replace the command with one that cannot start and prove the dispatch queue survives it. The Hyprland layer's `hyprctl reload config-only`, which `shell/Core/HyprlandLayer.qml` runs after each write, resolves through the same directory and carries the nested `HYPRLAND_INSTANCE_SIGNATURE`, so it reaches only the nested instance; it is the core's own reload, not a theme target's hook, and `scripts/smoke/rows/hyprland.sh` reads its effect back.
- The sandbox runs two private D-Bus daemons with no service directories as the session and system buses, so the shell's notification server and polkit agent never reach the user's buses and nothing is activated on them. It sets `TMUX_TMPDIR` to the sandbox runtime dir, so a tmux command cannot find the user's live server.
- A nested compositor that fails to allocate its output buffers stops laying out surfaces, and every geometry row after it reads zeros. A row that reads positions, sizes or reserved space runs under `geometry`; when every failed row is a geometry row and the nested compositor's own log holds `Output WAYLAND-<n>: pending state rejected: swapchain failed reconfiguring`, the line Aquamarine's Wayland backend writes when the nested window's output cannot allocate its buffers (`src/backend/Wayland.cpp`, v0.15.1), the smoke exits 77 with `nested-compositor=buffer-allocation-failed`. A `Failed to allocate a GBM buffer` line names no output and never excuses a run: passing runs on the owner's machine log failed 1920x1080 allocations for Hyprland's headless `FALLBACK` output. `scripts/smoke/verdict.sh` holds that verdict and the passing-run baseline; `scripts/test-smoke-verdict.sh` is its control. Any other failure exits 1. Re-run it; 77 is not a pass.
- `scripts/smoke/harness.sh` copies the shell into the sandbox and adds `scripts/smoke/Probe.qml`. The copy holds no shipped theme target: the sandbox's PATH is the host's, so a shipped target would detect the host's own application, and the test-run marker ([validation.md](validation.md)) refuses its reload hook; the theme rows add the fixture targets they read. It also keeps a copy of its own `hyprland.lua` as `hyprland-harness.lua` before the shell starts, since the shell's first run wires that file, and `scripts/smoke/rows/hyprland.sh` compares the two. The observer owns test counters, instance readback and form setup. A generated alias exposes the user file view only in this copy. The shipped shell contains none of these test methods.
- Hidden nested windows need the host Hyprland's `render_unfocused` window rule for class `aquamarine`. It supplies frame callbacks even on an inactive workspace or hidden scratchpad; `misc:render_unfocused_fps` controls the rate. Without it, keep the window visible. Put scratchpad routing, `no_initial_focus` and activation suppression in the host configuration; the smoke never opens a host workspace or changes host focus. Avoid `no_focus` when manual selection and movement are required. A row whose subject requires a drawn frame runs under `render`, which reads the bar windows' frame count through `frames` before and after; when every failure is a geometry or render row and a failed render row drew no frame, the smoke exits 77 with `nested-window=not-drawn`.
- A row can hold a mode on the nested output, such as the Settings rows' 480 by 720 monitor narrower than the window, through `hold_mode` and `release_mode` in `scripts/smoke/harness.sh`. Two writers the row does not control move the output off that mode. The host resizes or refocuses the nested window, and Hyprland gives the output the host window's size (`src/output/Monitor.cpp`, v0.56.2). A configuration reload drops the rule the row added through `hyprctl eval`. The window check reads the monitor and the layers in one batched `hyprctl` request and names a reset as `mode=<WxH> want=<mode>` rather than measuring the window against it. A row that fails after the output left the held mode counts as a mode reset, not as behaviour. When every failure is a mode reset, the smoke exits 77 with `nested-output=mode-reset`. The Settings rows reset the mode under their own hold as the control.
- `scripts/sandbox-shots.sh` takes visual evidence in the same sandbox. It captures the gallery, Settings, the launcher and the notifications in dark and light, with hover and selection states, and `--rev` runs an older shell for a before shot. `scripts/smoke/shot.sh` gives grim only the nested socket, in an empty environment. It refuses the host socket, a link to that socket, the host's runtime dir and any output directory outside `tmp/`. Each capture must differ from the shot before it. Otherwise it is the stale frame of a hidden window and fails. A grim with no frame after 10 s exits 77 with `nested-window=not-drawn`. `scripts/test-sandbox-shots.sh` is its control. Omarchy runs its acceptance screenshots (`test/acceptance.d/base-test.sh`, read 2026-09-28) as `timeout 10 grim ... || true` inside a VM session. VGS has no VM to capture from, so it uses the nested compositor, and a failed or stale capture fails instead of passing.
- The smoke's log check fails on every error line except those a row provokes on purpose and names in `expected_errors`.
- The smoke's read-only prefix row installs into the sandbox, verifies that pristine tree, replaces the installed target set with the sandbox's fixture targets, puts process-signalling stand-ins first on the installed shell's `PATH`, removes write bits from the staged prefix, restarts the shell from the installed `vgsh`, waits for `theme_idle`, runs `theme apply vgs`, checks the installed shell log, and compares the installed tree snapshot before and after. Its control holds the theme lock as the startup follow does and reads the apply's `reason=busy` refusal. The row uses a user-owned non-writable tree because tests cannot make a root-owned prefix.
- The smoke's teardown runs on every exit of the harness. It ignores TERM, INT and HUP first, so a second signal cannot end it. A second signal is common: a timeout signals the runner, then the systemd unit that stops signals every process in it. It stops the recorded process groups, then gives the owner read, write and directory search permission back on the whole sandbox before it removes the sandbox and the runtime dir. The read-only prefix row gives the write bits back only at its end, so a row that fails or is signalled before then leaves a tree `rm -rf` cannot empty without that step. `--keep` keeps the sandbox with the permissions given back, so plain `rm -rf` removes it. A failed step prints `qml-smoke: cleanup=chmod-failed` or `qml-smoke: cleanup=rm-failed` with the path on stderr. SIGKILL cannot be caught, and a run killed with it leaves the sandbox behind. The orchestrator's job runner sends SIGKILL 10 s after its TERM (`JOB_UNIT_KILL_GRACE` in `.agents/skills/orch/scripts/lib/job-unit.sh`), so the teardown must finish inside that grace. `scripts/test-smoke-teardown.sh` runs the teardown after a `set -e` failure, after TERM, HUP and INT, after a second signal during the teardown and under `--keep`, and its controls remove the permission step and the signal step.
- The sandbox runtime dir is a short name under the host's `XDG_RUNTIME_DIR`. The short path leaves space for Hyprland's signature and socket names.
- The compositor keeps a destroyed layer surface in `hyprctl layers` with pid -1 until it drops it. A row that counts surfaces counts only layers with a client, and reads reserved geometry from `hyprctl monitors` for what the user feels.
