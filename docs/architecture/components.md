# Components

Covers: shell/Ui/foundation/**, shell/Ui/controls/**, shell/Ui/feedback/**, shell/Ui/layout/**, shell/Ui/overlay/**, shell/Ui/icons/**, shell/Ui/qmldir, scripts/smoke/rows/overlays.sh, scripts/smoke/fixtures/plugins/acme.overlays/**, shell/Ui/AGENTS.md, scripts/vendor-lucide, scripts/test-lucide-data.js, scripts/test-icon-bounds.js, scripts/qml-tests/**, scripts/check-pointer-cursor.py, scripts/test-check-pointer-cursor.py

What each component of `qs.Ui` guarantees. The tokens they draw from and the layers they sit in are in [design-system.md](design-system.md). `ImageText`, `AngledCard`, `CardCarousel`, `AvatarGroup` and `VoiceOrb` are in [components-media.md](components-media.md), the overlays and the menus' scrolling are in [components-overlays.md](components-overlays.md), and the list motion of `ListCursor` and `ListEntrance` is in [motion.md](motion.md).

- A control that takes a name (`variant`, `size`, `role`, `tone`, `level`) logs an error naming the component and the value for an unknown name and draws its default. A control draws `FocusRing` while `visualFocus` holds, so a keyboard user sees the ring and a pointer user does not; the ring takes its corner from the item it fills. A control's side padding under a rounded corner is `Theme.controlPadding`, and every corner clearance steps by `inset.cornerStep`. A control sets `Accessible.name` from its text; `IconButton` requires `label` and logs an error without one. A disabled control draws at `opacity.disabled`. Every animation reads a `motion` token, so `motion.scale` of 0 stills the shell.
- Every element that takes a click shows the pointing hand while the pointer rests on it and it is enabled: it declares `PointerCursor`, a passive `HoverHandler` and the one place the shell names `Qt.PointingHandCursor`. Each control of `qs.Ui` that takes a click declares it, and so does a plugin's own `MouseArea`. A disabled control shows the arrow, since Qt picks no cursor from a disabled item, and a text field keeps its I-beam. A scroll bar keeps the arrow, as Qt's own does, and so does an area that takes a click away from a surface, such as `Scrim`. `scripts/check-pointer-cursor.py` refuses a `MouseArea` that takes a button, a `TapHandler` or a Qt Quick Templates button or slider in shipped QML without a `PointerCursor`. An exemption is a `// pointer-cursor-exempt: <reason>` line directly above the element. `scripts/test-check-pointer-cursor.py` plants one violation per rule. `vgs-plugin check` runs the rule on a third-party plugin's tree; `vgsh plugin validate` and `plugin add` run the manifest judge alone, since the shell loads a plugin whatever its cursors. The Qt and Hyprland facts it rests on are in [runtime-pointer.md](runtime-pointer.md). `scripts/smoke/rows/manager.sh`, `gallery.sh`, `overlays.sh` and `launcher.sh` read the shape the compositor shows over each kind of control.
- Omarchy (`basecamp/omarchy`, branch `quattro`, read 2026-09-29) sets the same shapes: the hand on its buttons, rows and bar widgets, the arrow where a control is disabled or busy, and the arrow on its click-away area and stock scroll bars. It writes `cursorShape: Qt.PointingHandCursor` into 44 `MouseArea`s one by one and has no check. VGS names the hand once and checks every click area: the literals it had reached seven plugin files and no `qs.Ui` control.
- `ListItem` owns the row highlight box, the icon size, the icon-to-text gap, the trailing-control gap and the two-line rhythm. The box sits on its container's inset edge, and the icon and text sit inside the row padding. A row that names its list's `ListCursor` in `cursor` draws no fill of its own: the cursor draws the highlight, the row hands it itself while `highlighted`, emits `pointed` for a hover the cursor lets through, and enters through `ListEntrance` as it is created unless `enters` is false. `MenuItem` and the list of `Select` draw their highlight the same way, so a menu, a dropdown and a pure list move one highlight under the keyboard and the pointer ([motion.md](motion.md)). `textStart` is where its text starts, for content a caller lines up under it.
- `Field` is an unboxed label, hint and control row. Its default horizontal padding is zero, so its label sits on its container's content edge and its control ends on that edge; a theme may indent all fields through `field.paddingX`.
- `Label` draws one typography role and sets both `font.weight` and `font.variableAxes`, since a variable font moves on the axis alone and a static family on the weight alone. Letter spacing is stated in em and set in pixels. A role's line height is a font-size multiple, floored at the font line box rounded up to a whole pixel. `Label` publishes the line box, half-leading, capital centre and optical width.
- `BarItem` is the one bar item: every first-party widget and every workspace pill composes it. It is `bar.item.height` tall, its content `bar.item.paddingX` in from each side, never narrower than it is tall, and an icon-only item is square with its `bar.item.icon` centred. A count or a label after the icon draws in `text.bar`, a mono chrome role with line height 1, `bar.item.iconGap` after it. Hover and press fill it with `bar.item.hover` and `bar.item.pressed`; `active` fills it with `bar.active`. `scripts/qml-tests/tst_baritem.qml` holds each. Every item sits on the bar's vertical centre; `scripts/smoke/rows/bar.sh` reads the pills, their labels and the clock back and holds each to it within one pixel, and `scripts/smoke/rows/manager.sh` does the same for the Settings gear.
- `Icon` draws Lucide path data from `shell/Ui/icons/Lucide.js`, which `scripts/vendor-lucide` writes as path commands. The shape is drawn in the data's box and scaled as an item, so `icon.stroke` is the same number of pixels at every size. `Icon.painted` is the ink's extent, read by `IconBounds.js` with the SVG path grammar: an arc's flags are one character each, an arc counts the axis extremes of its real ellipse inside its sweep, and S and T count the control point they reflect. The extent is never smaller than the ink; `scripts/test-icon-bounds.js` holds that over every Lucide icon against an independent outline sampler.
- Radios under one parent are exclusive, as the template makes them. `TextField` draws its action buttons as children of the field, not of its background, because the control puts the background under itself and the input takes every press on it.
- `TextArea`, `WeekdayChipGroup`, `TimeField`, `TimeChipList`, `DateField` and `PathField` support recurrence editors: multi-line commands, weekday chips, typed times, sorted time chips, a month grid and a directory picker. `PathField` reports each user edit at once and reports it again if the folder model later changes that path's validity. `scripts/qml-tests/tst_automation_controls.qml` holds each.
- `Pane` owns a container's inset box: a header, a scrolling body and a footer share one content edge, and the body scroll bar sits inside the right inset strip. `padding` and `cornerRadius` default to the container class's tokens, and `gap` and `bodySpacing` to `stack.group`; a plugin that owns its look hands its own for all four ([appearance.md](appearance.md)). A fitted pane lays out in the height its host gives it when that is less than its fitted height, so the footer stays inside a popup held to a short output. The content clears the drawn corner through `Inset.clearing`. A fitted pane caps its height and scrolls only the body; the footer stays outside the scrolling body, so its actions stay in view. A divider spans the inset box under the header while the body is scrolled, and over the footer while more of the body lies below. The viewport reaches a focus ring's room past the content's left, top and bottom edges, so a ring on an edge row is not clipped. A slot's width is its widest child's implicit width, never the children's laid-out boxes. `bodyRoom` is the height a body with content shows at the pane's cap, read from no height of the body, so a body can size itself from it. The `overlay` class, a full-screen surface over a scrim, pads by `inset.overlay` and clears no corner. `scripts/qml-tests/tst_pane.qml` holds each.
- `SlimScrollBar` is the slim bar a plugin that owns its look draws beside its own `Flickable`: it takes the flickable and every value it draws with, reads no theme token, shows only while the content overflows, widens under the pointer and drags the view. The launcher and the notifications stack compose it with their own looks; `scripts/qml-tests/tst_slimscrollbar.qml` holds each.
- `Dialog` is the one confirmation card and no overlay: its host places it. It composes `Pane`, fits its content until `dialog.maxHeightShare` of the available height, then scrolls the body. Enter presses the focused action, as `gum confirm` does, or a focused `tabItems` button, such as a disclosure's toggle, in the accept action's place. An `initialFocus` item of its content, such as a password field, takes the focus in the accept action's place and joins the Tab cycle; `tabItems` puts further content, such as a `Select` of identities, in the cycle ahead of the actions while it is shown and enabled. Its header states the rest; `scripts/qml-tests/tst_dialog.qml` holds each.
- `EmptyState` is what an empty list or view shows: an icon, one hint line and a recovery action, `stack.group` apart and centred in a box three two-line rows tall. The icon and the action draw only while named; the action emits `activated`. `scripts/qml-tests/tst_emptystate.qml` holds each.
- `Scrim` fills its parent with `color.scrim`, takes the presses, the hover and the wheel on it, so nothing under it answers, and emits `clicked`, so the surface declared after it can close on a click away. Omarchy's image picker washes at 0.5 of the background; `color.scrim` stays the one scrim role, at 0.6. `scripts/qml-tests/tst_scrim.qml` holds the fill, the colour under two themes, the click, and the press, hover and wheel kept from the controls under it.
- `Disclosure` is a `ListItem` that shows or hides the content declared inside it, under the row. A click on the row or Space toggles `expanded`; a chevron after the row's trailing items points down while the content is hidden and up while it shows, and hidden content takes no height. A control among the trailing items takes its own click and toggles nothing. A row whose `expandable` is false, one with nothing to show, draws no chevron and opens on no click, and keeps the chevron's room so its trailing items line up. The content starts at the row's text column. `scripts/qml-tests/tst_disclosure.qml` holds each.
- `Badge` draws a `sm` or `md` status chip. It places text by the label's capital centre, sizes from optical width, supports the neutral, info, success, warning, danger and accent tones, and logs an unknown size or tone before drawing the default.
- `Kbd` draws a keycap chip. It uses the label's optical width so the left and right ink insets match, and it places the label by capital height without changing the chip height.
- `IconButton` is a square icon-only `Button` whose icon follows its size. It requires a label, draws the icon dimmed at rest, makes it opaque on hover, focus, press or checked, and lets disabled opacity apply once to the whole control. `glyphStart` and `glyphEnd` are the box's distance from the glyph's painted bounds, so a header puts the glyph, not the box, on its content edge.
- `Switch` draws `sm` and `md` tracks. `sm` is for inline rows and list rows, and `md` is the default. The knob is the track height less the two insets, and widens while pressed. `Checkbox`, `Radio` and `Switch` label through the module's internal `IndicatorLabel` in `text.item`, centre the indicator on the label's capital centre on a whole pixel, take a press over a height of at least `size.control.sm`, and draw hover and press from their own tokens, checked or not.
- A row under a `ListCursor` shows its press through the cursor's `pressedColor`; a standalone `ListItem` and a `MenuItem` draw their own pressed fill. `Tabs` and `SegmentedControl` draw hover, press and disabled. `TextField` keeps its error colour on its focus outline.
- `Field` with `inline` true is the key/value row. It is `row.height` tall unless its control is taller, and `row.compactHeight` tall with `compact`, for a read-only value. It centres the label by capital height, centres the value control by its box, places the hint under the value column and publishes that column's x as `valueX`. A label longer than its column wraps to two lines.
- `Section` is a titled block of rows. It subtracts the parent positioner's spacing from `stack.section`, takes no top padding as the first item, puts its header on the content edge, and spaces its rows by `rowSpacing`, `stack.row` by default; a section of blocks passes `stack.group`. `SectionHeader` owns only the gap below its title and description.
- `CommandDisclosure` is the "Show command" disclosure ([D061](../decisions/D061-no-manual-commands.md)): a ghost `Button` reading Show command, or Hide command while `expanded`, that toggles a `CodeLine` of `command` under it; hidden, the line takes no height, and with `command` "" nothing draws. It sits beside the button that runs the step, never alone. `toggle` and `copyButton`, its line's Copy, are what a `Dialog` lists in `tabItems` so Tab reaches them. `TextField`'s `password` masks what is typed and keeps it off the clipboard, for a secret the shell stores. `scripts/qml-tests/tst_commanddisclosure.qml` holds both.
- `CodeLine` shows a command or path to copy: the text in the `code` role, wrapped at word boundaries, or inside a word longer than a line, so a long command shows whole, and a Copy `IconButton` inside the padding. One line is centred by capital height. Wrapped text starts at the padding plus half-leading, so the first and last line boxes have equal padding. The text is read-only and takes no focus; `scripts/qml-tests/tst_codeline.qml` holds each.
- `Toast` draws one notice in the shared stack. Its rectangular row starts at the normal toast padding for a square corner. With a rounded corner, it starts where the row's corners, one padding down from the top, stay one spacing step inside the drawn curve on both sides, through `Inset.clearing`. `scripts/qml-tests/tst_spacing.qml` holds both cases.

`Select.activated(index)` reports a user choice, including the current entry. Invalid indices emit nothing. A model replacement or a bound index change emits nothing. `scripts/qml-tests/tst_overlays.qml` pins the distinction, with controls in `scripts/test-qml-unit.sh`.
