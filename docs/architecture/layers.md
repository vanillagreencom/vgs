# Passive layers

Covers: shell/Core/Layers.qml, shell/Hosts/LayerHost.qml, shell/Hosts/OverlaySurface.qml, scripts/smoke/rows/layers.sh, scripts/smoke/fixtures/plugins/acme.layers/**

A passive layer is a surface a plugin draws in without taking the keyboard: a notification toast stack, an on-screen display, anything that shows while the user keeps typing into another window.

`layers` is a capability rather than a kind: [D026](../decisions/D026-passive-layers-are-a-capability.md). Its input contract is [D058](../decisions/D058-layer-input-union.md).

## The contract

- A plugin names `layers` in its manifest's `capabilities` and calls `shell.layers.show(component)` with a `Component` declared in its own files. It answers a disposer. Something that is not a component is refused with `refused: layers=not-a-component`, and a component that is not ready with `refused: layers=component-not-ready status=<n>`.
- `shell/Core/Layers.qml` holds each registration; `shell/Hosts/LayerHost.qml` builds one surface per screen for each, and one copy of the component inside it. The core binds the copy's `screen` after creation; loss of the host screen reaches that copy. A copy that does not declare `screen` is destroyed, logged as `layers: <plugin id> content not built on <screen>: <reason>`, and maps no surface.
- A copy may declare `shown`, a boolean map request independent of `Item.visible`. The host maps only while a screen exists and `shown` is true; absent `shown` retains the map-by-default contract. Hidden copies remain registered. `Item.visible` inherits a hidden host, so it cannot request that host's map without a dependency loop.
- The host retains its assigned target screen separately from the native window's screen getter. Both the content binding and map request use that assigned target. Losing it cannot map the content on a native fallback screen.
- An Item reads its host through the documented [QsWindow.window attached property](https://quickshell.org/docs/v0.3.1/types/Quickshell/QsWindow/). The passive host adds read-only `presented`: a requested map, `backingWindowVisible`, and a `QQuickWindow.frameSwapped` observation since that map. Hiding, losing the backing window or replacing content revokes it. This means a frame was queued for presentation, not that a person saw it. The [runtime QML contract](runtime-qml.md) defines that signal. Consumers must also check their own drawn content and usable geometry; component creation grants no presentation.
- The surface is anchored on every edge of its screen, on the overlay layer, under the namespace `vgs:layer`. It respects the space other layers reserve, so it covers the screen less the bar, and it reserves none. It never takes keyboard focus.
- Pointer input reaches the surface everywhere while the content's optional `inputAll` is true. Otherwise it reaches only the union of the rectangles in the content's optional `property var inputItems`, an array of Items from that copy's tree. An absent property or an empty array lets every press through. Gaps between items stay outside the mask. Replace the array when its members change; each item's geometry changes update its region.
- The shared surface maps each rectangle from the item's current tree and observes its ancestors. Parent layout, scrolling and remapping therefore update the same mask owner. `Region.item` alone does not observe that movement in the supported runtime: [runtime-qml.md](runtime-qml.md).
- `shell/Hosts/LayerHost.qml` uses `shell/Hosts/OverlaySurface.qml`, which also hosts the core's own notices, `vgs:toast` and `vgs:notice`. The shared surface owns the mask and its item regions. It sits on the overlay layer, the compositor keeps it clear of the space other layers reserve, and it reserves none. `inset` is its gap on every anchored edge: zero for passive plugin content, `toast.margin` for the toast stack, `dialog.margin` for the requirement notice. A corner placement anchors two edges and the toast host sizes the surface; `center` anchors all four, so a passive layer or notice fills the free area less its inset. The toast's `inputItems` are its visible cards, and the notice's are its dialog. A click between toasts, or beside the dialog, reaches what is below.
- The copy is built in the context of the file that declares the component, so it reads the plugin's state through that file's ids. The plugin's instance owns the state; the host owns the surfaces and their copies.
- A copy can outlive its instance for a moment: disabling a service deletes it with its slot, while the copies go on the event loop's next pass, as `scripts/smoke/rows/notifications.sh` read on 2026-09-28 through the log's diagnostics row. A copy's bindings on the instance check it for null, as `vgs.notifications`' stack does.
- A screen that is added gains a surface for every registration, and one that goes takes its surfaces with it. The disposer, or the instance's teardown, destroys every copy before the registration leaves, while the plugin that declared the component still exists.
- `vgsh ipc call shell lent` lists each registration under `layers` as its plugin and the screens it is built on.

## Invariants

1. A layer surface takes no keyboard focus, sits on the overlay layer and clears reserved space. Enforced by `scripts/smoke/rows/layers.sh`, which reads each surface's settings through the probe, its rectangle from the compositor's layer list, and a typed key reaching the focused client while the layer is mapped.
2. Each input item takes pointer input, and gaps and empty input pass it through to the client below. `inputAll` overrides the item list. Enforced by the same row, which reads press and release at two separate pads and from an xdg client under their gap, outside both pads and under an empty list. It removes and restores an item while the layer stays mapped. Controls drop the host's item binding, omit either pad from a copied surface's union, catch the gap with a full mask, and hide the client's button records; each breaks the same input assertion.
3. Every surface of a registration goes with its disposer, its plugin's disable and its screen. Enforced by the same row, from the layer list, the fixture's record of its copies and the lending record.
4. Hidden content retains its copy and maps no surface. The layers row changes `shown` and plants a host that ignores that request. The [Jarvis bubble row](jarvis-bubble.md#evidence) reads the presentation consumer and capture teardown after host or screen loss.
