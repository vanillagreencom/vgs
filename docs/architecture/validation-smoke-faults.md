# Smoke sandbox faults

Covers: scripts/smoke/verdict.sh, scripts/test-smoke-verdict.sh

The faults of the nested sandbox that the smoke reports as not measured, never as a pass, and the modes a row holds on the nested output. The sandbox and its harness are in [validation-smoke.md](validation-smoke.md).

- A nested compositor that fails to allocate its output buffers stops laying out surfaces, and every geometry row after it reads zeros. A row that reads positions, sizes or reserved space runs under `geometry`; when every failed row is a geometry row and the nested compositor's own log holds `Output WAYLAND-<n>: pending state rejected: swapchain failed reconfiguring`, the line Aquamarine's Wayland backend writes when the nested window's output cannot allocate its buffers (`src/backend/Wayland.cpp`, v0.15.1), the smoke exits 77 with `nested-compositor=buffer-allocation-failed`. A `Failed to allocate a GBM buffer` line names no output and never excuses a run: passing runs on the owner's machine log failed 1920x1080 allocations for Hyprland's headless `FALLBACK` output. `scripts/smoke/verdict.sh` holds that verdict and the passing-run baseline; `scripts/test-smoke-verdict.sh` is its control. Any other failure exits 1. Re-run it; 77 is not a pass.
- Hidden nested windows need the host Hyprland's `render_unfocused` window rule for class `aquamarine`. It supplies frame callbacks even on an inactive workspace or hidden scratchpad; `misc:render_unfocused_fps` controls the rate. Without it, keep the window visible. Put scratchpad routing, `no_initial_focus` and activation suppression in the host configuration; the smoke never opens a host workspace or changes host focus. Avoid `no_focus` when manual selection and movement are required. A row whose subject requires a drawn frame runs under `render`, which reads the bar windows' frame count through `frames` before and after; when every failure is a geometry or render row and a failed render row drew no frame, the smoke exits 77 with `nested-window=not-drawn`.
- A row can hold a mode and a scale on the nested output through `hold_mode` and `release_mode` in `scripts/smoke/harness.sh`: the Settings rows' 480 by 720 monitor narrower than the window, and the double mode at scale 2 that `scripts/smoke/rows/hidpi.sh` and `scripts/sandbox-shots.sh --scale 2` take before a shell starts, which keeps the logical size. A headless output cannot serve for scale 2: it stays 0x0 in the sandbox ([runtime-hyprland.md](runtime-hyprland.md)). `hold_mode` writes the rule to a file in the sandbox's runtime directory and applies it through `hyprctl eval`; the harness's `hyprland.lua` runs that file after its default rule on every load, and `release_mode` removes the file. A reload drops the eval'd rule and applies the file's rule again ([runtime-hyprland.md](runtime-hyprland.md)), so the file puts the hold back whenever the compositor applies its rules again. Writers the row does not control move the output off the held mode. The host resizes or refocuses the nested window, and Hyprland gives the output the host window's size, not its scale (`src/output/Monitor.cpp`, v0.56.2). A `scripts/sandbox-shots.sh --scale 2` run on host cachy on 2026-09-29, its hold set through `hyprctl eval` alone, read the output at 1755 × 933 and scale 1 partway through its shots; the writer is not identified. With the hold in the file, the same run read 3510 × 1866 at scale 2 through all 20 shots. The window check reads the monitor and the clients in one batched `hyprctl` request and names a reset as `mode=<WxH> want=<mode>` rather than measuring the window against it. A row that fails after the output left the held mode or scale counts as a mode reset, not as behaviour. When every failure is a mode reset, the smoke exits 77 with `nested-output=mode-reset`. The Settings rows reset the mode under their own hold as the control. The HiDPI row drops only the scale to 1 under its hold, reads that applied scale back and reads the hold as reset, the control of the hold's scale reading. It then reloads the configuration and reads the held mode and scale back; with the file removed, the same drop and reload leave the held mode at scale 1, the control of the file. A row that reads the hold itself runs under `hold_check`, so its failure counts as behaviour, never as a mode reset.
