# Helper CLI

Covers: bin/

`bin/vshell` is a thin dispatcher and `bin/vshell-helper` is the single-file Python CLI behind it. The helper owns everything the runtime cannot: parsing the formats VGS reads, rendering the files it generates, writing outside the user's home, and the subsystems whose logic would otherwise sit in QML.

## Boundaries

- The helper is deliberately one large file. Splitting it into modules is its own work, not a review finding; judge it for behaviour rather than for architecture.
- Niri KDL parsing and rendering is isolated behind its own module, and QML passes structured data rather than rendering config text.
- VGS never edits a compositor's own config. It generates fragments under a VGS-named directory and reports the one line the user adds to include them; the Niri backend writes its include with a backup, which is the existing stance for that compositor.
- Font rendering and compositor shape are helper-owned VGS settings, not part of theme generation.

## Invariants

1. An external tool is executed as an argv array, never as a shell string built from user data, and no path logs a secret, a network key, clipboard content or a raw frame payload. Enforced by `scripts/check-vshell-helper.py`.
2. A privileged write is validated before it lands and never follows a symlink at any component. The passwordless-sudo drop-in is validated under a staging name sudo ignores before it is moved into place, and its user-readable mirror is written without following links, because root writes it into a user-controlled tree.
3. The direction of a privileged toggle is never inferred. Callers state the state they displayed; where reality disagrees, the privileged half changes nothing, re-syncs its mirror and exits asking the caller to re-read. Inferring the direction turns a request to revoke into a permanent grant.
4. Granting elevated access always goes through a terminal and a confirmation; only revoking may take the quiet path. Where sudo already runs without prompting, a quiet grant would install a passwordless rule from one click with no window at all. The terminal requirement is grant-only, reported separately from availability, so a machine with no terminal can still revoke. Enforced by `scripts/test-sudo-toggle-confirm.js`.
5. A terminal is resolved in exactly one place, reached through `vshell terminal`. QML, plugin code, shell scripts and the Go backend all call it; none of them names a terminal binary. Each terminal's argument shape lives in one table, and a terminal with no app-id equivalent has the app id dropped rather than passed as an option it would reject.
6. The application-scoping wrapper is an enhancement, not a requirement: it is prepended only where it is present and usable, and usability is settled once per process with its own probe rather than by watching the payload die, since retrying the payload unscoped would run the user's command twice.
7. A terminal that exits within the settle window means the terminal failed only where the payload cannot itself exit fast. Without the hold wrapper the exit status belongs to the user's command, so the next candidate is not tried: retrying would flash a window and re-run that command once per installed terminal.
8. A launch failure reaches the user rather than only stderr, because every call site launches detached and discards output and status. A button that cannot work says so.
9. A pad's size is a percentage resolved late against the monitor's logical size, and its position is a named anchor plus an offset clamped onto that monitor. Pixels are correct on exactly one display, and a pad the user cannot see is indistinguishable from a keybind that does nothing.
10. Compositor rules for a pad are best-effort and the runtime toggle is the mechanism. Placement rules apply once at map time, so any application whose class settles after mapping loses that race permanently; the toggle re-asserts on every reveal, workspace membership first, because a window that never matched is sitting on whatever workspace was active and styling it perfectly would leave it there.
11. A pad that is rejected is rejected everywhere, not only in the half that emits rules — including from start-up launching, or a pad refused for being unusable would still launch its application at every login into a session with nowhere to put it. On Niri the stakes are higher still: a rule the compositor refuses to parse takes the whole config file down, so a pattern using constructs its regular-expression engine does not implement, or one that would terminate a raw string early, is refused rather than half-emitted.
12. A hide confirms its own outcome by reading state back, and an unanswerable query is neither success nor failure. Settings deletes a pad record only when release reports success, so "the compositor did not answer" must never read as "nothing to release"; the window finders answer with a distinct value for an unreadable list and an empty one, and only the second authorises deletion.
13. Removing a pad moves its window to the active workspace rather than closing it or refusing the removal. Removing a configuration entry must not destroy a running program, and a pad the user wants gone should not be unremovable until they find and close its window.
14. Brightness is addressed by a stable identity derived from the display's own descriptor, never by connector name, so ids survive re-cabling. The control interface on a display exposing several is probed rather than hardcoded, and the raw value range is read per display from its own descriptor.
15. Brightness scanning is event-driven with one bounded exception, because a repeating poll re-enters the bus even when the probed device is powered down, wedging probes in uninterruptible sleep. Repeated failures quarantine scanning; every lift starts a new counting episode, and a settled-scan generation keeps an out-of-order reply from overwriting a newer verdict. Enforced by `scripts/test-brightness-scan-ordering.js` and `scripts/check-brightness.py`.
16. A probe that can enter uninterruptible sleep runs in a helper subprocess, never in the helper's own process: neither a context deadline nor a wait delay can abandon a process blocked in the kernel, so isolation is what makes the deadline effective.
17. The remote-desktop host's virtual output and its unit are one operation, in that order, because the host picks its capture target at start-up — starting the unit without the output present streams the user's own screen with nothing in the journal to notice. No surface may start that unit by another route.
18. That output is created transactionally and removed only with provenance. A tool exiting cleanly is not the output existing, so presence is re-read before the unit starts; a failed start removes only what it created; and stop removes the output only where the record says VGS created it, keyed on the compositor instance so a record from a previous instance cannot describe the output present now.
19. Listening and streaming are different states, never collapsed into one. Every axis of the answer — host, session, session count, output, paired devices — has its own known flag, and they are dropped together, because leaving one standing renders half an answer as a whole one. Only an authoritative reply saying the session ended may clear the streaming indicator; losing the answer entirely does not. Enforced by `scripts/test-remote-desktop-state.js`.
20. Session state is read from the host's journal, bounded to the unit's current run. There is deliberately no fallback window: an anchor that cannot be established means no read, because replaying unbounded history shows a live capture with nobody connected, and inventing one trains the user to ignore the only indicator that says somebody is watching their screen.
21. A coding-agent stub is written only where VGS owns the file. A file without the marker line is foreign and never replaced, and a command that already resolves outside the stub directory gets no stub, because the stub directory sorts first and would hide the distribution's binary.
22. Wallpaper upscaling is one-shot by construction: each invocation loads a model, processes one image and exits, so nothing stays resident when idle. Its cache lives outside the repository, and clearing that directory uninstalls it.

## Decisions

[D006](../decisions/D006-scratchpad-window-identity.md) keeps class-based pad identity and makes pattern breadth visible instead of adopting a per-instance mechanism: a pad's pattern is an exact class match, so it claims every window of that application, and Settings reports how many live windows a pattern claims.

[D011](../decisions/D011-mise-owns-agent-harnesses.md) puts coding-agent harnesses and language toolchains under one user-level version manager driven by a single catalog, with `vshell update run` as the only upgrade implementation.
