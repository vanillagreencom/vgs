# Runtime: the nested Hyprland

Covers: scripts/smoke/shot.sh, scripts/smoke/host-window.sh, scripts/sandbox-shots.sh, scripts/smoke/rows/hidpi.sh

The facts of the nested Hyprland session the smoke and `scripts/sandbox-shots.sh` run in: its outputs, when it draws a frame, and how grim captures it, each with the source or the reading that establishes it. The sandbox itself is in [validation-smoke.md](validation-smoke.md); the other Hyprland facts are in [runtime-hyprland.md](runtime-hyprland.md).

- A headless output in the nested session gets no mode on an NVIDIA host. `hyprctl output create headless NAME` lists the monitor at 0x0 and scale 1, with or without a monitor rule for NAME. The nested compositor runs Aquamarine's Wayland backend and no DRM backend, so `CHeadlessBackend::getRenderFormats()` in `src/backend/Headless.cpp` (aquamarine v0.15.1) returns a fixed list whose 8-bit formats carry the modifier `DRM_FORMAT_INVALID`. That value is 0, the value of `DRM_FORMAT_MOD_LINEAR`, so `CGBMBuffer::CGBMBuffer` in `src/allocator/GBM.cpp` asks for a linear buffer, then for `GBM_BO_USE_LINEAR`, and NVIDIA refuses both, as the file's own comment says. Hyprland's log then holds, for each mode it tries, `Couldn't allocate a gbm buffer with size [1280, 720] and format XR24` and `REJECTED available mode 1280x720@60.00Hz!`, then `has NO FALLBACK MODES, and an INVALID one was requested: 0x0@60.00Hz`. The nested Wayland output allocates with NVIDIA's tiled modifier and works. Read in a nested Hyprland on host cachy (NVIDIA GPU, Hyprland 0.56.2, aquamarine 0.15.1) on 2026-09-29.
- The nested Wayland output takes any mode and an integer scale through `hl.monitor` in `hyprctl eval`. On a 1755 × 933 nested window, `mode = "3510x1866", scale = 2` read back from `hyprctl -j monitors` as 3510 × 1866 at scale 2, and `grim` on the nested socket captured a 3510 × 1866 PNG, in device pixels; `mode = "1755x933", scale = 1` read back as before. Double the mode at scale 2 keeps the logical size. Read on host cachy on 2026-09-29. `scripts/smoke/rows/hidpi.sh` and `scripts/sandbox-shots.sh --scale 2` hold this mode before they start a shell, since a running shell does not follow a scale change ([runtime-qml.md](runtime-qml.md)).
- The nested compositor draws its next frame only after the host answers the last one. Aquamarine's Wayland backend asks the host for a `wl_surface.frame` callback with each commit and schedules no frame while that callback is pending (`CWaylandOutput::commit` and `onFrameDone` in `src/backend/Wayland.cpp`, `CFrameScheduler::canSchedule` in `src/backend/FrameScheduler.cpp`, aquamarine v0.15.1); no environment variable or setting changes this. The host answers a hidden window's callbacks only when the window has `render_unfocused`, at `misc:render_unfocused_fps` (`m_renderUnfocusedTimer` in `src/render/Renderer.cpp`, Hyprland v0.56.2). A window joins that timer only on a window rule update, `window.updateRules`, which `Actions::setProp` in `src/config/shared/actions/ConfigActions.cpp` does not emit, so `setprop render_unfocused` alone does not start its frames. The host window rule is the one switch ([validation-smoke-faults.md](validation-smoke-faults.md)).
- grim 1.5.0 captures the whole layout one output at a time. For an output with no size it maps a zero-byte buffer, `mmap` refuses it, and grim exits with `failed to create buffer` (`create_buffer` in `buffer.c`). A headless output of the nested session, 0x0 on an NVIDIA host, is such an output; `grim -o NAME` captures one output and is unaffected. Read on host cachy (NVIDIA GPU, Hyprland 0.56.2, aquamarine 0.15.1, grim 1.5.0) on 2026-09-30, the nested window on the host's hidden scratchpad: beside `WAYLAND-1` at 1755 × 933 and a headless `VGS-SHOT` at 0x0, a layout capture failed and `grim -o WAYLAND-1` wrote the PNG. `shot` in `scripts/smoke/shot.sh` therefore captures one named output.
