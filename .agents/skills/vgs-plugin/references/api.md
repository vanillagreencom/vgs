# Plugin API

What a plugin receives and may call. The core owns every table here; a value not listed does not exist for a plugin.

## Kinds

| Kind | Entry point key | Base | Host today | Built when |
|---|---|---|---|---|
| `bar-widget` | `bar-widget` | `BarWidget` from `qs.Ui` | the active bar's sections | placed in `bar.layout.<section>`, not in `disabledPlugins`, and a bar is active |
| `bar` | `bar` | `Item` declaring the three section containers below | the bar host, one per screen | it is `bar.id` in the configuration and is not in `disabledPlugins` |
| `service` | `service` | `Item` | the service host | enabled |
| `background` | `background` | `Item` declaring `property var screen: null`, and optionally `property bool shown`: the host maps no surface on a screen while every instance there declares it false | the background host, one per screen, under every window | enabled |
| `panel` | `panel` | `Item` with `open(payloadJson)` and `close()`, optional `initialFocus`, sized by `implicitWidth` and `implicitHeight` | the panel host: a popup under its anchor item with a focus grab, or a layer surface on the top layer without one, centred on the whole monitor by default | enabled and summoned, until hidden |
| `overlay` | `overlay` | `Item` with `open(payloadJson)` and `close()`, optional `initialFocus` | the overlay host: an anchored popup, or a layer surface covering its screen without an anchor | enabled and summoned, until hidden |
| `menu` | `menu` | `Item` with `open(payloadJson)` and `close()`, optional `initialFocus`, sized by `implicitWidth` and `implicitHeight` | the menu host: a popup under its anchor item with a focus grab, or a layer surface on the overlay layer without one | enabled and summoned, until hidden |
| `window` | `window` | `Item` with `open(payloadJson)` and `close()`, optional `initialFocus`, sized by `implicitWidth` and `implicitHeight` for its first size, filling the window after | the window host: a Hyprland window titled with the manifest's `name`, floating and centred, with or without an anchor | enabled and summoned, until hidden or closed through Hyprland |
| `pane` | `pane` | `Item` with `open(payloadJson)` and `close()`, optional `initialFocus`, filling the holder's container: a body alone, with no `Pane` and no title, its content from x 0 and its height its `implicitHeight`; the holder draws the title, owns the inset and scrolls it | the enabled holder of capability `panes`, one pane at a time | enabled and mounted by that holder |

Enabled is defined in [`docs/architecture/plugins.md` § Kinds](../../../../docs/architecture/plugins.md#kinds); `PluginLogic.isEnabled` is the judge.

A summoned kind is built on summon and destroyed on hide. `open(payloadJson)` that throws refuses the summon with `refused: open-failed=<id>`, so a payload that does not parse is left to throw. Summoning an open one calls `open` again with the new payload. After `open()` returns, the host focuses the entry's optional `initialFocus` item with `Qt.ShortcutFocusReason` for an unanchored summon and `Qt.MouseFocusReason` for an anchored summon. Without `initialFocus`, the host slot keeps focus so Escape still reaches it and Tab enters the plugin's chain. Pass the item the surface belongs to as `anchor`. The compositor places an anchored surface beside that item in its own window and adjusts it at screen edges. Moving the item moves the popup. An anchored surface takes keyboard focus and closes on a click outside, receiving `close()`. The popup also closes when its anchor is hidden or destroyed. A panel or menu summoned without an anchor sits at its `placement` setting: `top-left`, `top`, `top-right`, `left`, `center` (the default), `right`, `bottom-left`, `bottom` or `bottom-right`. `center` ignores the space a bar reserves and centres on the whole monitor; every other placement keeps clear of it. A panel or menu summoned without an anchor closes on a press beside it over a client window or the empty desktop of its screen too, receiving `close()`; a press on a bar leaves it open, except at the `center` placement, whose layer covers the bar. A `window` ignores the anchor and `placement`: Hyprland maps it on the focused monitor, draws its border, focuses it and moves, tiles and closes it like any other window, and a close there calls `close()`. An Escape no item of the plugin accepts while a summoned panel, menu, overlay or window has the keyboard closes it the same way; accept Escape only for a step of the plugin's own, such as popping a page. It draws no frame of its own. Pick `window` for a surface the user works in; a flyout is an anchored `panel` or `menu`: [`docs/architecture/surfaces.md`](../../../../docs/architecture/surfaces.md).

## Properties every instance receives

| Property | Type | Assigned by | Meaning |
|---|---|---|---|
| `shell` | object | the core, after creation and again when the plugin's settings change | this plugin's scoped object, table below |

Declare it as `property var shell: null`, or inherit it from `BarWidget`.

## Properties a bar widget also receives

| Property | Type | Meaning |
|---|---|---|
| `bar` | object | the bar API below |
| `moduleName` | string | the plugin id; the core assigns it after creation |
| `settings` | object | the manifest's `settings` under the widget's layout entry, for example `{ "units": "metric" }`; the entry id is excluded; reassigned when the entry changes |

`BarWidget` adds `barSize` and `setting(name, fallback)`.

## Properties a bar also receives and declares

| Property | Direction | Type | Meaning |
|---|---|---|---|
| `screen` | received | ShellScreen | the screen this bar draws on |
| `leftSection`, `centerSection`, `rightSection` | declared | Item | the containers the core parents widgets into, in layout order; a `RowLayout` in the template |

A bar never creates, destroys or reads a plugin widget. It may draw built-in widgets of its own ahead of them in each container and register each with `shell.builtins`; [`docs/architecture/overview.md` § Vocabulary](../../../../docs/architecture/overview.md#vocabulary) defines the built-in widget.

`set` starts `vgsh theme background --json set <path>`, with `--screen <screen>` for an output name and `--every-screen` for screen `*`, which clears each screen's own image, and returns `ok`, or `refused: set=<path> reason=malformed-path` for a path that is not absolute and `refused: set=<screen> reason=malformed-screen` for any other screen that is not null, at once, and `done` receives `{ state, background, theme, path, screen, reason }`; `wallpapers` starts `vgsh theme wallpapers --json <name>` on the download lane, which runs beside the other jobs, with `--update` for `options` `{ update: true }`, and returns `ok`, or `refused: wallpapers=<name> reason=malformed-name`, `refused: wallpapers=<options JSON> reason=malformed-options` for options other than absent or `{ update: <boolean> }`, or `reason=busy` while a download runs, at once, and `done` receives `{ state, theme, wallpapers, images, sha256, reason }`; each of these hands `done` every other refusal; `swatch` is one accepted package's palette from the last list as `#aarrggbb` strings, null for a refused or unknown package; `current`, `revision` and `fileState` are `Theme.name`, `Theme.revision` and `Theme.fileState`, and `done` can run before they move; `modified` is the last list's answer, null before one; `last` is `{ applying, result, downloading }`, the apply running, the last result and the running download's `{ name, state, bytes, total }` or null, kept by the core across instances; `result` is also the result, with its `follow` outcome, of a follow that applied the changed package again; a destroyed instance's `done` is dropped and its job still completes. Contract: [`docs/architecture/theme-capability.md`](../../../../docs/architecture/theme-capability.md). `done` that is not a function throws `refused: theme=<verb> done=not-a-function` |
| `shell.hyprland.overridden`, `.devices`, `.foreignBinds`, `.switchKeyboardLayout(target)` | capability `hyprland` | `overridden` is null until read and after a failed read, else the paths of this plugin's `hyprland.options` the layer wrote whose value Hyprland reads back otherwise, plus paths this plugin lost to an earlier plugin conflict; `devices` is `{ mice: [{ name, touchpad }], keyboards: [{ name, layout, variant, options, activeKeymap, activeLayoutIndex, main }] }` from `hyprctl -j devices`, null until read and after a failed read, read again when a device comes or goes, a layout switches or Hyprland reloads; `foreignBinds` is null until read and after a failed read, else the keys, normalised as `hyprland.binds` keys are, that something other than the layer binds in the default submap, such as a user's own bind on the plugin's key; each non-null read is a frozen copy, bindable; `switchKeyboardLayout` moves every keyboard to `next`, `prev` or a layout index through `hyprctl switchxkblayout all <target>`, never a dispatch, and returns `ok` once queued, `refused: dispatch-queue=full limit=32 request=[...]`, or `refused: layout=<target> want=next|prev|index`: [`docs/architecture/hyprland-options.md`](../../../../docs/architecture/hyprland-options.md) |
| `shell.monitors.outputs`, `.saved`, `.overridden`, `.writeState`, `.write(rules)`, `.previewState`, `.preview(rules, seconds)`, `.confirm(token)`, `.revert(token)` | capability `monitors` | `outputs` is `hyprctl -j monitors all` as `[{ identifier, id, name, description, make, model, serial, width, height, refreshRate, x, y, scale, transform, vrr, disabled, mirrorOf, availableModes: [{ width, height, refresh }], currentFormat }]`, null until read and after a failed read, read again when an output comes or goes and after each reload; `saved` is the judged rules of `~/.config/vgs/monitors.json`, `[]` when absent, null while unread, refused or unreadable; `overridden` is the sorted identifiers of saved rules whose plugged-in output reads back otherwise, such as under a user's later `hl.monitor` line, null while `outputs` is unread; `writeState` is `{ phase, failure }`, `phase` one of `idle`, `saving`, `applying` (until the layer reloaded and the outputs were read back) and `failed`; `write(rules)` judges a rules list against `outputs`, then saves and applies it, and returns `ok` once queued or a `refused: ...` line, such as `refused: rule=0 scale=1.3 want=whole-logical-pixels mode=3840x2160`, `refused: rules=no-output-on want=one-output-on`, `refused: outputs=unread` or, while a preview runs, `refused: write=busy phase=preview-<phase>`; `preview(rules, seconds)` judges as `write` does, applies the rules for `seconds`, 2 to 60, without saving them, and returns `ok` once the helper runs or a `refused: ...` line; `previewState` is `{ phase, token, deadline, failure }`, `phase` one of `idle`, `starting`, `previewing` (with the `token` and the `deadline` in epoch seconds), `confirming`, `reverting` and `failed`; `confirm(token)` keeps the preview and writes its rules, `revert(token)` restores the outputs now, and at the deadline a guard outside the shell restores them unless kept; each non-null read is a frozen copy, bindable. A rule's fields and identifiers: [`docs/architecture/hyprland-monitors.md`](../../../../docs/architecture/hyprland-monitors.md); the preview: [`docs/architecture/hyprland-monitors-preview.md`](../../../../docs/architecture/hyprland-monitors-preview.md) |

A registration name is lower case, digits and dashes. Registering a taken shortcut or IPC name throws an `Error` whose message starts `refused:`. Register shortcuts and IPC handlers from one instance, a service, since every instance of the plugin shares the names. Disabling the plugin runs every disposer; call one to release earlier. A manifest naming `panes` must also name kind `window`. `lock`, `polkit`, `bluetoothAgent`, `monitors` and `panes` serve one plugin at a time: a second plugin naming one is not built while another holds it.

Nothing else is on it. A capability the manifest did not name is absent, not null.

The numeric arguments of `moveWindow`, `resizeWindow` and `moveCursor` accept numbers or canonical decimal integer strings within the signed 32-bit range. Resize dimensions must also be positive. These compositor methods return `ok` when the core queues the request, or `refused: ...` at the argument check or queue ceiling. A queued request can still fail or change nothing. Read the affected window, monitor or pointer state back before reporting an effect. `scripts/test-dispatch.js` pins both dialects and their refusals. `scripts/smoke/rows/compositor-dispatchers.sh` reads the effects back.

## Notification hints

## Manifest

The field table is [`docs/architecture/plugin-manifest.md` § Manifest](../../../../docs/architecture/plugin-manifest.md#manifest). An unknown key refuses the manifest.

A plugin of kind `pane` declares `pane: { group, order }`; the enabled `panes` holder uses those values to group and sort the section list.


`hyprland.appearance` is an object for a plugin that has capability `theme`. It maps `borders`, `radius` or `motion` to a boolean setting key in the same manifest schema. The first enabled plugin by id that declares appearance owns the switches. A later declaration is reported as a Hyprland problem and ignored. The core uses defaults when no owner declares a group: borders on, radius on and motion off. A user's Hyprland setting after the VGS include line still wins.
